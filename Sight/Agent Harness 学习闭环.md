来源：YouTube *Agent Harness for Learning Things*（[[Raw/Agent Harness for Learning Things]]）。核心：把 LLM 包成一个“学习型 agent harness”，让教学、练习和你的理解模型形成一个持续闭环，而不是把思考外包给 AI。

## 目标：单位心智努力换来的理解

学习系统优化的不是“让过程更轻松”，而是

$$
\text{有效理解}=\frac{\text{真正建立的理解}}{\text{投入的心智努力}}.
$$

最大的风险不是模型幻觉，而是**跳过挣扎**，产生“我懂了”的错觉。AI 应该帮你把心智努力分配到与材料直接交互的部分，而不是替你完成思考。

## 理解 ≠ 会用

- **教学（teaching）**负责安装理解。
- **练习（practice）**负责巩固理解，让它变得可用。

课堂上跟着推理走，能产生真实理解；但遇到问题时，相关想法不一定能被想起来。差别在于**回忆（recall）**：回忆依赖线索（cue）。

一个新概念最初只和“被教它的那个上下文”绑定，线索集很窄、很弱。练习的作用就是**拓宽并强化线索集**，让它在更多情境下被唤起。

```mermaid
flowchart LR
    T["教学<br/>安装理解"] --> U["理解"]
    P["练习<br/>拓宽线索"] --> R["可用知识"]
    U --> R
    R -->|"新问题触发"| P
```

## 优化前提：先有“你的理解模型”

不存在抽象的“最优课程”或“最优练习题”——是否冗余、是否够得着，都相对于**你当前的理解**。所以系统必须先知道：

- 你懂什么；
- 你是怎么理解的；
- 你的心理模型、推理方式、细微偏差。

只看对错不够：两个人可能给出同一个错误答案，但原因完全不同。系统需要**过程数据**，而不只是最终答案。这就是几乎每次交互都有 “thinking” 输入框的原因：把未经过滤的思考流直接交给 agent。

## 教学循环：Probe → Plan → Teach

```mermaid
flowchart TB
    A["Probe 探针<br/>快速选择题，二分定位理解边界"] --> B["Plan 计划<br/>最小依赖树：已知 → 目标"]
    B --> C["Teach 教学<br/>每次只走一个推理步"]
    C --> C1["你预测下一步"]
    C1 --> C2["Agent 讲解这一步"]
    C2 --> C3["检查你是否真的理解"]
    C3 -->|"未落地"| C1
    C3 -->|"落地"| D["下一个推理步"]
    D --> C
```

关键设计：

- **先探针**：用快速选择题定位“已知/未知”的边界，而不是从头讲。
- **再规划**：agent 从你已有的“显然为真”出发，推出到目标的最小依赖树。
- **逐步教学**：每一步都小到“只差一个推理步”，让中间结论也显得显然为真。
- **每步三拍**：你先预测 → agent 讲解 → 检查理解。预测本身既是学习机会，也给 agent 更多关于你思考过程的数据。
- **苏格拉底式**：每步两个问题，错误和困惑会立刻暴露，在继续往上搭之前修掉。

Agent 还可以调用四类子 agent：

| 子 agent | 作用 |
| --- | --- |
| Researcher | 查证事实 |
| PDF reader | 高效读取 PDF |
| SVG maker | 生成图表、示意图 |
| Demo builder | 生成可交互演示 |

## 练习：让回忆“有努力但能前进”

练习的目标不是“出题”，而是**给出线索，要求你主动回忆**。练习流会根据你的思考实时调整难度，两个主要旋钮：

1. **一道题组合多少个想法**；
2. **线索有多熟悉**。

理想难度是“需要努力才能想起，但不至于卡死”。当你真的卡住时，agent 给最小提示，把你推向正确方向，而不是直接给答案。

思考按块提交，agent 能从中推断你是否真的解出来，不必你手写最终答案。

## 持久模型：命题 + 推理链

教学和练习之间需要一个持久的记录，既压缩又能保留“想法之间怎么连接”。系统采用：

- **命题（propositions）**：被理解的最小陈述；
- **推理链（reasoning chains）**：命题之间为什么能推出彼此。

这些从教学会话中抽取出来，形成一张持续生长的图：

- 箭头表示**推理方向**；
- 节点可以被多个会话复用；
- 把 Y 轴设为推理深度，就能看到论证如何一层层向上生长；
- 可以跳到节点出现过的原始消息。

```mermaid
flowchart BT
    A["基础命题 A"] --> C["中间结论 C"]
    B["基础命题 B"] --> C
    C --> D["目标结论 D"]
    C --> E["另一条推理链"]
```

当前限制：图只显示“覆盖了什么”，还没有把评估结果写回节点；下一步才是让图告诉你“哪里掌握得好、哪里薄弱”。

## 什么是 Agent Harness

Agent harness 是 LLM 外面的一整套东西，让模型能在某个外部系统里探索和行动：

| Harness | 外部系统 | 人的角色 |
| --- | --- | --- |
| Coding agent | 计算机 | 操作者 |
| Research agent | 互联网 | 操作者 |
| Learning agent | **你的大脑** | **被作用的系统** |

学习型 harness 的特殊之处：你不是在驾驶 agent，而是 agent 作用的对象。所以它必须持续读取你的思考，而不是只接收最终答案。

## 为什么“大段文字”反而不好

不是因为长文难读，而是因为**长文会减少你输出思考的机会**。系统需要连续的数据流来判断你此刻的理解状态；一大段讲解会把反馈间隔拉长，让 agent 失去定位你理解边缘的机会。
