# 句柄 handle 与实例 instance · 语法知识 · N039

## 疑惑点

句柄 handle 到底是什么？为什么 ROS2 里哪哪都是——`GoalHandle`、`param_cb_handle_`、一堆 `SharedPtr` 成员？代码里总说「创建实例」「实例化」，实例又是什么、和「类」「变量」是什么关系？

## 实际情况

### 1. 句柄 handle 是什么（原 N039）

1. **本质：句柄 = 身份令牌（标识）+ 操控把手（操作）+ 拴绳（生命周期）**，通常就是一个 `SharedPtr`。你拿到句柄，不是拿到那个东西本身，而是拿到「和它对话 / 操控它的凭证」。类比：取餐号（future）= 那碗还没做好的面；遥控器 = 电视。

2. **为什么到处有**：ROS2 的通信对象（发布者/订阅者/定时器/动作目标/回调）有三样共同需求——要能**标识**（区分「几号目标」）、要能**操控**（发反馈/取消/注销）、要管**生命周期**（销毁自动清理）。句柄把这三样打包成一个对象，所以处处都是它。

3. **三类句柄**：

   | 类型 | 例子 | 作用 |
   | ---- | ---- | ---- |
   | 资源句柄 | `Publisher<Twist>::SharedPtr`、`TimerBase::SharedPtr` | 拴住发布者/定时器，析构自动释放 |
   | 目标句柄 | `ServerGoalHandle` / `ClientGoalHandle` | 标识「某一个具体目标」，操控都挂在它身上 |
   | 回调句柄 | `OnSet/PostSetParametersCallbackHandle` | 存着以后能注销 |

4. **生命线机制（最关键）**：句柄（shared_ptr）析构 → 对应东西自动注销/释放。所以 `param_cb_handle_` 必须存成成员变量，否则构造函数一结束、句柄析构、回调被注销（白注册）。

5. **和 future / 智能指针的关系**：句柄几乎都是 `SharedPtr`（引用计数 → 自动释放）；`future`（[[N030 future机制异步结果的凭证]]）本质也是句柄——异步结果的取餐号。所以「句柄哪里都有」= 凡是需要「标识 + 操控 + 生命周期」的东西，ROS2 都给你一个句柄。

6. **句柄的经典原型：文件描述符 fd**。最经典的句柄不是对象，是 C / Unix 里的一个 int：

   ```c
   int fd = open("file.txt", O_RDONLY);  // open 返回一个 int，不是文件本身
   read(fd, buf, sizeof(buf));           // 拿这个 int 去读写
   close(fd);                            // 拿它去释放
   ```
   你从头到尾没见过内核里的 FILE / inode——OS 内部维护「fd → 打开文件」的表。这个 int 就是句柄：它不「是」资源，是资源的「代号」。

7. **句柄全谱系（形式一直在变）**：

   | 句柄 | 载体 | 代表的资源 |
   | ---- | ---- | ---- |
   | 文件描述符 fd | int | 打开的文件 |
   | 窗口句柄 HWND（Windows） | 整数/指针 | 窗口 |
   | 裸指针 | 内存地址 | 内存对象 |
   | 智能指针 shared_ptr | 对象 | 堆对象（引用计数） |
   | future | 对象 | 异步结果 |
   | `Publisher::SharedPtr` / `TimerBase::SharedPtr` | 智能指针 | 发布者 / 定时器 |
   | `ServerGoalHandle` / `ClientGoalHandle` | 对象 | 某个动作目标 |

8. **本质（为什么从 int 到对象都叫「句柄」）**：不管载体是一格 int 还是一个对象，做的都是同一件事——**不直接给你资源，给你一个能「标识 + 操控 + 管生命周期」的抽象引用**。好处三样：**封装**（资源内部结构对调用方不可见，OS/库可在背后改布局、搬地址）、**安全**（拿不到资源裸地址）、**生命周期**（fd 要 close，shared_ptr 析构即释放，GoalHandle 析构即注销）。

### 2. 实例 instance 是什么（原 N040）

1. **一句话：类（class）是「图纸」，实例（instance）是照着图纸造出来的「实物」。** 类是类型定义，描述「这类东西有哪些数据成员 + 能做什么操作」；实例是用这个类造出来的一个具体对象，占一块真实内存，里面有它自己的数据。

2. **类 vs 实例的区别：编译期 vs 运行期。**
   - 类在**编译期**决定「这种对象在内存里长什么样」和「有哪些操作」，但类本身（除 static 成员）**不占运行期数据内存**——像图纸不占车间的地。
   - 实例是**运行期**真正分配出来的一块内存，装着这个对象自己的数据。

   ```cpp
   class Turtle {          // 类 = 图纸
     double x = 0, y = 0;  // 数据成员：海龟的位置
     void move(double dx, double dy) { x += dx; y += dy; }  // 方法：能移动
   };

   Turtle t1;   // t1 是实例 1：一块独立内存，装着 t1 自己的 x、y
   Turtle t2;   // t2 是实例 2：另一块独立内存，装着 t2 自己的 x、y
   t1.move(1, 0);  // 只改 t1 的 x,y，和 t2 无关
   ```

3. **类 → 实例的过程叫「实例化（instantiation）」**：

   ```cpp
   auto node = std::make_shared<rclcpp::Node>("my_node");
   //           └──────── 实例化一个 Node 对象 ────────┘
   ```
   `rclcpp::Node` 是类，`make_shared` 造出来的那个就是 Node 实例。

4. **「实例」和「变量」的关系**：一个类型是类的变量，它就是实例（或实例的引用/指针）。基本类型（int、double）的变量严格说也符合「对象」的宽泛定义，但口语里「实例」专指「类的对象」。

> **Note（连接 / 深化）：**
> - 连接：句柄底层是智能指针 SharedPtr，见 [[N001 节点基础书写骨架]]；future 是「异步结果的句柄」见 [[N030 future机制异步结果的凭证]]；GoalHandle 见 [[N034 Action概念与action接口]]；回调句柄见 [[N024 参数概念与四大通信机制全景]]；实例（对象）放栈还是堆见 [[N041 栈和堆的底层实现与区别]]。
> - 深化：句柄内部通常就两样——指向所属对象的弱引用 + 唯一 id；所以它「轻量、可拷贝、析构即注销」，这也是 RAII 思想的体现。实例的本质就是「一块按类定义排布好的内存 + 一组能操作它的方法」；类决定内存布局（sizeof 大小），实例是这份布局的一个具体落点。

## 总结

**本质：** 句柄 = 身份令牌 + 操控把手 + 拴绳（生命周期），ROS2 里通常就是一个 SharedPtr，凡是要「标识 + 操控 + 生命周期」的东西都用句柄包起来；实例 = 照「类」这张图纸造出的实物（运行期一块真实内存），类 → 实例叫实例化。
