# 函数参数与形参遮蔽 · 语法知识 · N049

**时间:** 2026-10-14
**标签:** #语法知识 #C++语法 #函数Function #形参实参 #遮蔽Shadowing #引用传递Reference
**关联:** [[N038 stdthread线程库与ROS2应用]] [[N040 实例instance是什么]] [[N048 constexpr编译期常量]]

## 疑惑点

写 `publish_cmd_vel` 时形参写成了 `m_v` / `m_w`，结果和成员变量同名——代码能编译，但「我传进去的值」和「函数里用的值」感觉对不上。形参和成员到底怎么区分？传参有哪些坑？

## 实际情况

### 1. 形参 vs 实参（两个名字，别混）

- **形参（parameter）**：定义函数时括号里写的「占位名」，如 `void f(double v)` 里的 `v`；
- **实参（argument）**：调用时传进去的「实际值」，如 `f(2.0)` 里的 `2.0`。

调用时，实参的值会**拷进形参**，函数里操作的是这份拷贝。

### 2. 形参遮蔽成员（shadowing）——这次的坑

形参名和成员名相同时，函数体内**形参优先**，成员被「遮蔽」：

```cpp
class T {
  double m_v = 2.0;            // 成员
  void go(double m_v) {        // 形参也叫 m_v，遮蔽了成员
    // 这里的 m_v 是形参，不是成员！
  }
};
```

`m_` 本该是成员专属前缀，拿它当形参名 → 名字撞了、语义也乱了。**函数体内写 `m_v` 时，读到的不是成员，是形参**——这就是「传进去的值对不上」的根源。

### 3. 命名约定：m_ 前缀 = 成员专属

- `m_` 开头 → **成员变量**；
- 形参用普通名（`linear` / `angular` / `v`），不加前缀。

一眼分清「这个变量是谁的」：

```cpp
void publish_cmd_vel(rclcpp::Rate & rate, double duration, double linear, double angular) {
  msg.linear.x = linear;          // ← 形参，一眼认出
  m_pub_cmd_vel->publish(msg);    // ← 成员，一眼认出
}
```

### 4. 传值 vs 传引用（参数怎么传）

| 写法 | 行为 | 什么时候用 |
| ---- | ---- | ---- |
| `double v` | 拷贝一份，改形参不影响外部 | 小类型（int / double 等）够用 |
| `double & v` | 不拷贝，改形参直接影响外部 | 需要「改原值」时 |
| `const double & v` | 不拷贝、只读 | 大对象（std::string 等）避免拷贝 |
| `Rate & rate` | 不拷贝 | 对象**不可拷贝**时只能传引用（见 N038） |

`rclcpp::Rate` 不可拷贝，所以必须 `rclcpp::Rate & rate`（[[N038 stdthread线程库与ROS2应用]]）。

### 5. 注意事项小结

1. **形参名别和成员撞**：撞了会被遮蔽，还破坏 `m_` 前缀的可读性。
2. **固定值别当参数传**：固定速度按风格写死 `constexpr`（[[N048 constexpr编译期常量]]），函数参数只留给「每次调用会变」的量。
3. **按值传的形参是拷贝**：函数里改它，外面的实参 / 成员不变——别指望改形参去改成员。
4. **不可拷贝对象（Rate 等）只能传引用 / 指针**。

## 总结

**本质：** 形参是「占位名」、实参是「实际值」，调用时实参拷进形参；形参名若与成员同名会**遮蔽**成员（函数体内读到的不是成员）。`m_` 前缀是成员专属，形参用普通名；传参要分清传值（拷贝）vs 传引用（不拷贝 / 不可拷贝对象必须引用）。
