# 栈和堆的底层实现与区别 · 语法知识 · N041

**时间:** 2026-10-08 21:11
**标签:** #语法知识 #C++语法 #栈Stack #堆Heap #内存Memory
**关联:** [[N001 节点基础书写骨架]] [[N027 stdmap的实现机制红黑树与操作管理]] [[N038 stdthread线程库与ROS2应用]] [[N040 实例instance是什么]]

## 疑惑点

栈和堆到底是什么？底层是怎么实现的？为什么要有两种放变量的地方？

## 实际情况

1. **内存全景图**：

   ```
   高地址
   ┌──────────────────┐
   │  栈 (stack)       │  ← 从高地址向低地址生长 ↓
   │  每线程独享,约 8MB  │     栈指针寄存器 RSP 指着「栈顶」
   │        ↓          │
   │  ─── 未使用空隙 ─── │  ← 栈往下长、堆往上长,往中间靠
   │        ↑          │     撞一起 = 内存耗尽
   │  堆 (heap)        │  ← 从低地址向高地址生长 ↑
   │  全进程共享,受内存限制│     由 malloc / free 记账管理
   ├──────────────────┤
   │  BSS段 / 数据段 / 代码段 │
   └──────────────────┘
   低地址
   ```

2. **栈的底层实现：一个寄存器就够了。** 核心一句话——「分配/释放」就是移动一个指针，没有任何查找和记账。
   - 局部变量大小在**编译期**确定，函数入口 `sub rsp, N` 一次性划好整个「栈帧（stack frame）」；所谓「分配一个 int」只是「用 rbp 减固定偏移去访问」，零分配成本。
   - 函数返回时 `add rsp, N` 把指针拨回去 = 整个帧「释放」完毕。**不清空数据**，只是移回指针，下次调用直接覆盖。
   - 严格**后进先出（LIFO）**：栈帧一层套一层，函数调用链天然就是这种嵌套结构，所以一个指针就能完美管理。
   - **代价**：固定大小（默认 8MB/线程）、生命周期绑死作用域（函数返回即失效）、递归太深 / 局部大数组 → **栈溢出（stack overflow）**。

3. **堆的底层实现：要有人记账（allocator）。** `new/delete` 底层调 `malloc/free`，它内部有一张**空闲链表（free list）**记录哪些块是空的：
   - `malloc(n)`：在空闲链表找一个 ≥ n 的块 → 块太大就**切开（split）** → 在返回给用户的地址**前面写一个「头」存这块大小** → 返回头后面的地址。
   - `free(p)`：读 p 前面那个「头」就知道大小 → 放回空闲链表 → 和相邻空闲块**合并（coalesce）**。
   - 大块（几 MB 以上）直接 `mmap` 向操作系统要整页内存。
   - 这就是为什么 `free(p)` / `delete` 不用告诉它大小——大小记在块前面的「头」里。
   - **代价**：慢（函数调用 + 查链表 + 加锁）、**碎片**（全是小块找不到连续大块）、生命周期手动管理（忘 delete → **内存泄漏**）。
   - **好处**：想多大多大（受内存 + swap）、生命周期任意（跨作用域存活）、任意顺序释放。

4. **两者为何存在不同（本质一句话）：**
   > 栈是「编译期就知道大小、生命周期严格嵌套」的存储，所以一个指针就够；堆是「运行期才知道大小、生命周期任意」的存储，所以必须有个 allocator 记账。

   | 维度 | 栈 | 堆 |
   | ---- | ---- | ---- |
   | 大小 | 编译期确定，小（约 8MB/线程） | 运行期确定，大（受内存限制） |
   | 分配/释放速度 | 极快（移动一个指针） | 慢（查链表/加锁/记账） |
   | 生命周期 | 绑死作用域，函数返回即失效 | 手动控制，可跨函数存活 |
   | 释放顺序 | 严格后进先出 | 任意顺序 |
   | 碎片 | 无 | 有 |
   | 谁在管 | 硬件/编译器（寄存器） | 运行时 allocator |
   | 线程 | 每个线程独享一个 | 全进程共享一个 |

   这是「速度 vs 灵活性」的经典权衡：栈用「限制你」换「极快」，堆用「慢一点」换「随便用」。两者不是谁好谁坏，是各干各的活。

5. **连接 ROS 代码**：

   ```cpp
   void on_message(const std_msgs::msg::String &msg) {
     int counter = 0;             // 栈：固定大小，回调结束自动销毁
     double pose[3] = {0,0,0};    // 栈：固定大小数组

     auto node = std::make_shared<rclcpp::Node>("n");
     // ↑ Node 实例在「堆」上（大小/生命周期不固定，shared_ptr 管理）

     std::vector<int> v;          // v 对象在「栈」上，但内部数组数据在「堆」上
     v.push_back(42);             // 所以能无限增长
   }
   ```
   - `std::vector` / `std::map` 的**对象本身**在栈上（几个指针 + size），**内部数据**在堆上——这就是它能动态增长而栈数组不能的原因（见 [[N027 stdmap的实现机制红黑树与操作管理]]）。
   - 每个 `std::thread` 有自己的栈（见 [[N038 stdthread线程库与ROS2应用]]）——「多线程 = 多个独立栈 + 一个共享堆」。
   - `make_shared` 造的对象都在堆上，靠 `shared_ptr` 引用计数自动 delete（见 [[N001 节点基础书写骨架]]）。

> **Note（连接 / 深化）：**
> - 连接：实例（对象）放栈还是堆见 [[N040 实例instance是什么]]；容器底层数据在堆见 [[N027 stdmap的实现机制红黑树与操作管理]]；线程各栈见 [[N038 stdthread线程库与ROS2应用]]。
> - 深化：栈是「编译期静态布局」的极致（快但死板），堆是「运行期动态布局」的极致（灵活但慢）——C++ 里所有「自动管理 vs 手动管理」「固定 vs 动态」的取舍，根源都在这两者上。

## 总结

**本质：** 栈 = 编译期定大小 + LIFO，一个指针（RSP）就完成分配/释放，极快但死板（固定约 8MB/线程、作用域内生命周期）；堆 = 运行期任意大小/生命周期，靠 allocator（malloc/free 空闲链表 + 头记账）管理，灵活但慢（有碎片、需手动释放）。两者是「速度 vs 灵活性」的权衡。
