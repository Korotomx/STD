# 同步异步与阻塞非阻塞 · 语法知识 · N042

**时间:** 2026-10-08 21:52
**标签:** #语法知识 #C++语法 #同步sync #异步async #阻塞Blocking #非阻塞NonBlocking
**关联:** [[N030 future机制异步结果的凭证]] [[N019 客户端实现 create_client]] [[N023 main函数变厚 executor演进]] [[N009 Executor事件循环]]

## 疑惑点

同步 / 异步 / 阻塞 / 非阻塞这四个词常被混着用，它们到底是不是一回事？ROS2 里说的「异步回调是正统姿势」「fut.get() 会死锁」到底对应哪一个？

## 实际情况

1. **核心：两对概念，两个正交维度，不是一回事。**

   | 对 | 问的是 | 关注点 |
   | ---- | ---- | ---- |
   | 同步 / 异步 | 结果**怎么回到你手上** | 是「当场给」还是「回头通知」 |
   | 阻塞 / 非阻塞 | 等待期间**线程在干嘛** | 是「挂起睡着」还是「继续跑」 |

   一句话：**同步** = 我等你结果当场给；**异步** = 结果好了你叫我；**阻塞** = 等的时候我睡着了（线程挂起）；**非阻塞** = 等的时候我还能干别的。

2. **同步 vs 异步（结果的传递方式）**：

   ```cpp
   // 同步：当场拿结果，拿不到就停在这行
   int r = compute();

   // 异步：先拿一个「凭证」future，结果以后给
   std::future<int> f = std::async(compute);  // 立刻返回，不干等
   int r = f.get();   // 到这一步才真正要结果
   ```
   - 同步：发起调用，结果**当场返回**，调用方和被调方步调一致。
   - 异步：发起调用后**立刻返回**（只拿到凭证），结果以后通过回调 / future / 事件通知。

3. **阻塞 vs 非阻塞（等待时线程的状态）**：

   ```cpp
   // 阻塞：结果没好，线程被挂起，卡在这一行
   int r = fut.get();   // 结果没到就一直睡在这

   // 非阻塞：立刻返回，没好也不卡
   if (fut.wait_for(0s) == std::future_status::ready) {
     int r = fut.get(); // 就绪才取
   }
   ```
   - 阻塞：结果没准备好前，调用线程被**挂起**（CPU 让出去），直到结果就绪。
   - 非阻塞：调用**立刻返回**（哪怕结果还没好），线程继续往下跑。

4. **2×2 组合（关键）**：

   | | 阻塞 | 非阻塞 |
   | ---- | ---- | ---- |
   | **同步** | 同步阻塞 `fut.get()` — 原地等，线程挂起（最「重」） | 同步非阻塞 轮询 `fut.wait_for(0)` 反复查 — 线程没挂但在空转，还是「主动要结果」 |
   | **异步** | 异步阻塞 — 罕见，注册了回调却又 get 卡住等，通常算设计矛盾 | 异步非阻塞 — 注册回调，事件到了自动触发（ROS 回调模型） |

   常被忽略的交叉：**轮询是「同步 + 非阻塞」**——还是主动「要结果」（同步），但没挂起、期间能干别的（非阻塞），代价是空转烧 CPU。

5. **连回 ROS2**：
   - `create_client` + `async_send_request` + 回调 = **异步非阻塞**（发起请求立刻返回，响应到了回调被 executor 调起，见 [[N019 客户端实现 create_client]]）。
   - 主流程里 `fut.get()` = **同步阻塞**——结果没到线程卡死，这正是 **E004 死锁**根源：executor 被 get() 卡住，没法再进回调处理响应，永远等不到。
   - `fut.wait_for(0)` 轮询 = **同步非阻塞**。
   - spin / executor 事件循环 = 事件驱动的**异步非阻塞**：注册一堆回调（异步），等消息间隙还能处理别的回调（非阻塞，见 [[N009 Executor事件循环]] / [[N023 main函数变厚 executor演进]]）。

> - 深化：**日常简化**——读文档时「同步」≈「阻塞」（你要等结果）、「异步」≈「非阻塞」（你不等、靠回调）。这个粗略映射够用，但遇到「轮询」「死锁」这种边界情况，仍要回到「结果传递方式 × 线程状态」两个维度拆开看。

## 总结

**本质：** 同步/异步 = 结果「当场给 vs 回头通知」；阻塞/非阻塞 = 等待时线程「挂起 vs 继续跑」，两个正交维度。四组合里 ROS2 的正统姿势是**异步非阻塞**（注册回调 + executor 调度），`fut.get()` 是**同步阻塞**（主流程里用会卡死 executor → 死锁）。
