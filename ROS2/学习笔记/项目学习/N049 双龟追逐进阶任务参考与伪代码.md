# 双龟追逐进阶任务 · 项目学习 · N049

**时间:** 2026-10-14 01:15
**标签:** #项目学习 #turtlesim #Service服务 #架构Architecture
**关联:** [[N020 turtle_chase小海龟追击项目架构与代码拆解]] [[E003 构建依赖-turtlesim消息拆到turtlesim_msgs]] [[E004 运行时-Service客户端等响应的死锁与executor冲突]]

## 背景

课程设计**进阶任务(双龟追逐)**需要补的功夫比基础任务大:随机生成、kill/spawn 重生、set_pen 藏轨迹、躲墙……涉及 yaml / launch / 服务等多块知识。翻学习项目时发现 `dev_ws` 里早就写过一个小海龟追击项目(就是 [[N020]])——它已经解决了「A 追 B」的核心,可以直接当进阶任务的底子。

## 复用了什么

把 `~/dev_ws/src/turtle_chase` 整个复制到了课程设计工作空间 `~/ros2_course_ws/src/turtle_chase` 作参考,并补了一份 `进阶任务_伪代码.md`(差距分析 + 逐条伪代码 + 决策点 + 最小实现顺序)。

| 参考文件 | 角色 |
| ---- | ---- |
| `target_turtle.cpp` | B 龟:随机游走 + 提供 `get_target_pose` 服务 |
| `chaser_turtle.cpp` | A 龟:定时调服务 + 按角度差比例转向追击 |
| `srv/GetTargetPose.srv` | 空请求 → `float64 x, y` |

追击核心算法(直接复用):`angle_diff = atan2(dy,dx) − self_theta`,角速度 = `K × angle_diff`,线速度定值,距离近则停。

## 差距(进阶任务要求 − 参考代码现状)

| 要求 | 现状 | 要补 |
| ---- | ---- | ---- |
| B 随机位置生成 | 用默认 turtle1 | `/spawn` 随机坐标 |
| 追到后靠得近 | 停在 0.5 处 | 阈值实测 + 触发重生 |
| B 消失 + 新位置重生 | 无 | `/kill` + `/spawn` |
| 隐藏轨迹 | 无 | `/set_pen(off=1)` |
| B 躲墙(进阶) | 全范围随机转向,会撞墙 | 靠墙时限制朝向到「背离墙」半平面 |

## 决策点(思考)

- **Q1** 拿 B 位置:服务请求 vs 直接订阅 `/B/pose`?实时性 / 点对点的区别?
- **Q2** 「追到 → 重生」链路归 A 还是 B?谁需要知道对方哪些信息?
- **Q3** spawn / kill / set_pen 用同步 call 会阻塞什么?(注意 [[E004]] 的 executor 死锁坑)
- **Q4** `catch_threshold` 取值与线速度、控制周期、过冲的关系,怎么实测?

## 最小实现顺序

1. 跑通「生成」:spawn 随机 B + 藏轨迹(把 spawn/kill/set_pen 用一遍)
2. 接入追击(参考代码基本直接用)
3. 加闭环:追到 → kill+spawn 重生
4. 最后做躲墙(加分)

## 总结

进阶任务的本质是「在现成的 A 追 B 闭环上,把 B 的**生命周期**(出生/死亡/重生)和**轨迹隐藏**补齐」——多出来的都是 turtlesim 自带服务(`spawn`/`kill`/`set_pen`)的调用与编排,追击本身不用重写。
