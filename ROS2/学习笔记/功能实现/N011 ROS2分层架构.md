# ROS2 分层架构（rclcpp/rcl/rmw/DDS） · 功能实现 · N011

**时间:** 2026-10-04 17:19
**标签:** #功能实现 #架构Architecture #rclcpp #rcl #rmw #DDS #消息类型
**关联:** [[N001 节点基础书写骨架]] · [[N010 订阅者与回调参数]]

## 疑惑点

ROS2 对它自带的那些库到底是怎么处理的？整体架构是怎样的？是不是 rclcpp 专门负责 C 语言的通信功能、而跨语言的消息类型是独立出来的另一个库？

## 实际情况

理解对了一半，有一个关键要纠正：**`rclcpp` 不是「通信功能」，是「客户端库（外壳）」；真正的通信在 rcl → rmw → DDS 这一串里。**

分层架构（从上到下）：

```
你的节点代码 (C++ / Python)
        │
        ▼
rclcpp / rclpy    ← 客户端库(语言封装),提供 Node/create_publisher 等好用的 API
        │
        ▼
rcl (纯 C)        ← 核心库,语言无关:图/节点/话题/时间/日志/参数
        │
        ▼
rmw (中间件接口)   ← 抽象层,隔离具体 DDS
        │
        ▼
DDS 实现           ← 真正网络通信:CycloneDDS / FastDDS / Connext
```

| 层 | 是什么 | 职责 |
|----|--------|------|
| rclcpp / rclpy | 客户端库 | 给每种语言一套符合语言习惯的 API；**不实现通信**，只封装 |
| rcl | 核心库(纯 C) | ROS 真正核心逻辑：节点注册、图、话题/服务/参数、时间、日志、调度 |
| rmw | 中间件接口 | 抽象层，把 ROS 逻辑与具体 DDS 隔开，可换 DDS 不改上层 |
| DDS | 中间件实现 | 节点发现、序列化、跨进程/跨机器传输 |

**核心结论：`rclcpp` 是外壳，`rcl` 是大脑，`rmw + DDS` 是通信管道。**

**消息类型（用户问的第二点，理解正确 ✅）：**

- 消息类型确实是**独立的、横向贯穿的一层**：接口定义 `.msg/.srv/.action` 只写定义，`rosidl` 工具自动生成 C / C++ / Python 多套类型代码。
- 所以同一个消息类型能被 C++ 和 Python 跨语言共用（如 `std_msgs/msg/String`、自定义的 `turtle_demo_interfaces`）。
- 数据流：`publish(msg)` → rclcpp → rcl → rmw → CycloneDDS 序列化/发送；对端反向穿过四层 → 触发回调。

> **Note（连接 / 深化）：**
> - 连接：rclcpp 提供的 `create_publisher` 等 API 见 [[N001 节点基础书写骨架]]；回调触发见 [[N010 订阅者与回调参数]]。
> - 深化：DDS 可换（CycloneDDS/FastDDS/Connext）正是 rmw 抽象层的价值；`ros2 node list`、`ros2 topic list` 查的是 rcl 维护的「图」。

## 总结

**本质：** ROS 2 严格分层——`rclcpp/rclpy`(语言封装外壳) → `rcl`(纯 C 核心逻辑) → `rmw`(中间件抽象) → `DDS`(实际通信)；消息类型由 `.msg/.srv/.action` 独立定义、`rosidl` 生成多语言代码，所以跨语言共享。
