# ROS2 底层通讯的网络机制（DDS/RTPS/UDP/组播） · 功能实现 · N047

**时间:** 2026-10-13 00:41

**关联:** [[N011 ROS2分层架构]] · [[N002 QoS队列深度10]] · [[N015 话题通信的端到端延迟]]

## 疑惑点

N011 里说「DDS 负责真正网络通信」，但 DDS 到底是怎么在网络上通信的？ROS2 节点之间传消息，底层走的是 TCP 还是 UDP？没有 roscore 了，节点之间怎么互相找到对方？能不能用计算机网络的知识（TCP/UDP、端口、单播组播、发现）把这些讲清楚？

## 实际情况

**一句话：ROS2 的通信 = DDS 在 UDP/IP 之上实现了「去中心化的发布/订阅」。** 没有中心服务器，节点靠组播自动发现，数据靠 UDP 单播传输，可靠性靠 RTPS 在 UDP 之上自己补（ACK+重传），不靠 TCP。

### 1. 先摆正位置：两套「分层」别混

N011 学的 rclcpp/rcl/rmw/DDS 是 **ROS2 自己**的分层，那四层**全在 TCP/IP 的应用层里**。真正「上网」时，DDS 这个应用层协议直接坐在**传输层的 UDP** 之上（也可配 TCP）：

```
应用层   你的节点代码 + rclcpp + rcl + rmw + DDS/RTPS
传输层   UDP（默认） / TCP（可选）
网络层   IP（单播 unicast / 组播 multicast）
链路层   以太网 / WiFi / 环回
```

关键结论：**ROS2 底层跑的是 UDP 数据报，不是 TCP 连接。**

### 2. 为什么是 UDP 而不是 TCP

TCP 与 UDP 的取舍（计算机网络核心概念）：

| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接（3 次握手） | 无连接 |
| 可靠性 | 可靠（ACK + 重传 + 有序） | 尽力而为，可能丢 / 乱序 |
| 延迟 | 高（握手、队头阻塞） | 低 |
| 通信方式 | 只能一对一单播 | 可单播、组播、广播 |

实时 / 机器人系统要的是「低延迟 + 能组播 + 按需可靠」，所以 DDS 选 **UDP 打底**，把「可靠」留给自己按需加。

**核心要点：ROS2 的「可靠」不是 TCP 给的，是 RTPS 协议在 UDP 之上自己模拟的 ACK + 重传。**

### 3. 没有中心服务器：靠组播「自动发现」

- **ROS1** 有个 `roscore`（中心 master）：所有节点启动都先去它那注册、查话题 —— 像中心 DNS / 注册中心，单点故障、启动顺序敏感。
- **ROS2** 砍掉了 master，改成 DDS 的**去中心化自动发现**。这跟网络里「没有 DNS 服务器时，主机靠 ARP 广播 / 组播自己找到邻居」是同一个思路。

发现分两步（RTPS 协议定义）：

1. **SPDP（参与者发现）**：每个参与者（≈一个进程/节点）周期性往一个**组播地址**发「我在这，这是我的 GUID（全局唯一 ID）」。类比：开机后网卡广播 ARP「谁是网关」。
2. **SEDP（端点发现）**：双方互相交换端点细节 —— 话题名、消息类型、QoS、IP:端口。类比：DNS 把「名字」解析成「IP:端口」。

双方**话题名 + 类型 + QoS 兼容**，就建立 writer↔reader 关联，数据通路打通。

> 注意：**组播只用于「发现」阶段**；真正传数据时通常已经是**点对点单播**。

### 4. 数据怎么传（publish → 回调的全过程）

1. **序列化**：`publish(msg)` 把消息对象打成字节流（CDR 格式，类似「网络字节序」的统一二进制表示），跨平台 / 跨语言才能互相看懂。
2. **打包**：序列化字节 + RTPS 头（序号、时间戳、GUID）组成 RTPS 报文。
3. **发送**：走 UDP 单播发到对端。（本机两个节点时，CycloneDDS 甚至直接走共享内存、不过网络栈。）
4. **接收**：对端收到 → 反序列化回消息对象 → 放进订阅队列 → executor 从队列取出触发回调。

### 5. QoS = 把「网络行为」变成可选项（重点）

ROS2 底层通讯最妙的地方：把 TCP/UDP 的差异变成一个个**可单独勾选的 QoS 策略**：

| 网络概念 | ROS2 QoS | 含义 |
|---|---|---|
| TCP 的可靠（ACK+重传） | Reliability = RELIABLE | 丢包了补，像 TCP |
| UDP 的尽力（丢了不管） | Reliability = BEST_EFFORT | 发出去就不管 |
| 接收缓冲区大小 | Depth（队列深度） | 存多少条 |
| 缓存历史（晚来的也能拿） | Durability = Transient Local | 新订阅者拿到历史 |

所以 N002 里 `create_publisher` 的 `10`（队列深度）、N015 里「Reliable 有 ACK 比 Best Effort 慢」，本质都是 **RTPS 在 UDP 之上对 TCP 特性的选择性模拟**。

### 6. 一张对照表收尾

| 计算机网络 | ROS2 / DDS |
|---|---|
| IP 地址 | GUID（参与者唯一 ID） |
| 端口 port | endpoint（writer / reader） |
| DNS / ARP | SPDP + SEDP 组播发现 |
| TCP 三次握手 | RTPS 建立 writer↔reader 关联的握手 |
| TCP ACK + 重传 | Reliable QoS |
| UDP 尽力而为 | Best Effort QoS |
| 组播 | 发现 + 一对多 |
| 单播 | 点对点数据 |
| 网段 / VLAN 隔离 | DDS domain |

### 7. 一个 talker → listener 的完整故事

1. talker、listener 各自启动，加入同一个 DDS domain（同 domain 才能互相看见，像同一网段）。
2. 双方 SPDP 组播 → 互相发现对方 GUID。
3. SEDP 交换端点 → 发现「talker 发 `/chatter`、listener 收 `/chatter`，类型都是 String，QoS 兼容」→ 匹配成功。
4. talker `publish` → 序列化 → UDP 单播。
5. listener 收到 → 反序列化 → 队列 → executor 调回调。
6. （若 RELIABLE）listener 回 ACK，talker 丢了就重传。

> **Note（连接 / 深化）：**
> - 连接：DDS 这一层在四层架构里的位置见 [[N011 ROS2分层架构]]；QoS 的 Depth / Reliability 见 [[N002 QoS队列深度10]]；Reliable 的 ACK 如何拖慢延迟见 [[N015 话题通信的端到端延迟]]。
> - 深化：本机通信可能走共享内存（不过网络栈），跨机才真正走 UDP；组播只在发现阶段用，数据是单播；不同 DDS domain 之间互相看不见（像 VLAN 隔离）。

## 总结

**本质：** ROS2 底层通讯 = DDS 在 UDP/IP 之上实现「去中心化发布/订阅」：没有 master，节点靠组播自动发现（SPDP 参与者发现 + SEDP 端点发现），数据靠 UDP 单播传输，可靠性靠 RTPS 在 UDP 之上按 QoS 选择性模拟（RELIABLE≈TCP 的 ACK+重传，BEST_EFFORT≈UDP）。rclcpp/rcl/rmw/DDS 四层全在应用层，真正上网时坐在 UDP 之上。
