`build/install/log` 属于**工作空间**而非单个包；一个 `src/` 可以放多个包共享这套产物。包怎么变成可执行文件，则由 `package.xml`、`CMakeLists.txt` 和 colcon/ament 三者接力完成。

## 工作空间 vs 包

- `build/`（中间文件）、`install/`（最终产物）、`log/`（日志）是工作空间级别，按包名分子目录。
- `src/` 下可放多个包，它们共享一套 build/install/log。
- `colcon build` 构建所有包；`colcon build --packages-select xxx` 只构建指定包。
- 包之间有依赖（如 B 用 A 定义的消息）必须放**同一个 ws**，colcon 会按依赖顺序构建。
- 只有完全独立的项目才拆成多个 ws（各自一套 build/install/log）。

## source 的作用

`source xxx.bash` = 在**当前终端进程**里执行脚本，把环境变量、别名加载进来。

- `source /opt/ros/lyrical/setup.bash` → 能找到 `ros2` 命令和 ROS 库。
- `source ~/dev_ws/install/setup.bash` → 自己构建的包能被 `ros2 run` 找到。
- 环境变量是进程级的，新终端不继承，所以每个终端都要重新 source；写进 `~/.bashrc` 可自动加载。

不能直接 `./setup.bash`：`export` 只改子进程，脚本退出即丢；source 在当前进程执行才留得住。

`setup.bash` 内部是套娃：`setup.bash` → `setup.sh` → `local_setup.sh` → 各包的 `local_setup.bash`（`.` 是 `source` 的简写）。真正改的是四个变量：

| 变量 | 作用 |
|---|---|
| `PATH` | 找命令 |
| `LD_LIBRARY_PATH` | 找 .so |
| `AMENT_PREFIX_PATH` | **ROS 2 找包的核心** |
| `PYTHONPATH` | Python 模块 |

`ros2 run` / `ros2 pkg prefix` 都靠 `AMENT_PREFIX_PATH` 定位包。

## 从 .cpp 到可执行文件

三样东西接力：`package.xml`（声明要什么）+ `CMakeLists.txt`（声明怎么构建）+ `colcon build`（执行）。

**package.xml** 是依赖清单，不参与编译本身：

```xml
<depend>rclcpp</depend>
<depend>std_msgs</depend>
```

**CMakeLists.txt** 是构建规则：

| 行 | 作用 |
|---|---|
| `find_package(rclcpp REQUIRED)` | 找头文件 + 库位置 |
| `add_executable(my_node src/my_node.cpp)` | 声明一个可执行文件 |
| `target_link_libraries(my_node ${rclcpp_TARGETS})` | 链接依赖 |
| `install(TARGETS my_node DESTINATION lib/${PROJECT_NAME})` | 装到 install |

一个 `.cpp` 对应一个 `add_executable`。

**编译四步**：预处理（展开 `#include`）→ 编译（源码到汇编）→ 汇编（到 `.o`，函数地址留空）→ 链接（`.o` + 库填地址）。

头文件给「声明」，让编译通过；库给「实现」，让链接通过。缺头文件是编译错，缺库是链接错。`${rclcpp_TARGETS}`（Lyrical 写法，等于 `rclcpp::rclcpp`）同时携带头文件路径和链接库，一行 `target_link_libraries` 搞定两者；旧 `ament_target_dependencies` 已移除。

## 构建体系三角色

| 角色 | 是什么 | 职责 |
|---|---|---|
| colcon | 构建工具（指挥） | 扫 `src/`、读 package.xml、按依赖顺序调度、装进 `install/` |
| ament | 构建系统（执行） | `ament_cmake` 基于 CMake；`ament_package()` 生成包元数据 |
| export | package.xml 的 `<export>` | 最关键 `<build_type>ament_cmake</build_type>`，告诉 colcon 用哪套系统 |

流水线：

```
colcon build
  → 读 package.xml 的 <export><build_type>ament_cmake</build_type>
  → 执行 CMakeLists.txt: find_package(ament_cmake) → 编译/链接 → ament_package()
  → 产物装进 install/ + 生成 ament index 元数据
  → source install/setup.bash 后，ros2 run 靠元数据找到包
```

`ament_package()` 生成的元数据在 `install/<包>/share/ament_index/resource/` 下；没有它，`ros2 pkg` / `ros2 run` 发现不了这个包，别的包也 `find_package()` 不到。纯 Python 包用 `ament_python`。

这里的 export 是 package.xml 标签，和 shell 的 `export` 命令无关。

## 产物与运行

编译产物在 `build/`，install 复制到 `install/project1/lib/project1/`；`source install/setup.bash` 写入环境变量；`ros2 run project1 my_node` 靠环境变量定位执行。改代码后要重新 build，`--symlink-install` 可让 install 软链源码、改动即时生效。

## 坑

- **CMake 注释是 `#`，不是 `//`**：`find_package(rclcpp REQUIRED) // 注释` 会报 `Parse error`。C/C++ 才用 `//`，package.xml 用 `<!-- -->`。
- 忘了 `ament_package()`：包构建成功但 `ros2 run` 找不到。
- 忘了 source：新终端里 `ros2 run` 报「包不存在」。
- 改代码没重新 build：运行的是旧可执行文件。

> PS：`colcon build --packages-select` 配合 `--symlink-install` 是日常迭代最快的组合。

build/install/log 属于工作空间、`src/` 下多包共享；`.cpp → 可执行` 由 package.xml 声明依赖、CMakeLists 声明规则，colcon 调度 ament 执行；source 把 `AMENT_PREFIX_PATH` 等变量加载进当前终端。
