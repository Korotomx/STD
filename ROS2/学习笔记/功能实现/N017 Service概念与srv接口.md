# Service 概念与 .srv 接口 · 功能实现 · N017

**时间:** 2026-10-05 14:19
**标签:** #功能实现 #Service服务 #Topic话题 #接口Interface
**关联:** [[N001 节点基础书写骨架]] [[N011 ROS2分层架构]]

## 疑惑点

Service 是什么？和 Topic 有什么区别？.srv 接口文件怎么写？

## 实际情况

1. **Service = 请求-响应**：客户端发请求，服务端处理返回响应，一来一回、一对一、一次性。
2. **vs Topic**：

   | | Topic | Service |
   |---|---|---|
   | 方向 | 单向(发布→订阅) | 双向(请求→响应) |
   | 关系 | 多对多 | 一对一 |
   | 持续性 | 持续 | 一次性 |
   | 接口 | .msg | .srv |
   | 用途 | 数据流 | 命令/查询 |

3. **类比**：Topic = 广播电台（一直播谁爱听谁听）；Service = 打电话（拨号→应答→挂断）。
4. **.srv 格式**：两段，请求 `---` 响应：

   ```
   # 请求（可为空）
   ---
   float64 x
   float64 y
   ```

5. **编译生成**：`<包名>::srv::<服务名>` 类型，含 `.Request` 和 `.Response` 两个子结构；`float64` → C++ `double`。

> **Note（连接 / 深化）：**
> - 连接：接口类型由 rosidl 生成，见 [[N011 ROS2分层架构]]、[[N014 从cpp到可执行文件]]。
> - 深化：Service 是「拉」（客户端主动调），Topic 是「推」（发布者主动发）。

## 思考

（留白 —— 想想「周期性查位置」用 Service 是轮询，若改成 Topic 就是推送，两者在实时性上的取舍）

## 总结

**本质：** Service 是请求-响应的双向通信，接口用 .srv（请求 + 响应两段），编译生成 Request/Response 类型。
