# 订阅者与回调参数 · 功能实现 · N010

**时间:** 2026-10-04 17:19
**标签:** #功能实现 #Subscriber订阅者 #Callback回调 #stdbind #通信
**关联:** [[N001 节点基础书写骨架]] · [[N006 stdbind与回调]] · [[N002 QoS队列深度10]]

## 疑惑点

`listener.cpp`（订阅端）怎么拆解？它和 talker 的差别在哪？`std::bind(..., this, _1)` 里多出来的 `_1` 是什么？回调的 `const ... &` 参数又是什么？

## 实际情况

listener 和 talker 是**同一套骨架**，差别只在通信件：talker 用 publisher + timer，listener 用 subscription。唯一的新知识点在**订阅回调如何接收消息**。

```cpp
#include <functional>   // std::bind / std::placeholders
#include <memory>       // std::make_shared / shared_ptr
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using std::placeholders::_1;   // ← talker 里没有，占位符

class Listener : public rclcpp::Node
{
public:
  Listener() : Node("listener")
  {
    subscription_ = this->create_subscription<std_msgs::msg::String>(
      "topic", 10, std::bind(&Listener::topic_callback, this, _1));
  }
private:
  void topic_callback(const std_msgs::msg::String & msg) const
  {
    RCLCPP_INFO(this->get_logger(), "I heard: '%s'", msg.data.c_str());
  }
  rclcpp::Subscription<std_msgs::msg::String>::SharedPtr subscription_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Listener>());
  rclcpp::shutdown();
  return 0;
}
```

分点拆解：

1. **`using std::placeholders::_1`** —— 占位符，这是 talker 里没有的。
2. **`create_subscription` 三个参数**：话题名 `"topic"`、队列 `10`、callable。话题名必须和 talker 发布的**完全一致**，靠字符串对上、双方互不知道对方（解耦）。
3. **`std::bind(&Listener::topic_callback, this, _1)` —— 比 talker 的 timer 多了 `_1`**。

**重点（实质解析）：**

- `std::bind` 把「成员函数 + this」打包成 callable（见 N006）。但订阅回调**要接收消息**，这个消息是框架收到消息时**自动传进来的**，不是我们自己传。
- `_1` 是占位符，表示「这个 callable 的第 1 个参数」→ 对应回调的第 1 个形参。所以 `bind(&topic_callback, this, _1)` = 打包成「接收 1 个参数 msg，调用 `this->topic_callback(msg)`」的可调用对象。
- **对比**：timer 的回调 `timer_callback()` 无参数，所以 `bind(&timer_callback, this)` 没有 `_1`。
- **一句话记法：`_1` 的个数 = 回调里需要框架传入的参数个数。**

**回调的参数形式：**

- `const std_msgs::msg::String & msg` —— **const 引用**传参：不拷贝消息（消息可能较大）、const 保证不修改原消息。
- 函数末尾的 `const`（常成员函数）—— 表示这个回调不修改 `this` 的成员变量。
- `msg.data.c_str()` —— `data` 是 String 消息里的 string 字段，`c_str()` 转成 C 字符串给 `RCLCPP_INFO`（printf 风格的 `%s`）。

> **Note（连接 / 深化）：**
> - 连接：节点骨架见 [[N001 节点基础书写骨架]]；bind 原理见 [[N006 stdbind与回调]]；队列 10 见 [[N002 QoS队列深度10]]。
> - 深化：订阅回调参数另一种常见写法是 `const std_msgs::msg::String::SharedPtr & msg`（共享指针）；`_1` `_2` 对应多个参数；lambda 写法 `[this](const std_msgs::msg::String & msg){ ... }` 更直观。

## 总结

**本质：** 订阅端与发布端共用同一节点骨架，差别只在「用 create_subscription 建订阅者」；订阅回调要接收消息，所以 bind 用 `_1` 占位符把框架传入的消息接到回调形参上，回调参数用 const 引用避免拷贝。
