# 四大通信机制 · 常用语法速查表

> 一句话记住分工：**话题传数据 / 服务发命令 / 动作做长任务 / 参数存配置**。
> 每个 API 一句话讲功能，详细拆解见对应 N 编号笔记（双链）。
> 每个机制末尾附一段「最小完整类」骨架，拼上第 5 节的通用 `main` 即可跑。

## 0. 四机制一句话对比

| 机制 | 本质 | 方向 | 接口文件 | 典型 API |
| ---- | ---- | ---- | ---- | ---- |
| 话题 Topic | 持续数据流 | 发布者→订阅者（1→N） | `.msg` | `create_publisher` / `create_subscription` |
| 服务 Service | 一次请求/应答 | 客户端→服务端（1→1） | `.srv` | `create_service` / `create_client` |
| 动作 Action | 长任务（带反馈） | 客户端→服务端（1→1） | `.action` | `create_server` / `create_client` |
| 参数 Parameter | 配置键值对 | 节点内 / 跨节点 | 无（内置） | `declare_parameter` / `get_parameter` / `set_parameter` |

## 1. 话题 Topic

### 发布端
- `create_publisher<Msg>("topic", 10)` — 声明发布者，`10` 是 QoS 队列深度
- `publish(msg)` — 把一条消息发出去
- `std::make_shared<Msg>()` — 造一条消息对象

### 订阅端
- `create_subscription<Msg>("topic", 10, cb)` — 声明订阅者，消息到了自动调 `cb`
- `cb(const Msg::SharedPtr msg)` — 订阅回调，收到消息时触发

### QoS（服务质量）
- `rclcpp::QoS(10)` — 队列深度 10（Keep Last）
- `.reliable()` / `.best_effort()` — 可靠性：可靠重传 / 尽力而为
- `.transient_local()` — 持久化，后来的订阅者也能收到历史最后一条

### 回调绑定
- `std::bind(&Cls::method, this, std::placeholders::_1)` — 把「成员函数 + this」打包成可调用对象
- `[this](const Msg::SharedPtr msg) {...}` — lambda 写法，`[this]` 捕获 this

### 最小完整类（发布端 + 订阅端）

```cpp
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"
using namespace std::chrono_literals;

// 发布端：每秒发一条 String
class Talker : public rclcpp::Node {
public:
  Talker() : Node("talker") {
    pub_   = this->create_publisher<std_msgs::msg::String>("chatter", 10);
    timer_ = this->create_wall_timer(1s, std::bind(&Talker::timer_cb, this));
  }
private:
  void timer_cb() {
    std_msgs::msg::String msg;
    msg.data = "hello";
    pub_->publish(msg);                            // 栈对象直接 publish（引用重载）
  }
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
};

// 订阅端：收到消息打日志
class Listener : public rclcpp::Node {
public:
  Listener() : Node("listener") {
    sub_ = this->create_subscription<std_msgs::msg::String>(
      "chatter", 10, std::bind(&Listener::cb, this, std::placeholders::_1));
  }
private:
  void cb(const std_msgs::msg::String::SharedPtr msg) {   // 回调参数是 SharedPtr
    RCLCPP_INFO(this->get_logger(), "收到: %s", msg->data.c_str());
  }
  rclcpp::Subscription<std_msgs::msg::String>::SharedPtr sub_;
};
```

## 2. 服务 Service

### 接口文件 `.srv`
- 请求/应答两段，用 `---` 分隔：`int32 x` / `---` / `int32 sum`

### 服务端
- `create_service<Srv>("srv", cb)` — 声明服务端
- `cb(const Srv::Request::SharedPtr req, Srv::Response::SharedPtr res)` — 服务回调，读 `req` 写 `res`

### 客户端
- `create_client<Srv>("srv")` — 声明客户端
- `client->wait_for_service(timeout)` — 等服务端上线
- `client->async_send_request(req, cb)` — 异步发请求（回调里拿响应，不阻塞）——正统姿势
- `client->send_request(req)`（老 API）— 同步发、会阻塞，回调里用会死锁（见 [[E004 运行时-Service客户端等响应的死锁与executor冲突]]）

### 等响应
- `future.get()` — 拿结果，阻塞当前线程，只在「结果已就绪」时用
- `shared_future` — 异步结果的「凭证」，配合 `async_send_request`（见 [[N030 future机制异步结果的凭证]]）
- `rclcpp::spin_until_future_complete(node, future, timeout)` — main 里一次性调用时等结果（等期间持续 spin，不死锁）

### 最小完整类（服务端 + 客户端，add_two_ints）

```cpp
#include "rclcpp/rclcpp.hpp"
#include "example_interfaces/srv/add_two_ints.hpp"
using namespace std::chrono_literals;
using AddTwoInts = example_interfaces::srv::AddTwoInts;

// 服务端：回调里算和、写 res，返回即自动回复
class AddServer : public rclcpp::Node {
public:
  AddServer() : Node("add_two_ints_server") {
    srv_ = this->create_service<AddTwoInts>(
      "add_two_ints",
      std::bind(&AddServer::cb, this, std::placeholders::_1, std::placeholders::_2));
  }
private:
  void cb(const AddTwoInts::Request::SharedPtr  req,   // 读请求
          AddTwoInts::Response::SharedPtr res) {       // 写响应
    res->sum = req->a + req->b;
  }
  rclcpp::Service<AddTwoInts>::SharedPtr srv_;
};

// 客户端：定时器里异步调用（节点正在 spin，用回调姿势，不死锁）
class AddClient : public rclcpp::Node {
public:
  AddClient() : Node("add_two_ints_client") {
    client_ = this->create_client<AddTwoInts>("add_two_ints");
    timer_ = this->create_wall_timer(2s, std::bind(&AddClient::call, this));
  }
private:
  void call() {
    if (!client_->wait_for_service(1s)) return;          // 没上线就下周期再试
    auto req = std::make_shared<AddTwoInts::Request>();
    req->a = 3; req->b = 4;
    client_->async_send_request(req,                     // 异步 + 回调（见 [[N019 客户端实现 create_client]]）
      [this](rclcpp::Client<AddTwoInts>::SharedFuture f) {
        RCLCPP_INFO(this->get_logger(), "3+4=%ld", f.get()->sum);
      });
  }
  rclcpp::Client<AddTwoInts>::SharedPtr client_;
  rclcpp::TimerBase::SharedPtr timer_;
};
```

## 3. 动作 Action

### 接口文件 `.action`
- 三段：目标 goal / 结果 result / 反馈 feedback，用两个 `---` 分隔（见 [[N034 Action概念与action接口]]）

### 服务端
- `rclcpp_action::create_server<Action>(node, name, 3个回调)` — 声明动作服务端（见 [[N035 动作服务端 create_server]]）
- `handle_goal` → `GoalResponse` — 收到目标，决定接受/拒绝
- `handle_cancel` → `CancelResponse` — 收到取消，决定同意/拒绝
- `handle_accepted` — 目标被接受后起线程执行 `execute`
- `goal_handle->publish_feedback(fb)` — 持续回报进度
- `goal_handle->is_canceling()` — 每圈查是否被请求取消
- `goal_handle->succeed(result)` / `canceled(result)` — 交结果（成功 / 已取消）

### 客户端
- `rclcpp_action::create_client<Action>(node, name)` — 声明动作客户端（见 [[N036 动作客户端 create_client]]）
- `wait_for_action_server(timeout)` — 等动作服务端上线
- `async_send_goal(goal, options)` — 异步发目标
- `options.feedback_callback` — 收持续反馈
- `options.result_callback` — 收最终结果，`result.code` 区分 SUCCEEDED / ABORTED / CANCELED

### 最小完整类（服务端 + 客户端，自定义 `turtle_patrol/action/Patrol`）

> 依赖自定义 `.action`（`action/Patrol.action`：goal=`float32 duration` / result=`bool completed`+`string message` / feedback=`float32 elapsed`），完整可编译版见 [[N035 动作服务端 create_server]]、[[N036 动作客户端 create_client]]。

```cpp
#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "turtle_patrol/action/patrol.hpp"   // 自定义 action 生成头（snake_case）
using Patrol = turtle_patrol::action::Patrol;
using GoalHandle = rclcpp_action::ServerGoalHandle<Patrol>;

// 服务端：三个生命周期回调 + execute 线程
class PatrolServer : public rclcpp::Node {
public:
  PatrolServer() : Node("patrol_server") {
    server_ = rclcpp_action::create_server<Patrol>(
      this, "patrol",
      std::bind(&PatrolServer::handle_goal, this, _1, _2),     // ① 接目标
      std::bind(&PatrolServer::handle_cancel, this, _1),       // ② 接取消
      std::bind(&PatrolServer::handle_accepted, this, _1));    // ③ 目标被接受
  }
private:
  rclcpp_action::GoalResponse handle_goal(
      const rclcpp_action::GoalUUID &, std::shared_ptr<const Patrol::Goal> goal) {
    return goal->duration > 0 ? rclcpp_action::GoalResponse::ACCEPT_AND_EXECUTE
                              : rclcpp_action::GoalResponse::REJECT;
  }
  rclcpp_action::CancelResponse handle_cancel(const std::shared_ptr<GoalHandle>) {
    return rclcpp_action::CancelResponse::ACCEPT;
  }
  void handle_accepted(const std::shared_ptr<GoalHandle> gh) {
    std::thread{std::bind(&PatrolServer::execute, this, _1), gh}.detach();  // 起线程跑
  }
  void execute(const std::shared_ptr<GoalHandle> gh) {
    auto fb = std::make_shared<Patrol::Feedback>();
    rclcpp::Rate rate(1.0);
    while (!gh->is_canceling()) {          // 每圈查取消
      fb->elapsed += 1.0f;
      gh->publish_feedback(fb);            // 持续回报进度
      rate.sleep();
    }
    auto result = std::make_shared<Patrol::Result>();
    result->completed = true;
    result->message = "done";
    gh->succeed(result);                   // 交成功（被取消则 gh->canceled(result)）
  }
  rclcpp_action::Server<Patrol>::SharedPtr server_;
};

// 客户端：等服务端 → 发目标（挂反馈 + 结果两个回调）
class PatrolClient : public rclcpp::Node {
public:
  PatrolClient() : Node("patrol_client") {
    client_ = rclcpp_action::create_client<Patrol>(this, "patrol");
    if (client_->wait_for_action_server(5s)) send_goal();
  }
private:
  void send_goal() {
    auto goal = Patrol::Goal();
    goal.duration = 10.0f;
    auto options = rclcpp_action::Client<Patrol>::SendGoalOptions();
    options.feedback_callback =                       // 收中间进度（持续触发）
      [this](rclcpp_action::ClientGoalHandle<Patrol>::SharedPtr,
             std::shared_ptr<const Patrol::Feedback> fb) {
        RCLCPP_INFO(this->get_logger(), "已巡逻 %.0f 秒", fb->elapsed);
      };
    options.result_callback =                         // 收最终结果（结束触发一次）
      [this](const rclcpp_action::ClientGoalHandle<Patrol>::WrappedResult & r) {
        if (r.code == rclcpp_action::ResultCode::SUCCEEDED)   // SUCCEEDED/ABORTED/CANCELED
          RCLCPP_INFO(this->get_logger(), "完成: %s", r.result->message.c_str());
      };
    client_->async_send_goal(goal, options);
  }
  rclcpp_action::Client<Patrol>::SharedPtr client_;
};
```

## 4. 参数 Parameter

### 声明 / 读 / 写（节点内）
- `declare_parameter("name", 默认值)` — 声明参数，默认值同时定下类型（见 [[N025 参数的声明读写与命令行工具]]）
- `get_parameter("name").as_int() / .as_double() / .as_string() / .as_bool()` — 读参数（要 `.as_xxx()` 转类型）
- `set_parameter(rclcpp::Parameter("name", 值))` — 改自己的参数
- `has_parameter("name")` — 判断某参数是否已声明

### 参数回调（被改时通知）
- `add_pre_set_parameters_callback(cb)` — 写入**前**（可改参数列表），签名 `void(vector<Parameter>&)`
- `add_on_set_parameters_callback(cb)` — 写入**前**（可拒绝修改），签名 `SetParametersResult(const vector&)`
- `add_post_set_parameters_callback(cb)` — 写入**后**（读新值），签名 `void(const vector&)`（见 [[N028 参数服务与参数回调]]、[[E005 运行时-参数回调用错时机导致转发慢一拍]]）

### 参数客户端（改别的节点）
- `rclcpp::AsyncParametersClient(node, "对方节点名")` — 异步参数客户端（回调里用，不死锁）
- `rclcpp::SyncParametersClient(node, "对方节点名")` — 同步参数客户端（主流程用）
- `client->set_parameters({Parameter("x", 1)}, cb)` — 异步设置对方参数
- `client->wait_for_service(timeout)` — 等对方参数服务上线

### 命令行
- `ros2 param list / get / set / describe / dump / load` — 列 / 读 / 写 / 描述 / 导出 / 加载
- `--ros-args -p x:=1` — 命令行直接设参数
- `--ros-args --params-file f.yaml` — 从 YAML 文件加载（见 [[N033 YAML参数文件与配置分离]]）

### 最小完整类（声明 + 读 + 被改通知）

```cpp
#include "rclcpp/rclcpp.hpp"

class ParamNode : public rclcpp::Node {
public:
  ParamNode() : Node("param_node") {
    this->declare_parameter("background_r", 30);      // 声明（默认值定类型）
    this->declare_parameter("speed", 1.5);
    this->declare_parameter("robot_name", "turtle1");

    // 被外部改后触发：读新值 + 应用
    cb_handle_ = this->add_post_set_parameters_callback(
      [this](const std::vector<rclcpp::Parameter> & params) {
        for (const auto & p : params) {
          if (p.get_name() == "background_r")
            RCLCPP_INFO(this->get_logger(), "新背景色 = %ld", p.as_int());
        }
      });

    int r = this->get_parameter("background_r").as_int();   // 读：先 get 再 .as_int()
    this->set_parameter(rclcpp::Parameter("speed", 2.0));   // 写自己
  }
private:
  rclcpp::node_interfaces::PostSetParametersCallbackHandle::SharedPtr cb_handle_;
};
```

## 5. 通用骨架 / 运行

- `rclcpp::init(argc, argv)` — 初始化 ROS2
- `rclcpp::spin(node)` — 单节点单线程跑起来（事件循环）
- `rclcpp::shutdown()` — 优雅关闭
- `MultiThreadedExecutor` — 多线程执行器，多回调并发（见 [[N023 main函数变厚 executor演进]]）
- `create_wall_timer(2s, cb)` — 周期定时器
- `this->get_logger()` + `RCLCPP_INFO(...)` — 打日志

### 通用 main 模板

> 上面第 1~4 节每个「最小完整类」，拼上这个 `main` 就是一个可跑节点（把 `Talker` 换成对应类名即可）。

```cpp
int main(int argc, char ** argv) {
  rclcpp::init(argc, argv);                       // ① 初始化
  rclcpp::spin(std::make_shared<Talker>());       // ② 创建节点 + 进入事件循环（阻塞到 Ctrl+C）
  rclcpp::shutdown();                             // ③ 收尾
  return 0;
}
```

## 6. ROS2 CLI 常用指令速查

> 统一格式 `ros2 <子命令> <动词> [参数]`，任何一层都能 `--help` 看用法。
> `< >` 必填、`[ ]` 可选；`'{...}'` 里是 YAML 格式的数据；`-t` = 顺带打印类型。

### 6.1 环境 & 运行
- `source /opt/ros/lyrical/setup.bash` — 每个新终端必 source（Lyrical 发行版）
- `source install/setup.bash` — 构建后再 source 自己的工作空间
- `ros2 run <包> <可执行>` — 跑一个节点，如 `ros2 run turtlesim turtlesim_node`
- `ros2 launch <包> <launch文件>` — 跑 launch，如 `ros2 launch turtle_chase_game turtle_chase_game.launch.py`

### 6.2 节点 node
- `ros2 node list` — 列出运行中的节点
- `ros2 node info <节点>` — 看该节点的订阅 / 发布 / 服务 / 动作 / 参数全景

### 6.3 话题 topic
- `ros2 topic list` / `list -t` — 列话题 / 带类型
- `ros2 topic info <话题>` — 类型 + 发布者 + 订阅者
- `ros2 topic type <话题>` — 只看类型
- `ros2 topic echo <话题>` — 实时打印消息（`--once` 只打印一条）
- `ros2 topic hz <话题>` / `bw <话题>` — 测发布频率 / 带宽
- `ros2 topic pub <话题> <类型> '{数据}'` — 发一条（`-r <Hz>` 循环发），如
  `ros2 topic pub -r 1 /chatter std_msgs/msg/String 'data: hello'`
- `ros2 topic find <类型>` — 反查哪些话题用这个类型

### 6.4 服务 service
- `ros2 service list` / `list -t` — 列服务 / 带类型
- `ros2 service type <服务>` — 看某服务的类型
- `ros2 service find <类型>` — 反查哪些服务用这个类型
- `ros2 service call <服务> <类型> '{请求}'` — 调一次，如
  `ros2 service call /add_two_ints example_interfaces/srv/AddTwoInts '{a: 3, b: 4}'`

### 6.5 动作 action
- `ros2 action list` — 列动作
- `ros2 action info <动作>` — 看动作的客户端 / 服务端
- `ros2 action send_goal <动作> <类型> '{目标}'` — 发目标（`--feedback` 持续显示反馈），如
  `ros2 action send_goal /patrol turtle_patrol/action/Patrol '{duration: 10.0}' --feedback`

### 6.6 接口 interface（拿不准类型名时先问它）
- `ros2 interface list` / `list -m` — 列所有接口 / 只看 msg（`-s` 看 srv、`-a` 看 action）
- `ros2 interface show <类型>` — 看接口定义，如 `ros2 interface show turtlesim_msgs/srv/Spawn`
- `ros2 interface package <包>` — 某包的所有接口
- `ros2 interface proto <类型>` — 生成一条消息的 YAML 模板（配合 topic pub / service call 填空）

### 6.7 参数 param（详见第 4 节）
- `ros2 param list [节点]` — 列参数（不写节点则列全部）
- `ros2 param get / set / describe / dump / load` — 读 / 写 / 描述 / 导出 / 加载

### 6.8 包 & 构建
- `ros2 pkg list` — 列出所有包
- `ros2 pkg prefix <包>` — 包安装路径
- `ros2 pkg executables <包>` — 包里的可执行文件
- `ros2 pkg create --build-type ament_cmake <包>` — 新建 C++ 包（可加 `--dependencies rclcpp`）
- `colcon build` — 全量构建
- `colcon build --packages-select <包>` — 只构建某包
- `colcon build --symlink-install` — 符号链接安装（改代码免重装，Python 常用）

### 6.9 运行时重映射 & 其他
- `ros2 run <包> <节点> --ros-args -r /旧话题:=/新话题` — 重映射 remap
- `ros2 run <包> <节点> --ros-args -p 参数:=值` — 运行时设参数
- `ros2 daemon stop` — 重启守护进程（`ros2 node/topic list` 不刷新时用）
- `ros2 doctor` — 环境体检
- `rqt_graph` — 图形化看节点 / 话题关系图
