参数是节点运行时的键值对配置，存在节点内建的 map 容器里，不是成员变量。`declare` 登记、`get/set` 按名字查改；容器通过参数服务对外开放、通过参数回调对内通知；YAML 则把参数值从代码里搬进配置文件。

## 参数与四大机制

| 机制 | 一句话 | 类比 | 接口 | 关系 | 持续性 |
|---|---|---|---|---|---|
| Topic | 单向持续数据流 | 广播电台 | `.msg` | 多对多 | 持续 |
| Service | 一次性请求-响应 | 打电话 | `.srv` | 一对一 | 一次性 |
| Action | 长任务 + 反馈 + 可取消 | 外卖下单 | `.action` | 一对一 | 长时 |
| Parameter | 读写配置 | 设置菜单 / 旋钮 | 无（键值对） | 节点私有 | 持久 |

分工：改配置用参数（长期生效），传数据用话题，发命令/查询用服务。参数底层是 Service 的特化——每个节点天生自带一组隐藏的参数服务。

## 声明、读写、命令行

```cpp
this->declare_parameter("background_r", 30);          // 声明 + 默认值
int r = this->get_parameter("background_r").as_int(); // 先拿 Parameter 再转类型
this->set_parameter(rclcpp::Parameter("background_r", 255));
```

- 必须先声明才能 get，否则抛 `ParameterNotDeclaredException`；重复声明抛 `ParameterAlreadyDeclaredException`。
- 默认值同时定下类型；`get_parameter` 返回 `rclcpp::Parameter` 对象，用 `.as_int() / .as_double() / .as_string() / .as_bool()` 转，类型对不上抛异常。
- `set_parameter` 改自己；外部改走参数服务。
- `get_parameter_or("speed", 1.0)` 未声明时也能读默认值；参数类型由首次声明固定，之后不能改。

声明时可带描述与取值范围，`ros2 param describe` 能看到：

```cpp
rcl_interfaces::msg::ParameterDescriptor desc;
desc.description = "背景红色分量";
desc.integer_range.resize(1);
desc.integer_range[0].from_value = 0;
desc.integer_range[0].to_value   = 255;
this->declare_parameter("background_r", 30, desc);
```

命令行：

```bash
ros2 param list /turtle_painter
ros2 param get  /turtle_painter background_r
ros2 param set  /turtle_painter background_r 255
ros2 param describe /turtle_painter background_r
ros2 param dump /turtle_painter > p.yaml
ros2 param load /turtle_painter p.yaml
```

以 `turtle_painter` 为例：声明 `background_r/g/b`（默认 `30 / 144 / 255`），`ros2 param set` 就能改背景色。

## 参数存在哪

参数**不是 C++ 成员变量**。`double speed_;` 编译期定死；`declare_parameter` 是往节点内部的运行时容器登记一个「名字 → 值」条目：

```
参数容器（节点内建）
┌────────────────────────────┐
│ "background_r"  →  30      │
│ "background_g"  →  144     │
│ "background_b"  →  255     │
└────────────────────────────┘
```

`get_parameter(name)` = 按名字查容器，`set_parameter` = 按名字改值。参数是「运行时按名字查」，不是「编译期按变量名访问」。

用容器而不是成员变量，是因为参数要：能被外部按字符串名字访问、能动态增删、能序列化后通过参数服务收发。`rclcpp::Parameter` 内部用 `std::variant` 存值，所以一个容器能混存 int / double / string / bool / 数组。

## 参数服务与回调

节点启动就自动挂一组隐藏服务：

```
/turtle_painter/list_parameters
/turtle_painter/get_parameters
/turtle_painter/get_parameter_types
/turtle_painter/set_parameters
/turtle_painter/set_parameters_atomically
/turtle_painter/describe_parameters
```

`ros2 param` 就是这些服务的客户端（`get` → `get_parameters`、`set` → `set_parameters`、`list` → `list_parameters`）。

代码里跨节点改参数用 `AsyncParametersClient`，等价于 `ros2 param set`：

```cpp
auto client = std::make_shared<rclcpp::AsyncParametersClient>(this, "/turtle_painter");
client->wait_for_service();
auto future = client->set_parameters({rclcpp::Parameter("background_r", 255)});
auto results = future.get();       // main / 独立线程用；executor 回调里会死锁
bool ok = results[0].successful;   // 被 on_set 回调拒绝则为 false
```

被改后要响应，就注册回调：

```cpp
m_cb_handle = this->add_post_set_parameters_callback(
  std::bind(&TurtlePainter::on_param_change, this, std::placeholders::_1));

void on_param_change(const std::vector<rclcpp::Parameter> & params) {
  for (const auto & p : params)
    RCLCPP_INFO(this->get_logger(), "参数被改: %s", p.get_name().c_str());
  apply_color();
}
```

- 返回的 handle **必须存成员变量**，否则析构即注销回调。
- 回调一次收**一批**被改的参数。
- 时机有三种：`add_pre_set_parameters_callback`（写入前，可改参数列表）、`add_on_set_parameters_callback`（写入前，可拒绝，`get_parameter` 拿旧值）、`add_post_set_parameters_callback`（写入后，读新值）。转发/联动要用 post，否则「慢一拍」，见 [[错误记录]] E005。

完整链路：

```
外部 ros2 param set /turtle_painter background_r 255
  → 调 /turtle_painter/set_parameters
  → 更新容器里的 background_r
  → 触发 post_set 回调（联动 + 校验）
  → 结果回给外部
```

校验可以在 on_set 回调里返回 `successful = false` 拒绝修改，容器保持旧值。

## YAML：配置与代码分离

参数写死在代码或 launch 内联字典里，改一个值就要改代码。YAML 把参数值独立成文件，同一节点可用不同 YAML 跑出不同行为。

格式固定为「节点名 → `ros__parameters` → 键值对」：

```yaml
turtle_painter:
  ros__parameters:
    background_r: 30
    background_g: 144
    background_b: 255
    use_sim_time: false
```

- 一个文件可装有多个节点，并列写节点名块。
- `/**` 表示应用到所有节点：

```yaml
/**:
  ros__parameters:
    use_sim_time: true
```

加载方式一，launch 里传**文件路径字符串**：

```python
import os
from ament_index_python.packages import get_package_share_directory

cfg = os.path.join(get_package_share_directory('turtle_demo'), 'config', 'params.yaml')

Node(package='turtle_demo', executable='turtle_painter', name='turtle_painter',
     parameters=[cfg])                                  # 字符串 = 文件
```

传字典则是内联参数；两者可混用，后面的覆盖前面的：

```python
parameters=[cfg, {'background_b': 0}]
```

加载方式二，命令行：

```bash
ros2 run turtle_demo turtle_painter --ros-args --params-file /path/to/params.yaml
```

`ros2 param dump` 导出的正是这种「节点名 + `ros__parameters`」结构，所以能直接 load 回去。

YAML 值类型按字面量推断：`30` → integer、`3.14` → double、`true/false` → bool、`hello` → string、`[1,2,3]` → 数组。推断类型必须和 `declare_parameter` 的类型一致，否则加载报错。

## 坑

- **节点名不匹配静默失效**：YAML 顶层节点名必须和实际节点名（含命名空间）完全一致，对不上不报错，参数悄悄没加载。
- **YAML 布尔陷阱**：`yes/no/on/off` 都被当布尔值，想传字符串必须加引号。
- **参数回调时机**：on_set 读旧值，联动要用 post_set。
- **回调 handle 没存成员**：回调被注销。
- **YAML 缩进敏感**：层级靠空格，错一个空格层级就错。
- 参数名建议蛇形命名；`__` 开头是 rclcpp 内部保留。运行时改动不会自动写回 YAML，要 `dump` 才导出当前值。

> PS：YAML 是通用序列化格式，ROS 2 只是借用；Docker Compose、K8s、CI 配置都是 YAML。配置优先级链：命令行 `:=` > 内联参数 > YAML 文件 > 代码默认值。

参数 = 节点内 map 容器里的运行时配置，declare 登记、get/set 查改；参数服务对外开放、post_set 回调对内通知；YAML 把值独立成「节点名 + ros__parameters」的文件，启动时灌进容器。
