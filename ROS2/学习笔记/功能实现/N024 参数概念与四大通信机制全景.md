# 参数 Parameter 概念与四大通信机制全景 · 功能实现 · N024

**时间:** 2026-10-06 19:44
**标签:** #功能实现 #Parameter参数 #Topic话题 #Service服务 #Action动作 #架构Architecture
**关联:** [[N017 Service概念与srv接口]] [[N001 节点基础书写骨架]] [[N034 Action概念与action接口]]

## 疑惑点

参数 Parameter 是什么？它和话题、服务、动作这四大通信机制是怎么分工的？

## 实际情况

1. **参数 = 节点运行时的「可配置项」**：本质是键值对（key → value），存的是**配置**（颜色、速度上限、阈值、波特率…），而不是在传输数据。类比「设置菜单 / 旋钮」——拧一下、值变了、长期生效。

2. **四大通信机制全景**（在 [[N017 Service概念与srv接口]] 的 Topic/Service 基础上补全）：

   | 机制 | 一句话 | 类比 | 接口 | 关系 | 持续性 |
   |---|---|---|---|---|---|
   | Topic 话题 | 单向持续数据流 | 广播电台 | `.msg` | 多对多 | 持续 |
   | Service 服务 | 一次性请求-响应 | 打电话 | `.srv` | 一对一 | 一次性 |
   | Action 动作 | 长任务 + 反馈 + 可取消 | 外卖下单→配送→送达 | `.action` | 一对一 | 长时 |
   | Parameter 参数 | 读写配置 | 设置菜单 / 旋钮 | 无（键值对） | 节点私有 | 持久 |

3. **参数的三件基本操作**（概念层面，细节另开笔记）：
   - **声明** `declare_parameter(name, 默认值)` —— 节点先「报名」自己有哪些参数；
   - **读写** `get_parameter` / `set_parameter` —— 读自己 / 改自己；
   - **监听修改** `add_on_set_parameters_callback` —— 被外部 `ros2 param set` 改时触发回调。

4. **关键：参数底层是「服务」** —— 每个节点**天生自带一个隐藏的「参数服务」**。你敲 `ros2 param set`，或别的节点想改你的参数，走的都是这个服务。所以**参数 = Service 机制的特化应用**，正好接上 N017。

5. **分工：什么时候用参数** —— 要「改配置」用参数（改了长期生效）；要「传数据」用话题（持续流）；要「发命令 / 查询」用服务（一次性问答）。

> **Note（连接 / 深化）：**
> - 连接：参数服务本质是服务，见 [[N017 Service概念与srv接口]]；参数声明/读写的具体 API 与命令行工具将在下一条笔记展开。
> - 深化：参数是「**节点私有**」的，不像话题/服务那样是「图中公开」的连接；要读**别人**的参数，必须通过对方暴露的参数服务，而不是直接读它的内存。

## 总结

**本质：** 参数是节点运行时的键值对配置，底层靠每个节点自带的「参数服务」实现；四大机制分工——话题传数据、服务发命令、动作做长任务、参数存配置。
