## 疑惑点

参数 Parameter 是什么、和话题/服务/动作怎么分工？怎么声明、读写、命令行操作？参数存在哪（不是类成员变量吗）？外部怎么访问、被改后节点怎么知道？

## 实际情况

### 1. 概念：参数 = 节点运行时的「可配置项」（原 N024）

1. **参数 = 节点运行时的键值对（key → value）**，存的是**配置**（颜色、速度上限、阈值、波特率…），而不是在传输数据。类比「设置菜单 / 旋钮」——拧一下、值变了、长期生效。

2. **四大通信机制全景**：

   | 机制 | 一句话 | 类比 | 接口 | 关系 | 持续性 |
   |---|---|---|---|---|---|
   | Topic 话题 | 单向持续数据流 | 广播电台 | `.msg` | 多对多 | 持续 |
   | Service 服务 | 一次性请求-响应 | 打电话 | `.srv` | 一对一 | 一次性 |
   | Action 动作 | 长任务 + 反馈 + 可取消 | 外卖下单→配送→送达 | `.action` | 一对一 | 长时 |
   | Parameter 参数 | 读写配置 | 设置菜单 / 旋钮 | 无（键值对） | 节点私有 | 持久 |

3. **参数的三件基本操作**（概念层面）：**声明** `declare_parameter`（先「报名」）→ **读写** `get_parameter` / `set_parameter` → **监听修改** `add_on_set_parameters_callback`。

4. **关键：参数底层是「服务」**——每个节点**天生自带一个隐藏的「参数服务」**。你敲 `ros2 param set`，或别的节点想改你的参数，走的都是这个服务。所以**参数 = Service 机制的特化应用**。

5. **分工**：要「改配置」用参数（长期生效）；要「传数据」用话题（持续流）；要「发命令 / 查询」用服务（一次性问答）。

### 2. 声明 / 读 / 写 + 命令行工具（原 N025）

1. **声明 `declare_parameter`**（在构造函数里，先「报名」再使用）：

   ```cpp
   this->declare_parameter("background_r", 30);   // 参数名 + 默认值
   ```

   - 参数必须先声明才能 `get`，否则抛 `ParameterNotDeclaredException`；
   - **默认值同时定下类型**：`30` → 整数类型（内部用 variant 存，运行时才知道类型）；
   - 重复声明同名参数会抛 `ParameterAlreadyDeclaredException`。

2. **读 `get_parameter`**：

   ```cpp
   int r = this->get_parameter("background_r").as_int();  // 先拿 Parameter 对象，再 .as_xxx() 转类型
   ```

   - `get_parameter` 返回 `rclcpp::Parameter` 对象，要用 `.as_int() / .as_double() / .as_string() / .as_bool()` 转成具体类型；类型对不上会抛异常。

3. **写 `set_parameter`**（改自己）：

   ```cpp
   this->set_parameter(rclcpp::Parameter("background_r", 255));
   ```

   - 自己改自己；或由外部 `ros2 param set` 改（走参数服务，见第 1、4 节）。

4. **命令行工具**（以 `turtle_painter` 为例）：

   ```bash
   ros2 param list /turtle_painter                          # 列出有哪些参数
   ros2 param get  /turtle_painter background_r             # 读
   ros2 param set  /turtle_painter background_r 255         # 写（触发参数回调）
   ros2 param describe /turtle_painter background_r         # 看类型 / 描述
   ros2 param dump /turtle_painter > p.yaml                 # 导出配置
   ros2 param load /turtle_painter p.yaml                   # 从文件加载
   ```

5. **实战对照 `turtle_painter`**：声明 `background_r/g/b` 三个参数（默认 `30 / 144 / 255` 蓝色），运行中敲 `ros2 param set /turtle_painter background_r 255` 就能改背景色。

### 3. 存在哪：节点内的键值对容器（原 N026）

`declare_parameter("background_r", 30)` 看起来像是在「声明一个变量」。但类的成员变量是编译期就固定好的，运行时不能往类里动态加成员啊？那参数到底存在哪里？

**参数不是 C++ 成员变量**。类里的 `double speed_;` 是编译期定死的；而 `declare_parameter` 不是往类里加成员，是往节点内部的一个**运行时容器**里登记：

1. **每个 `rclcpp::Node` 内建一个「参数容器」**（键值对，本质类似 `std::map<std::string, rclcpp::Parameter>`），这是所有参数的「家」。

2. **`declare_parameter(name, default)` 的真相 = 往容器里塞一个键值对**：

   ```
   参数容器（节点内建）
   ┌────────────────────────────┐
   │ "background_r"  →  30      │  ← declare 就是登记这一行
   │ "background_g"  →  144     │
   │ "background_b"  →  255     │
   └────────────────────────────┘
   ```

   - 它做的是「登记一个 名字 → 值 的条目」，并标记「已声明」；所以 `declare` = **登记关联**，不是「声明一个成员变量」。

3. **`get_parameter(name)` = 按名字查容器**，返回 `Parameter` 对象；`set_parameter` = 按名字改容器里的值。参数是「运行时按名字查」的，不是「编译期按变量名访问」的。

4. **为什么用容器、不用成员变量？** 因为参数要：能被**外部按字符串名字**访问（成员变量做不到）；能**动态增删**；能**序列化**成消息、通过参数服务收发。→ 只有「键值对容器」天然满足这三点。

5. **类比**：类成员变量 = 盖房子时就定死的房间（编译期）；参数 = 一本「键值对登记表」，运行时随便往表里写一行、按名字查一行。

6. **深化**：`rclcpp::Parameter` 内部用 `std::variant` 存值，所以一个容器能**混存** int / double / string / bool / 数组——这是它和「强类型成员变量」最本质的区别。

### 4. 参数服务与参数回调：容器如何被访问和通知（原 N028）

参数存在节点内的 map 容器里，那外部（`ros2 param set`、别的节点）怎么访问？容器里的值被改后，节点自己怎么知道并响应？

1. **参数服务 = 访问容器的「对外入口」**。节点一启动就自动挂一组隐藏服务，用 `ros2 service list` 能看到：

   ```
   /turtle_painter/list_parameters
   /turtle_painter/get_parameters
   /turtle_painter/get_parameter_types
   /turtle_painter/set_parameters
   /turtle_painter/set_parameters_atomically
   /turtle_painter/describe_parameters
   ```

2. **`ros2 param` 命令就是这些服务的客户端**：`get` → `get_parameters`、`set` → `set_parameters`、`list` → `list_parameters`。所以参数 = **Service 的特化应用**。

3. **参数回调 = 容器被改后的「对内通知」**：

   ```cpp
   param_cb_handle_ = this->add_on_set_parameters_callback(
     std::bind(&TurtlePainter::on_param_change, this, std::placeholders::_1));
   ```

   - 返回的 handle **必须存成成员变量**，否则 handle 析构时回调会被自动注销；
   - 回调签名：`SetParametersResult cb(const std::vector<Parameter>& params)` —— 一次收**一批**被改的参数。

4. **回调还能「拒绝」修改（参数校验的入口）**：

   ```cpp
   rcl_interfaces::msg::SetParametersResult on_param_change(
     const std::vector<rclcpp::Parameter> & params)
   {
     for (const auto & p : params)
       RCLCPP_INFO(this->get_logger(), "参数被改: %s", p.get_name().c_str());
     apply_color();   // 联动：参数变了重新应用背景色

     rcl_interfaces::msg::SetParametersResult res;
     res.successful = true;   // 校验不合法可置 false，并填 res.reason
     return res;
   }
   ```

5. **完整链路**（外部改一次参数，容器和回调怎么配合）：

   ```
   外部: ros2 param set /turtle_painter background_r 255
     ↓ 调隐藏服务 /turtle_painter/set_parameters
   节点内:
     ① 参数服务收到请求
     ② 更新容器(map)里的 background_r → 255
     ③ 触发 on_set_parameters_callback(传入被改的参数)
     ④ 回调里做联动 + 校验
     ⑤ 回调返回 SetParametersResult
     ↓
   参数服务把结果回给外部
   ```

> **Note（连接 / 深化）：**
> - 连接：参数服务是 Service 的特化（[[N017 Service概念与srv接口]]）；`dump`/`load` 导出的就是 YAML 文件（[[N033 YAML参数文件与配置分离]]）；改**别的**节点的参数用参数客户端（[[N029 turtle_painter参数中转节点拆解]]）。
> - 深化（已纠正，2026-10-07）：`add_on_set_parameters_callback` 是在**参数写入之前**触发的（可拒绝修改），回调里 `get_parameter` 拿到的是**旧值**，新值在回调参数 `params` 里；要拿新值做联动，用 `add_post_set_parameters_callback`（写入之后触发）。三种回调时机对比见 [[E005 运行时-参数回调用错时机导致转发慢一拍]]。

## 思考

（留白 —— 参数明明是「节点私有」的，为什么还要靠「参数服务」这种跨节点通道去访问？这跟它的定位矛盾吗？）

> 当时自己答的几段：
> - 参数的改变可能会导致其他功能的实现出现变化，内部的变化要让外界知晓则需要向其他部分进行信息交流。
> - parameter 对象理论上是一个 map 容器，取用转成 int。
> - `this->undeclare_parameter("name");` 就可以删除参数，返回 bool。
> - 若回调返回 `successful = false` 拒绝修改，容器里的值应是**旧值**（未写入）。

## 总结

**本质：** 参数是节点运行时的键值对配置，存在节点内建的 map 容器里（不是成员变量）；`declare` = 往容器「登记」、`get/set` = 按名字查改容器。容器通过「参数服务」（= Service 特化）对外开放、通过「参数回调」对内通知；外部改参数 = 调 `set_parameters` 服务 → 更新容器 → 触发回调 → 返回结果，回调还能拒绝（校验）。四大机制分工——话题传数据、服务发命令、动作做长任务、参数存配置。
