# 参数存在哪：节点内的键值对容器 · 功能实现 · N026

**时间:** 2026-10-06 20:11
**标签:** #功能实现 #Parameter参数 #C++语法
**关联:** [[N024 参数概念与四大通信机制全景]] [[N025 参数的声明读写与命令行工具]]

## 疑惑点

`declare_parameter("background_r", 30)` 看起来像是在「声明一个变量」。但类的成员变量是编译期就固定好的，运行时不能往类里动态加成员啊？那参数到底存在哪里？

## 实际情况

（你的猜测是对的 —— 参数不是类成员，节点内部早就「建好了容器」，`declare` 只是往容器里登记关联。）

1. **参数不是 C++ 成员变量**。类里的 `double speed_;` 是编译期定死的；而 `declare_parameter` 不是往类里加成员，是往节点内部的一个**运行时容器**里登记。

2. **每个 `rclcpp::Node` 内建一个「参数容器」**（键值对，本质类似 `std::map<std::string, rclcpp::Parameter>`），这是所有参数的「家」。

3. **`declare_parameter(name, default)` 的真相 = 往容器里塞一个键值对**：

   ```
   参数容器（节点内建）
   ┌────────────────────────────┐
   │ "background_r"  →  30      │  ← declare 就是登记这一行
   │ "background_g"  →  144     │
   │ "background_b"  →  255     │
   └────────────────────────────┘
   ```

   - 它做的是「登记一个 名字 → 值 的条目」，并标记「已声明」；
   - 所以 `declare` = **登记关联**，不是「声明一个成员变量」。

4. **`get_parameter(name)` = 按名字查容器**，返回 `Parameter` 对象；`set_parameter` = 按名字改容器里的值。所以参数是「运行时按名字查」的，不是「编译期按变量名访问」的。

5. **为什么用容器、不用成员变量？** 因为参数要：
   - 能被**外部按字符串名字**访问（`ros2 param get /turtle_painter background_r`）——成员变量做不到「按名字从外部找」；
   - 能**动态增删**（运行时登记任意多个）；
   - 能**序列化**成消息、通过参数服务收发。

   → 只有「键值对容器」天然满足这三点。

6. **类比**：类成员变量 = 盖房子时就定死的房间（编译期）；参数 = 一本「键值对登记表」，运行时随便往表里写一行、按名字查一行。

> **Note（连接 / 深化）：**
> - 连接：参数服务之所以能「按名字」访问别人的参数（见 [[N024 参数概念与四大通信机制全景]]），正是因为参数存在这个按名字索引的容器里。
> - 深化：`rclcpp::Parameter` 内部用 `std::variant` 存值，所以一个容器能**混存** int / double / string / bool / 数组——这是它和「强类型成员变量」最本质的区别。

## 总结

**本质：** 参数不占类成员，而是存在节点内建的键值对容器里；`declare_parameter` 是往容器「登记」一个 名字 → 值，`get / set` 是按名字查改容器——因为参数要按名字被外部访问、动态增删、可序列化，所以用容器而非编译期成员。
