## 疑惑点

一个标准 rclcpp 节点到底由哪些部分组成？为什么是「类 + 继承 Node」的写法？

## 实际情况

7 部分固定骨架：

```cpp
#include "rclcpp/rclcpp.hpp"

class Talker : public rclcpp::Node {
public:
  Talker() : Node("talker") {                       // ③ 构造函数，节点名
    publisher_ = this->create_publisher<std_msgs::msg::String>("topic", 10); // ④
    timer_ = this->create_wall_timer(1s, std::bind(&Talker::timer_callback, this)); // ④
  }
private:
  void timer_callback() { /* ... */ }               // ⑤ 回调
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_; // ⑥ 成员变量
  rclcpp::TimerBase::SharedPtr timer_;              // ⑥
};

int main(int argc, char ** argv) {                  // ⑦ main 四步
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Talker>());
  rclcpp::shutdown();
  return 0;
}
```

① 头文件 → ② 类继承 `rclcpp::Node` → ③ 构造函数 `Node("名字")` → ④ 创建 publisher / subscription / timer → ⑤ 回调函数 → ⑥ 成员变量用 `SharedPtr` → ⑦ main 四步。

**重点强调：**

1. **节点名 ≠ 类名** —— `Node("talker")` 里的 `"talker"` 是运行时注册的节点名，`Talker` 只是 C++ 类名，两者无关。
2. **回调从不手动调用** —— 你只写逻辑，框架在合适时机自动调用（talker 由定时器触发、listener 由收消息触发）。
3. **没有 `spin` 节点启动后立刻退出** —— `spin` 是进入事件循环、阻塞到 Ctrl+C 的关键。
4. **⑥ 必须用成员变量（不是局部变量）** —— 回调里要用它，生命周期必须和节点一样长；局部变量在构造函数结束后销毁，回调再调用会崩。
5. **⑦ main 四步** —— `init`（初始化）→ `make_shared<Talker>()` + `spin`（创建节点并进入事件循环）→ `shutdown`（收尾）。

> **Note（连接 / 深化）：**
> - 连接：`spin` 内部是 Executor 在跑，见 [[N009 Executor事件循环]]；回调的 `std::bind` 写法可换成 lambda，见 [[N007 lambda表达式]]。
> - 深化：工程上常用「依赖注入」把参数传给节点构造函数；publisher/timer 常写成 `SharedPtr` 成员并带 `_` 后缀约定。

## 总结

**本质：** rclcpp 节点 = 「继承 `rclcpp::Node` 的类」，在构造函数里用 `create_*` 建通信件与定时器、用成员变量保存、靠回调响应事件，最后由 `main` 里 `init → spin → shutdown` 驱动。
