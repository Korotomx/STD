句柄 = 身份令牌 + 操控把手 + 生命周期拴绳，ROS 2 里通常就是一个 `SharedPtr`；你拿到的不是资源本身，而是和它对话的凭证。实例 = 照「类」这张图纸造出来的实物，占一块运行期内存。

## 句柄

ROS 2 的通信对象（发布者、订阅者、定时器、动作目标、回调）都有三种需求：标识、操控、管生命周期。句柄把这三样打包。

| 类型 | 例子 | 作用 |
|---|---|---|
| 资源句柄 | `Publisher<Twist>::SharedPtr`、`TimerBase::SharedPtr` | 拴住资源，析构自动释放 |
| 目标句柄 | `ServerGoalHandle` / `ClientGoalHandle` | 标识某个具体目标，反馈/取消都挂在它身上 |
| 回调句柄 | `OnSet/PostSetParametersCallbackHandle` | 存着以后能注销 |

**生命线机制**：句柄（shared_ptr）析构 → 对应东西自动注销/释放。所以参数回调的 handle 必须存成员变量，否则构造函数一结束、句柄析构、回调被注销。

future 本质也是一种句柄——异步结果的取餐号，见 [[N009 Executor事件循环]]。

### 经典原型：文件描述符

```c
int fd = open("file.txt", O_RDONLY);   // 返回 int，不是文件本身
read(fd, buf, sizeof(buf));            // 拿它读写
close(fd);                             // 拿它释放
```

你从头到尾没见过内核里的 FILE / inode；OS 内部维护「fd → 打开文件」的表。这个 int 就是句柄：不是资源，是资源的代号。

### 全谱系

| 句柄 | 载体 | 代表的资源 |
|---|---|---|
| 文件描述符 fd | int | 打开的文件 |
| 窗口句柄 HWND | 整数/指针 | 窗口 |
| 裸指针 | 内存地址 | 内存对象 |
| `shared_ptr` | 对象 | 堆对象（引用计数） |
| future | 对象 | 异步结果 |
| `Publisher::SharedPtr` | 智能指针 | 发布者 |
| `ServerGoalHandle` | 对象 | 某个动作目标 |

载体从 int 到对象都叫句柄，因为做的事一样：不直接给资源，给一个能标识、操控、管生命周期的抽象引用。好处是封装（内部布局不可见）、安全（拿不到裸地址）、生命周期明确（析构即释放/注销）。

## 实例

类是图纸，实例是照着图纸造出来的实物。类在编译期决定内存布局和操作，本身（除 static 成员）不占运行期数据内存；实例是运行期分配的一块内存，装自己的数据。

```cpp
class Turtle {
  double x = 0, y = 0;
  void move(double dx, double dy) { x += dx; y += dy; }
};

Turtle t1;              // 实例 1，自己一块内存
Turtle t2;              // 实例 2，另一块内存
t1.move(1, 0);          // 只改 t1
```

类 → 实例的过程叫实例化：

```cpp
auto node = std::make_shared<rclcpp::Node>("my_node");
```

`rclcpp::Node` 是类，`make_shared` 造出来的是 Node 实例。一个类型是类的变量，它就是实例（或实例的引用/指针）。

## 坑

- 句柄不存成员 → 回调/资源提前注销。
- 同一个回调注册两次会得到两个句柄，析构其中一个不会注销回调（每个句柄独立管理）。
- 类与实例别混：`sizeof` 是类决定的布局大小，实例是这份布局的一个落点。

> PS：句柄内部通常只有「指向所属对象的弱引用 + 唯一 id」，所以轻量、可拷贝、析构即注销，是 RAII 的典型体现。

句柄是资源的抽象引用（标识 + 操控 + 生命周期），形式上从 int 到智能指针不等；实例是类在运行期的一块具体内存，类 → 实例叫实例化。
