栈和堆是两种存储：栈靠移动一个栈指针，极快但大小与生命周期受编译期和嵌套关系限制；堆靠 allocator 记账，灵活但慢、会有碎片。本质是「速度 vs 灵活性」的权衡。

## 内存布局

```
高地址
┌──────────────────┐
│ 栈 (stack)        │  从高向低生长，每线程独享，约 8MB
│        ↓          │
│  ─── 未使用 ───   │  栈向下、堆向上，撞上即耗尽
│        ↑          │
│ 堆 (heap)         │  从低向高生长，全进程共享
├──────────────────┤
│ BSS / 数据段 / 代码段 │
└──────────────────┘
低地址
```

## 栈：一个寄存器就够

- 局部变量大小编译期确定，函数入口 `sub rsp, N` 一次划好整个栈帧；「分配一个 int」只是用 `rbp` 减固定偏移访问，零分配成本。
- 函数返回 `add rsp, N` 把指针拨回去，整个帧释放；**不清空数据**，下次调用直接覆盖。
- 严格后进先出（LIFO），函数调用链天然嵌套，所以一个指针就能管理。
- 代价：固定大小（默认 8MB/线程）、生命周期绑死作用域、递归太深或局部大数组会栈溢出。

## 堆：要有人记账

`new/delete` 底层调 `malloc/free`，内部用空闲链表记录哪些块可用：

- `malloc(n)`：找 ≥ n 的块，太大就 split，在返回地址前写「头」记录大小，返回头后面的地址。
- `free(p)`：读 p 前面的头得知大小，放回空闲链表，并与相邻空闲块合并（coalesce）。
- 大块直接 `mmap` 向操作系统要整页。
- 所以 `free(p)` 不用告诉大小——大小就记在块前面的头里。
- 代价：慢（查链表、加锁）、碎片、手动管理（忘 delete 泄漏）；好处：想多大多大、生命周期任意、任意顺序释放。

## 对比

| 维度 | 栈 | 堆 |
|---|---|---|
| 大小 | 编译期确定，小（约 8MB/线程） | 运行期确定，大 |
| 分配/释放 | 极快（移动指针） | 慢（查链表/加锁/记账） |
| 生命周期 | 绑死作用域 | 手动控制，可跨函数 |
| 释放顺序 | 严格 LIFO | 任意 |
| 碎片 | 无 | 有 |
| 管理者 | 硬件/编译器 | 运行时 allocator |
| 线程 | 每线程独享 | 全进程共享 |

栈用「限制你」换「极快」，堆用「慢一点」换「随便用」。

## 对应到 ROS 代码

```cpp
void on_message(const std_msgs::msg::String & msg) {
  int counter = 0;             // 栈：回调结束自动销毁
  double pose[3] = {0,0,0};    // 栈：固定大小

  auto node = std::make_shared<rclcpp::Node>("n");   // Node 实例在堆上
  std::vector<int> v;          // v 对象在栈上，内部数组在堆上
  v.push_back(42);
}
```

- `vector` / `map` 的对象本身在栈上（几个指针 + size），内部数据在堆上，所以能动态增长。
- 每个 `std::thread` 有自己的栈：多线程 = 多个独立栈 + 一个共享堆。
- `make_shared` 造的对象都在堆上，靠引用计数自动 delete。

## 坑

- 返回局部变量的地址/引用 → 悬空。
- 栈上开巨大数组 → 栈溢出，应改用堆容器。
- `new` 后忘记 `delete` → 泄漏；优先智能指针。
- 堆上对象被多个线程释放 → 重复释放，需明确所有权。

> PS：能用栈就用栈（快、自动）；需要动态大小、跨作用域或共享所有权时才上堆。

栈是编译期定大小 + LIFO，一个指针完成分配释放；堆是运行期任意大小/生命周期，靠 allocator 记账；容器对象在栈、数据在堆。
