`std::map` 是有序关联容器，底层是红黑树（自平衡二叉搜索树）。它靠颜色约束 + 旋转把树高压在 `O(log n)`，因此查找/插入/删除都稳定对数时间，且能按 key 有序遍历。

## 节点结构

每个节点存键值对，分散在堆上、指针相连：

```cpp
struct Node {
  Key key;          // 排序依据
  T value;
  Node *left, *right, *parent;
  bool is_red;
};
```

普通 BST 在顺序插入时会退化成链表（O(n)），红黑树用颜色和旋转保持近似平衡。

## 五条性质

1. 每个节点非红即黑。
2. 根是黑。
3. 叶子（NIL）是黑。
4. 红节点的两个子节点都是黑（不允许红相邻）。
5. 从任意节点到其所有后代叶子的路径上，黑节点个数相同。

由 4、5 推出最长路径 ≤ 2 × 最短路径，树高约 `2·log₂(n)`，三种操作都 `O(log n)`。

## 三大操作

- **查找**：从根往下，比 key 小走左、大走右、相等命中。
- **插入**：按 BST 落到叶子位置，新节点默认红色；父节点是黑就结束，父是红则按叔叔节点颜色旋转 + 重着色，可能一路修到根。
- **删除**：无子直接删；一个子用子顶替；两个子找后继替换再删；之后同样修复红黑性质。

旋转是修复的核心：左旋把右子提上来、自己变它的左子，右旋对称；旋转不破坏 BST 的中序有序性。

## 与 unordered_map 对比

| 操作 | `std::map`（红黑树） | `std::unordered_map`（哈希表） |
|---|---|---|
| 查找 | O(log n) | 平均 O(1)，最坏 O(n) |
| 插入 / 删除 | O(log n) | 平均 O(1)，最坏 O(n) |
| 有序 | 是（按 key 遍历） | 否 |
| 内存 | 每节点 3 指针 + 颜色位 | 桶数组 + 链表 + 负载因子 |

要「有序遍历 / 区间查询」用 map；要「更快、不在乎顺序」用 unordered_map。

## 与 ROS 参数的关系

参数容器是有序 map，所以 `ros2 param list` 的输出按参数名字母序排列。map 节点分散在堆上，插入/删除后迭代器大多仍有效（不像 vector 会整体搬移）。

## 坑

- `operator[]` 访问不存在的 key 会插入默认值；只查询用 `find` / `at`。
- 自定义 key 需要提供比较函数（默认 `std::less`）。
- 频繁按 key 随机访问且无需顺序时，红黑树的常数开销不划算。

> PS：需要按插入顺序遍历用 `std::vector` + 索引；需要同时有序和快速查找可考虑 `flat_map`（有序数组）。

map = 红黑树，颜色约束 + 旋转保证 `O(log n)` 与有序；有序选 map，纯查找选 unordered_map。
