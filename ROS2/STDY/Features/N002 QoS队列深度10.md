`create_publisher<...>("topic", 10)` 里的 `10` 只是 QoS 的一个维度（队列深度）。本篇把它放回完整的 QoS、端到端延迟与 DDS/RTPS 传输链里看：ROS 2 的通信 = DDS 在 UDP/IP 之上实现的去中心化发布/订阅。

## QoS：四个独立维度

`10` 的完整含义是 **Keep Last 10**：队列最多保留最近 10 条。其余维度取默认：

| 维度 | 作用 | 默认 | 其他 |
|---|---|---|---|
| Reliability | 消息能不能丢 | Reliable | Best Effort |
| Durability | 晚到的订阅者能否拿历史 | Volatile | Transient Local |
| History | 队列怎么存 | Keep Last | Keep All |
| Depth | 队列深度 | 10 | 任意 |

`10`（Depth）和 Transient Local（Durability）是**两个独立维度，互不占用**。默认 Volatile 意味着订阅者只收到订阅之后的消息。

- 不能丢的关键数据：Reliable + Transient Local + 较大 Depth。
- 高频传感器数据（点云等）：Best Effort 降低延迟与开销。

## 端到端延迟

从 `publish()` 到订阅回调执行是一条异步链路，六步：

```
序列化 → DDS 写入 → 传输(共享内存 / UDP / 网络) → DDS 接收 → 反序列化 → executor 调度回调
```

每步 µs 级，累加即总延迟。量级：

| 场景 | 延迟 |
|---|---|
| 本机共享内存（CycloneDDS 默认） | 几十 ~ 几百 µs |
| 本机 UDP loopback | ~100 µs ~ 1 ms |
| 跨机 1G 以太网 | 几百 µs ~ 几 ms |
| 尾延迟（99.9%） | 调度抖动可到 ms 级 |

直觉：**本机亚毫秒，跨机毫秒级**。人眼分辨率约 10ms，所以「看起来同步」；纳秒时间戳实测到过一次 340µs。

影响因素：消息大小、传输方式（共享内存 < UDP < 跨机）、QoS（Reliable 有 ACK 握手，比 Best Effort 慢）、**executor 单线程回调串行（最大变量）**、系统负载、网络抖动。

工程后果：

- **控制闭环**：延迟是相位滞后，过大或过抖会超调、震荡、失稳。
- **抖动比固定延迟致命**：固定延迟可预测可补偿，随机抖动不可补偿。
- **数据新鲜度**：延迟 × 速度 = 位置偏差（100ms × 1m/s = 10cm）。
- **队列积压**：生产快于消费时，延迟越涨越大。
- **多机融合**：要求时间戳对齐。

缓解：回调快进快出；能丢的数据用 Best Effort + 小消息；本机共享内存；慢回调隔离（callback group / 多线程 executor）；关键控制用 QoS `Deadline` 监控。

## 底层：DDS / RTPS / UDP

先分清两套「分层」：rclcpp/rcl/rmw/DDS 是 ROS 2 自己的四层，**全在 TCP/IP 应用层**；真正上网时 DDS 直接坐在传输层 UDP 之上（也可配 TCP）。

```
应用层   节点代码 + rclcpp + rcl + rmw + DDS/RTPS
传输层   UDP（默认） / TCP（可选）
网络层   IP（单播 / 组播）
链路层   以太网 / WiFi / 环回
```

**ROS 2 底层跑的是 UDP 数据报，不是 TCP 连接。**

选 UDP 的理由：TCP 面向连接、有握手和队头阻塞、只能单播；机器人要低延迟、能组播、按需可靠。DDS 把「可靠」留给自己加——**RTPS 在 UDP 之上模拟 ACK + 重传**，而不是靠 TCP。

### 没有 master：组播自动发现

ROS 1 靠 `roscore` 集中注册；ROS 2 去中心化，分两步：

1. **SPDP（参与者发现）**：每个参与者周期往组播地址发「我在这，这是我的 GUID」。类比 ARP 广播。
2. **SEDP（端点发现）**：交换话题名、类型、QoS、IP:端口。类比 DNS 解析。

话题名 + 类型 + QoS 兼容，就建立 writer↔reader 关联。**组播只用于发现，数据走点对点单播。**

### publish → 回调

1. `publish(msg)` 序列化成字节流（CDR 格式，跨语言统一表示）。
2. 加 RTPS 头（序号、时间戳、GUID）组成报文。
3. UDP 单播发出；本机两节点时 CycloneDDS 可能直接走共享内存。
4. 对端反序列化 → 进订阅队列 → executor 触发回调。

### QoS 就是把网络行为变成可选项

| 网络概念 | ROS 2 QoS |
|---|---|
| TCP 的 ACK + 重传 | Reliability = RELIABLE |
| UDP 尽力而为 | Reliability = BEST_EFFORT |
| 接收缓冲区大小 | Depth |
| 缓存历史 | Durability = Transient Local |

所以 `10` 与「Reliable 比 Best Effort 慢」本质都是 RTPS 在 UDP 上对 TCP 特性的选择性模拟。

### 网络概念 ↔ ROS 2 对照

| 计算机网络 | ROS 2 / DDS |
|---|---|
| IP 地址 | GUID |
| 端口 | endpoint（writer / reader） |
| DNS / ARP | SPDP + SEDP 组播发现 |
| TCP 三次握手 | RTPS 建立 writer↔reader 关联 |
| TCP ACK + 重传 | Reliable QoS |
| UDP 尽力而为 | Best Effort QoS |
| 网段 / VLAN | DDS domain |

## 坑

- **Reliable 一定比 Best Effort 慢**：多了 ACK 与重传，丢包时更明显。
- **组播被禁**（Docker / 跨网段）：发现失败，需配 peer 列表走单播发现。
- **不同 DDS domain 互相看不见**，像 VLAN 隔离。
- **单线程 executor 卡住**会让延迟持续上涨，见 [[N009 Executor事件循环]]。
- 本机通信可能根本不过网卡，抓包看不到 UDP。

> PS：跨机部署先确认 domain、组播、防火墙；对延迟敏感的控制话题用 Best Effort + 小消息，状态估计用 Reliable。

`10` 是 QoS 的 Depth；端到端延迟由序列化、DDS 传输、反序列化、executor 调度叠加而成；DDS 用 UDP 单播传数据、组播做发现，并用 QoS 按需模拟 TCP 的可靠性。
