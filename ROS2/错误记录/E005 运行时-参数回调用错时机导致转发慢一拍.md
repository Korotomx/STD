# E005 · 运行时/API — 参数回调用错时机导致转发慢一拍

**日期:** 2026-10-07
**标签:** #运行时 #API #Parameter参数 #Callback回调

## 问题

`turtle_painter` 里 `ros2 param set` 改了自己的参数后，转发给 turtlesim 的颜色总是「上一次」的值——改一次没反应，再改一次才变成上上次想要的颜色（慢一拍）。

## 原因

节点用的是 `add_on_set_parameters_callback`，它在**参数写入容器之前**触发。回调里 `get_parameter` 读到的还是**旧值**，所以转发出去的是旧值。新值其实在回调参数 `params` 里，但还没进容器。

## 解决方案

改用 `add_post_set_parameters_callback`（**写入之后**触发），并把回调签名从 `SetParametersResult` 改成 `void`：

```cpp
// 改前（慢一拍）
param_cb_handle_ = this->add_on_set_parameters_callback(
  std::bind(&TurtlePainter::on_param_change, this, std::placeholders::_1));

rcl_interfaces::msg::SetParametersResult on_param_change(
  const std::vector<rclcpp::Parameter> & params) { ... }

// 改后
param_cb_handle_ = this->add_post_set_parameters_callback(
  std::bind(&TurtlePainter::on_param_change, this, std::placeholders::_1));

void on_param_change(const std::vector<rclcpp::Parameter> & params) { ... }
```

> **Note（关联）：** Lyrical 把参数回调拆成 pre / on / post 三种（时机不同），详见 [[N028 参数服务与参数回调]]；三种回调时机速查见 [[四大通信机制语法速查表]]。
