# E002 · 运行时 — 残留节点导致话题多发布者，listener 收到交叉消息

**日期:** 2026-10-05
**标签:** #运行时 #话题 #节点 #进程 #DDS

## 问题

实战运行 talker / listener 时，发现 listener 收到的计数远超 talker 端：自己的 talker 才发到 130，listener 端已经显示 500+。

## 原因

1. 图上有 **2 个 talker** 同时往话题 `topic` 发布（一个残留 + 一个新开），listener 两个都收。
2. `count_` 是**每个 talker 进程各自独立**的计数器，两个 talker 的计数交错，所以 listener 看到的数字乱跳、且涨得飞快。
3. 残留来源：后台 `ros2 run ... &` 起节点后，`kill $PID` 杀的是 `ros2 run` 的 **Python 壳**，真正的节点是它的子进程——壳死了，节点变孤儿继续跑。

诊断证据：

```bash
ros2 node list
# /listener  /listener  /talker  /talker   ← 各 2 个，且完全同名

ros2 topic info /topic
# Publisher count: 2, Subscription count: 2
```

## 解决方案

1. **诊断**：`ros2 node list` / `ros2 topic info /topic` 看节点数和发布者数。
2. **清理**：杀**真正的节点进程**（可执行文件路径），不是 `ros2 run` 壳：

   ```bash
   pkill -f "install/project1/lib/project1/my_node"
   pkill -f "install/project1/lib/project1/listener"
   ```

3. **预防**：
   - 前台运行：直接 `Ctrl+C`（rclcpp 收到 SIGINT 优雅退出，最干净）。
   - 后台运行：杀可执行文件路径，或记录真正的节点 PID。

> **Note（关联）：**
> - 进程分层：`ros2 run`（Python 壳）→ 真正节点可执行文件（子进程），见 [[N014 从cpp到可执行文件]]。
> - 优雅终止：Ctrl+C = SIGINT，见 [[N008 spin的终止方式]]。
> - 本质是「同一 topic 可被多个 publisher 同时写」，订阅端不区分来源，见 [[N010 订阅者与回调参数]]。
