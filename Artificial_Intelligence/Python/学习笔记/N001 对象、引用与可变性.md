# 对象、引用与可变性(Python 对象模型)· 语法知识 · N001

**时间:** 2026-10-11
**标签:** #Python #对象模型ObjectModel #引用Reference #可变性Mutability #别名Aliasing #浅拷贝ShallowCopy #深拷贝DeepCopy
**关联:** [[C 指针与值]] [[数据容器 list·tuple·dict·set]]

## 疑惑点

之前写「变量 为容器」——那是 C 的心智(`int x` 在栈上划格子)。Python 里没有「装值的盒子」,那 `x = [1,2,3]` 到底发生了什么?为什么 `y = x` 之后改 `y` 会连带改 `x`?

## 实际情况

1. **名字是「标签」不是「盒子」**:`x = [1,2,3]` = 先创建一个列表对象,再把名字 `x` 贴上去;`y = x` = 给同一个对象再贴一个标签 `y`,**没有复制**。
2. **`is` 比身份、`==` 比内容**:`x is y` 问「是不是同一个对象」,`x == y` 问「内容相不相等」;`id()` 返回每个对象的「身份证号」。
3. **可变 vs 不可变**:`list/dict/set` 可变(原地改,`id` 不变);`int/str/tuple` 不可变(「改」= 新建对象重新贴标签,`id` 变)。所以 `s = s + " world"` 不是原地改,是造新串。
4. **别名(aliasing)**:多个名字指向同一可变对象 → 改一个,另一个「也变」(其实是同一个)。
5. **浅拷贝 vs 深拷贝**:`a[:]` / `a.copy()` / `list(a)` 只复制外层(内层对象仍共享);`copy.deepcopy(a)` 连内层一起复制,完全独立。
6. **可变默认参数的坑**:`def f(item, target=[])` 的 `[]` 在**函数定义时**只创建一次、被所有调用共享 → 正确写法 `target=None` + 内部判空再建。

## 思考

(留白 —— Python 为什么要设计成「一切皆对象 + 名字是标签」,而不是像 C 那样「变量直接装值」?这个设计对「函数传参」「内存管理」各带来什么影响?)

## 总结

**本质**:赋值 = 贴标签,不是复制;对象分可变/不可变;别名、浅拷贝、默认参数坑,全是这套「引用模型」的直接推论。吃透它,list 原地修改、dict 传参、`is` vs `==` 的坑就一次全通了。
