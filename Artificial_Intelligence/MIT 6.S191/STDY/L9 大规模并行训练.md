## 为什么用 GPU、为什么要 scale

训练一个神经网络的主体是大量矩阵乘法。一个 $256\times4096$ 的输入乘 $4096\times4096$ 的权重，大约需要 $8\times10^9$ 次浮点运算；2011 年的 CPU 约 $0.1$ TFLOP/s，而当时的 GTX 580 快约 $16$ 倍。AlexNet 用两张 GTX 580 训练了两周，点燃了深度学习革命；今天的 H100 又比游戏 GPU 快约 $1000$ 倍。

**scaling law** 给出两条经验规律：

- **数据更多 → loss 更低**：Llama 2 7B 的训练曲线随 token 数单调下降，呈幂律。
- **同样数据下模型更大 → loss 更低**：Llama 2 的 7B/13B/34B/70B 四个版本，在同一 token 数下参数量越大损失越低。

工业界的例子：

| 模型 | 参数量 | 训练 token |
| --- | --- | --- |
| GPT-3 | 175B | 300B |
| Llama 2 | 70B | 2T |
| LFM2.5 | 1.2B | 28T |

有趣的是模型反而在变小：**训练只是一次性成本，推理才是长期成本**。GPT-3 的权重一台笔记本都放不下，而 LFM2.5 1.2B 能跑在手机甚至树莓派上。所以「scale」不等于盲目变大，而是在质量、训练成本、推理成本之间找平衡。

## 训练的内存账本

先算一笔账。一个 1B 参数模型，batch size 16、256 层、hidden size 1024，训练时需要：

| 项目 | 说明 | 显存 |
| --- | --- | --- |
| 参数 | fp16，每参数 2 字节 | 2 GB |
| 梯度 | 每个参数一份 | 2 GB |
| Adam 状态 | 每参数两个 fp32 变量（一阶、二阶矩） | 8 GB |
| 激活值 | 反向传播要用，与层数、batch、hidden 成正比 | 约 16 GB |
| **合计** | | **约 28 GB** |

模型权重只占 2 GB，但训练要 28 GB——**训练内存远大于模型本身**。外推到 70B，约需 2 TB，单卡显存放不下。

两个省内存的手段：

- **激活检查点（activation checkpointing）**：前向时只保存每隔几层的激活，反向时重新计算中间层。用额外一次前向换内存，通常能省数倍；因为前向只占整体计算的一小部分，代价可以接受。
- **offloading**：把优化器状态、暂时不用的层或激活搬到 CPU 内存。问题是 PCIe 带宽远低于 HBM，GPU 会等数据；适合单卡微调 70B、超长上下文等「训练量不大但模型很大」的场景。

## 集群长什么样

一个典型节点有 8 张 GPU，通过 **NVLink** 互连（scale-up），CPU 通过较慢的 PCIe 连接这些 GPU；节点之间用 **InfiniBand** 组网（scale-out），并支持 **RDMA**，让 GPU 直接把数据从 HBM 送到网卡，绕过主机 CPU。

这形成了一条通信层级：

$$
\text{寄存器/cache} \;\ll\; \text{HBM} \;\ll\; \text{NVLink} \;\ll\; \text{InfiniBand}.
$$

并行策略的选择，本质上就是**让通信密集的部分留在快链路上，让通信少的部分跨节点**。

## 数据并行：最直接的切法

随机梯度下降的每个样本梯度是独立的，最后只需求平均。于是：

1. 每张 GPU 复制一份完整模型（含优化器状态）；
2. 把一个大 batch 平均分给各 GPU；
3. 各自前向、反向算局部梯度；
4. 最后做一次 **all-reduce mean**，把梯度求平均并同步。

前向和反向完全并行，只有最后一步通信，所以**近似线性扩展**：加 GPU 就能加吞吐。例如 batch 256 分到 4 张卡，每张 64 个样本。

瓶颈在**有效 batch size**：batch 太大时泛化会变差，训练曲线和测试集表现都会下降。所以数据并行不能无限堆，想继续提速就得换别的维度切。

## 优化器分片：ZeRO 的第一层

既然每张卡都存一份优化器状态太浪费，就把优化器状态按参数切开，每张卡只保存自己那一段。更新时：

1. 前向、反向仍然各自独立；
2. **reduce-scatter**：把各卡梯度按分片发送到对应卡；
3. 每张卡只更新自己负责的那段参数；
4. **all-gather**：把更新后的参数同步回所有卡。

示例中每卡显存从 12 GB 降到 8 GB。省的是优化器状态（Adam 每参数两个变量），代价是额外的通信。

## 流水线并行：按深度切

把网络的层按深度分给不同 GPU：GPU 0 放前几层，GPU 1 放中间层，依此类推。问题是**流水线气泡（pipeline bubble）**：GPU 0 做前向时，后面的 GPU 都在等；反向时反过来，整体利用率很低。

解决办法是**微批（micro-batching）**：把一个大 batch 切成若干小块，GPU 0 算完第一个微批就把它传给 GPU 1，同时开始算第二个微批。这样各卡可以重叠工作。

工业界的进一步优化：

- Llama 3 让前向和反向更早重叠；
- DeepSeek 的 **DualPipe** 把「反向到输入」和「反向到权重」拆成更细的单元，分别调度。

## 张量并行：按层内切

矩阵乘法 $XW=Y$ 可以把 $W$ 切开：

- **列并行**：$W$ 按列切，输入 $X$ 在每张卡上复制，输出 $Y$ 按列分片；
- **行并行**：$W$ 按行切，输入 $X$ 按列分片，输出是各卡的部分和，需要 all-reduce 相加。

Transformer 的 MLP 通常把「列并行 → 非线性 → 行并行」叠起来：输入复制，中间状态分片，最后只做**一次 all-reduce** 就恢复完整输出。这样两层只付一次通信。

张量并行通信非常密集，通常限制在**同一个节点内**（NVLink），不跨节点。

## 序列/上下文并行

按 token 维度切：把 8K 上下文的前 2K 放 GPU 0、后 2K 放 GPU 1，依此类推。

- MLP 等逐 token 运算不混时间，**不需要通信**；
- 注意力层会混合所有位置，需要切分 KV cache，并用 ring attention 等算法处理跨卡注意力。

实践上通常先训练短上下文（如 8K），最后再用少量 token 扩展到长上下文，而不是从头用 1M 上下文训练。

## 专家并行与 MoE

**Mixture of Experts（MoE）** 把权重矩阵按行切成若干「专家」，再用一个 **router** 为每个 token 选择少数几个专家激活。这样可以在不按比例增加计算量的情况下扩大模型容量。

把不同专家放到不同 GPU 上，就是**专家并行**。它和稀疏矩阵类似：每次只激活一部分权重。

MoE 的关键问题是**负载均衡**：

- 训练稳定性：router 可能把几乎所有 token 都送给同一个专家，导致其他专家永远得不到训练；
- 设备利用率：如果 token 都涌向少数专家，对应的 GPU 过载，其余 GPU 空闲，训练速度大幅下降。

Liquid AI 的 LFM2 8B A1B 是 8.3B 总参数、1.5B 激活参数：推理速度接近 1.5B 模型，容量接近 8B 模型。

## 框架：DeepSpeed、FSDP、Megatron

| 框架 | 来源 | 主要能力 | 使用风格 |
| --- | --- | --- | --- |
| DeepSpeed ZeRO | Microsoft | 优化器/梯度/参数分片（stage 1/2/3）、offload | 一行包装 + YAML 配置 |
| FSDP | Meta / PyTorch 原生 | ZeRO-3 风格的全分片数据并行 | 包一层 `FSDP` module |
| Megatron-LM | NVIDIA | 张量并行、流水线并行、大规模 Transformer 预训练 | 自定义 model-parallel 单元，代码改动多 |

- **ZeRO stage 1**：只分片优化器状态；
- **stage 2**：再分片梯度；
- **stage 3**：连参数也分片，前向/反向时按需 all-gather，用完丢弃。适合单卡放不下的大模型。
- **FSDP**：PyTorch 原生实现，思路类似 stage 3；进入某层时 all-gather 参数，离开时丢弃，反向时再取回。
- **Megatron-LM**：把张量并行、流水线并行做进模型定义，功能更全但侵入性更强。

Google 不用 PyTorch，走的是 JAX 路线。选框架时，DeepSpeed 最容易上手，FSDP 最「PyTorch 原生」，Megatron 则适合需要精细控制大规模并行的预训练。

## 组合成 5D 并行

实际训练不是只选一种策略，而是把多个维度叠起来：

| 维度 | 切什么 | 通信特点 | 典型放置 |
| --- | --- | --- | --- |
| 数据并行 DP | batch | 每步一次 all-reduce | 可跨节点 |
| 张量并行 TP | 层内权重矩阵 | 每层多次 all-reduce，通信密集 | 节点内 NVLink |
| 流水线并行 PP | 网络深度（层） | 点对点传激活，气泡需微批掩盖 | 跨节点 |
| 专家并行 EP | MoE 专家 | 按 router 分发 token | 视规模 |
| 序列/上下文并行 CP/SP | token 序列 | MLP 无通信，注意力需特殊处理 | 长上下文阶段 |

一个示意配置是 2048 张 GPU：DP=8、TP=8、PP=4，再叠加 EP/CP。核心原则是**让通信模式匹配集群拓扑**——NVLink 内做通信密集的张量并行，InfiniBand 上做通信较少的数据并行和流水线并行。

此外还有混合精度（权重/激活用低精度，敏感部分保留高精度）、融合 kernel、FlashAttention 等缓存友好算法，进一步压内存、提吞吐。

## 问答里的几个补充

- **去中心化训练**：数据并行通信最少，最适合跨数据中心；异步训练是活跃研究方向，但大规模成功案例还不多。
- **小模型怎么加速**：层数少、矩阵小，切成张量并行很困难；主要靠蒸馏（让 student 拟合 teacher 的完整分布）和更丰富的训练信号，而不是单纯堆 GPU。
- **数据质量**：前几万亿 token 可以从 Wikipedia、arXiv 等高质量来源获得，越往后越难；需要过滤模型、消融实验；全合成数据可能导致训练崩塌（「模型没有灵魂」）。
- **端侧模型**：模型变大与手机内存的矛盾，一部分靠算法与架构创新，一部分靠与 AMD、Qualcomm 等硬件厂商协同演进。

## 小结

- 训练是矩阵乘法密集型任务，GPU 的并行算力远高于 CPU；scaling law 说「更多数据 + 更大模型 → 更低 loss」。
- 训练显存 ≈ 参数 + 梯度 + 优化器状态 + 激活；1B 参数约 28 GB，70B 约 2 TB。
- 省内存：激活检查点、offloading、分片。
- 并行维度：数据并行（切 batch）、优化器/参数分片（ZeRO/FSDP）、流水线并行（切层）、张量并行（切矩阵）、序列并行（切 token）、专家并行（切 MoE 专家）。
- 通信层级决定放置：NVLink 内做 TP，跨节点做 DP/PP；实际系统是 5D 并行的组合。
- 没有一种策略通吃；模型大小、集群拓扑、通信带宽共同决定配置。
