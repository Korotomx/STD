## 一句话

**图像坐标以左上角为原点、y 向下，单位是「连续像素」；letterbox 本质是一次「等比缩放 + 居中平移」的仿射变换，正变换用 `min` 算缩放、加 `pad`，逆变换用 `(dst - pad) / scale`；坐标必须用 float，才能保留缩放和插值产生的亚像素信息。**

## 1. 图像坐标系

### 1.1 左上原点、y 向下

OpenCV、PIL、YOLO、多数深度学习框架统一使用：

```text
(0,0) ──────────→ x
  │
  │
  ↓
  y
```

- 原点在图像左上角
- `x` 向右增大
- `y` 向下增大
- OpenCV 访问方式是 `img[y, x]`，先行后列
- 图像宽 `W` 对应 x 方向，高 `H` 对应 y 方向

YOLO 的归一化坐标也沿用这套约定：

```text
(0,0) = 左上角
(1,1) = 右下角
```

### 1.2 不同库的约定可能不同

| 场景 | 原点 | y 方向 |
| ---- | ---- | ---- |
| OpenCV | 左上 | 向下 |
| PIL / Pillow | 左上 | 向下 |
| YOLO / 多数深度学习 | 左上 | 向下 |
| matplotlib `imshow` | 左上（默认 `origin='upper'`） | 向下 |
| matplotlib `plot`（数学坐标） | 左下 | 向上 |
| OpenGL 纹理坐标 | 左下 | 向上 |
| 机器人相机光学坐标系 | 光心 | x 右、y 下、z 前 |

仿射矩阵本身不关心原点在哪，**只要源图和目标图用同一套约定**，公式就成立。真正会变的是平移项的符号。

本篇全部按 **左上原点、y 向下** 讲，和 OpenCV / YOLO 一致。

## 2. 单位：像素，但是连续坐标

### 2.1 像素不是点，是小方块

图像数组是离散的：

```text
img[y][x]    x, y 是整数索引
```

但几何变换里的坐标是**连续坐标**，单位仍是像素（px）。

可以这样理解：

```text
像素 (10, 5) 是一个 1×1 的小方块
它的中心在坐标 (10, 5)
它的范围约为 x ∈ [9.5, 10.5], y ∈ [4.5, 5.5]
```

所以 `10.3` 是合法坐标，表示「第 10 个像素中心往右 0.3 个像素」，落在第 10 和第 11 个像素之间。

### 2.2 存储是整数，坐标是浮点

| 东西 | 类型 | 单位 / 范围 |
| ---- | ---- | ---- |
| 图像像素值 | `uint8` | 0~255 |
| 像素索引 | `int` | 第几行、第几列 |
| 几何坐标 | `float32` | 连续像素坐标，如 123.45 px |
| 模型输入 | `float32` | 0.0~1.0（归一化后） |
| 模型输出框 / 关键点 | `float32` | 640 输入空间里的像素坐标 |
| 置信度 | `float32` | 0.0~1.0，无单位 |

**存储用整数，计算用浮点。** 这是两件事。

### 2.3 框和关键点的单位

```text
x1, y1, x2, y2     像素，连续值
keypoint_x/y       像素，连续值
keypoint_conf      0~1，无单位
score              0~1，无单位
class_id           整数索引，无单位
```

## 3. 为什么坐标必须用 float

### 3.1 缩放比例本身不是整数

groundzero 的图：

```text
s = 0.15625
```

源图坐标 `x = 100` 变换后：

```text
x' = 100 * 0.15625 + 80 = 95.625
```

`95.625` 不是整数。强行取整成 `96`，立刻丢了 `0.375 px`。

### 3.2 插值需要小数权重

双线性插值要问「这个小数坐标落在哪两个像素之间，各占多少权重」。

例如反算回源图得到：

```text
src_x = 10.3
```

它落在像素 10 和 11 之间：

```text
像素 10 权重 = 1 - 0.3 = 0.7
像素 11 权重 = 0.3
结果 = 0.7 * img[10] + 0.3 * img[11]
```

没有小数，就没有插值，图像会锯齿、关键点会抖动。

### 3.3 模型输出本来就是连续回归值

YOLO 的框和关键点是**回归**出来的，不是分类出来的：

```text
keypoint_x = 312.47
keypoint_y = 198.83
```

模型输出的就是浮点数。转成整数等于人为把精度限制在 1 px。

### 3.4 逆映射会放大误差

groundzero 从 640 映射回 3072：

```text
src_x = 6.4 * dst_x - 512
```

在 640 空间里差 1 px：

```text
6.4 * 1 = 6.4 px
```

原图上就差 6.4 px。所以 640 空间里的**亚像素**信息很重要，不能提前取整。

### 3.5 留白本身可能是小数

如果缩放后宽度是奇数，例如 481：

```text
pad_x = (640 - 481) / 2 = 79.5
```

留白就是 79.5 px，不是整数。用 int 会左右不对称。

### 3.6 用 int 的后果

| 用 int 的问题 | 后果 |
| ---- | ---- |
| 缩放产生小数被截断 | 坐标系统性偏移 |
| 多次变换累积舍入 | 误差越滚越大 |
| 无法做双线性插值 | 图像锯齿、关键点抖动 |
| 640 空间 1 px 误差 | 原图放大 6.4 倍 |
| 关键点回归需要亚像素 | 精度直接掉一个档次 |

### 3.7 和 FP16 / INT8 的关系

- **FP32**：坐标精度足够，是默认。
- **FP16**：尾数 10 位，在 `[512, 1024)` 区间相邻可表示值间隔约 0.5，坐标误差最多约 0.25 px；逆映射回原图约 1.6 px。groundzero 实测关键点最大差 1.39 px，就是这个量级。
- **INT8**：640 空间只有 256 档，平均一格约 2.5 px，关键点回归基本不能用。

所以 groundzero 的 FP16 engine 里，检测头中坐标范围超过 `[-512, 512]` 的 Concat 节点被自动保留为 FP32，避免坐标精度掉太多。

## 4. Letterbox 正变换：源图 → 目标图

### 4.1 为什么需要 letterbox

模型输入固定 640×640。直接 `cv2.resize(img, (640,640))` 会把长宽比压扁，框和关键点全都偏，所以必须**等比缩放 + 补灰边**。

### 4.2 缩放比例

设源图宽高 `W_s, H_s`，目标宽高 `W_d, H_d`：

```text
s = min(W_d / W_s, H_d / H_s)
```

为什么取 `min`：

- 要保证整张源图都能塞进目标框
- 两个方向的比例取小的那个，长边刚好贴边，短边留白
- 如果取 `max`，短边会溢出，图就被裁掉

### 4.3 居中留白

缩放后的图默认贴在左上角，要居中：

```text
pad_x = (W_d - s * W_s) / 2
pad_y = (H_d - s * H_s) / 2
```

也就是两边各留一半空白。

### 4.4 正变换公式

```text
dst_x = src_x * s + pad_x
dst_y = src_y * s + pad_y
```

### 4.5 齐次坐标矩阵

平移不能写成 2×2 矩阵，所以升到 3×3 齐次坐标：

```text
[ dst_x ]   [ s  0  pad_x ]   [ src_x ]
[ dst_y ] = [ 0  s  pad_y ] * [ src_y ]
[   1   ]   [ 0  0    1    ]   [   1   ]
```

日常写的 2×3 仿射矩阵是它的简写：

```text
[ s  0  pad_x ]
[ 0  s  pad_y ]
```

### 4.6 groundzero 实例

源图是 `3072 × 4096`（宽 × 高），注意 OpenCV 的 shape 是 `(H, W, C) = (4096, 3072, 3)`，不要弄反。

```text
s = min(640/3072, 640/4096)
  = min(0.2083, 0.15625)
  = 0.15625

缩放后宽 = 3072 * 0.15625 = 480
缩放后高 = 4096 * 0.15625 = 640

pad_x = (640 - 480) / 2 = 80
pad_y = (640 - 640) / 2 = 0
```

所以：

```text
dst_x = 0.15625 * src_x + 80
dst_y = 0.15625 * src_y
```

## 5. 逆变换：目标图 → 源图

### 5.1 为什么要逆变换

做图像重采样时，标准做法是 **inverse warping（逆向映射）**：

```text
遍历目标图每个像素 (dst_x, dst_y)
  → 用逆变换算出它来自源图的哪个坐标 (src_x, src_y)
  → 在源图上采样
  → 如果落在源图外，填灰 114
```

| 方向 | 做法 | 问题 |
| ---- | ---- | ---- |
| 正向 | 遍历源图每个像素，算它落到目标图哪里 | 放大时目标图会出现空洞 |
| 逆向 | 遍历目标图每个像素，算它应该采样源图哪里 | 每个目标像素都有值，不会空洞 |

### 5.2 解方程得到逆变换

从正变换出发：

```text
dst_x = src_x * s + pad_x
```

解出 `src_x`：

```text
dst_x - pad_x = src_x * s

src_x = (dst_x - pad_x) / s
```

所以逆变换就两步：

```text
1. 先减掉留白：dst_x - pad_x
2. 再除以缩放：/ s
```

### 5.3 逆缩放 = 1 / min = max

```text
s_inv = 1 / s
      = 1 / min(W_d/W_s, H_d/H_s)
      = max(W_s/W_d, H_s/H_d)
```

**逆变换里的 `max` 不是新规则，就是 `1 / min`。**

### 5.4 逆偏置

展开：

```text
src_x = dst_x / s - pad_x / s
      = s_inv * dst_x - pad_x / s
```

所以逆偏置是：

```text
q_x = -pad_x / s
q_y = -pad_y / s
```

代入 `pad_x = (W_d - s*W_s)/2`：

```text
q_x = (W_s - s_inv * W_d) / 2
q_y = (H_s - s_inv * H_d) / 2
```

### 5.5 两个偏置的单位不一样

| 量 | 含义 | 所在空间 | groundzero 例子 |
| ---- | ---- | ---- | ---- |
| `s` | 正缩放 | 无量纲 | 0.15625 |
| `pad_x` | 左留白 | 目标图像素 | 80 |
| `pad_y` | 上留白 | 目标图像素 | 0 |
| `s_inv` | 逆缩放 | 无量纲 | 6.4 |
| `q_x = -pad_x/s` | 逆偏置 | **源图像素** | -512 |
| `q_y = -pad_y/s` | 逆偏置 | **源图像素** | 0 |

这是最容易晕的地方：**正偏置在目标空间，逆偏置在源空间。**

### 5.6 groundzero 实例

```text
s_inv = 1 / 0.15625 = 6.4

q_x = -80 / 0.15625 = -512
q_y = -0  / 0.15625 = 0
```

逆变换：

```text
src_x = 6.4 * dst_x - 512
src_y = 6.4 * dst_y
```

### 5.7 齐次坐标逆矩阵

正变换矩阵：

```text
M = [ s  0  pad_x ]
    [ 0  s  pad_y ]
    [ 0  0    1    ]
```

逆矩阵：

```text
M_inv = [ 1/s  0  -pad_x/s ]
        [  0  1/s  -pad_y/s ]
        [  0   0      1     ]
```

矩阵求逆自动处理了「先平移后缩放」的顺序反转。

### 5.8 不要背逆偏置

实际写代码时只记：

```text
正变换：dst = src * s + pad
逆变换：src = (dst - pad) / s
```

逆偏置 `-pad/s` 是展开后自然得到的，不需要单独记。

## 6. 用数轴看偏置

### 6.1 正变换

```text
源图 x:    0 ─────────────────── 3072
              × 0.15625
缩放后:    0 ─────── 480
              + 80
目标图 x': 0 ── 80 ─────── 560 ── 640
               ↑              ↑
            源图左边界      源图右边界
               |← 留白 80 →|
```

### 6.2 逆变换

```text
目标图 x': 0 ── 80 ─────── 560 ── 640
               ↓              ↓
源图 x:  -512 ─ 0 ───────── 3072 ─ 3584
         |←灰边→|    源图     |←灰边→|
```

验证：

```text
x' = 0    → 6.4*0    - 512 = -512   # 源图外，灰色 114
x' = 80   → 6.4*80   - 512 = 0      # 源图左边界
x' = 320  → 6.4*320  - 512 = 1536   # 源图中心
x' = 560  → 6.4*560  - 512 = 3072   # 源图右边界
x' = 640  → 6.4*640  - 512 = 3584   # 源图外，灰色 114
```

逆偏置是负的，因为目标图最左边那一截本来就是灰边，它「来自」源图边界外的负坐标。

## 7. 代码对应

### 7.1 letterbox

```python
def letterbox(img, new_size=640):
    h, w = img.shape[:2]                       # 注意是 H, W
    r = min(new_size / h, new_size / w)
    new_w, new_h = int(round(w * r)), int(round(h * r))
    resized = cv2.resize(img, (new_w, new_h), interpolation=cv2.INTER_LINEAR)

    dw, dh = (new_size - new_w) / 2, (new_size - new_h) / 2
    left, right = int(round(dw - 0.1)), int(round(dw + 0.1))
    top, bottom = int(round(dh - 0.1)), int(round(dh + 0.1))

    padded = cv2.copyMakeBorder(
        resized, top, bottom, left, right,
        cv2.BORDER_CONSTANT, value=(114, 114, 114)
    )
    return padded, r, (left, top)
```

对应关系：

```text
r       = s
left    = pad_x
top     = pad_y
114     = YOLO 默认灰边值
```

`round(dw - 0.1)` / `round(dw + 0.1)` 是为了让左右留白尽量对称，避免浮点数四舍五入导致总宽差 1 px。

### 7.2 逆映射框和关键点

```python
def inverse_letterbox(x, y, r, pad):
    left, top = pad
    return (x - left) / r, (y - top) / r
```

框的四个角、关键点的 `(x, y)` 都用这一套；关键点的 `conf` 不参与变换。

### 7.3 等价的展开写法

```python
s_inv = 1.0 / r
x_src = s_inv * x_dst - left / r
y_src = s_inv * y_dst - top / r
```

和 `(x_dst - left) / r` 完全一样。日常用前者更直观。

### 7.4 用 warpAffine 生成图

如果不用 `resize + copyMakeBorder`，也可以：

```python
M = np.array([[s, 0, pad_x],
              [0, s, pad_y]], dtype=np.float32)

dst = cv2.warpAffine(
    src, M, (640, 640),
    flags=cv2.INTER_LINEAR,
    borderValue=(114, 114, 114),
)
```

注意：

- `warpAffine` 接收的是**正变换矩阵**（源 → 目标）
- 它内部会自己求逆，再按目标像素反查源图
- `borderValue` 填的就是灰边 114
- 实践中 `resize + copyMakeBorder` 通常更快，也是 Ultralytics 的做法

## 8. 双线性插值与半像素

### 8.1 双线性插值

目标坐标反算回源图后，通常不是整数：

```text
src_x = 10.3
src_y = 5.8
```

双线性插值取周围 4 个像素：

```text
x0 = floor(src_x) = 10,  x1 = 11
y0 = floor(src_y) = 5,   y1 = 6

wx = src_x - x0 = 0.3
wy = src_y - y0 = 0.8

top    = (1-wx) * img[y0, x0] + wx * img[y0, x1]
bottom = (1-wx) * img[y1, x0] + wx * img[y1, x1]
value  = (1-wy) * top + wy * bottom
```

这就是为什么坐标要保留小数：`wx, wy` 就是插值权重。

### 8.2 半像素约定

严格的图像重采样里，OpenCV 使用像素中心约定：

```text
src = (dst + 0.5) / scale - 0.5
```

而 YOLO 的训练和推理统一使用本篇这套无半像素的仿射公式：

```text
dst = src * s + pad
src = (dst - pad) / s
```

两者在 640 空间里最多差半个目标像素，逆映射回 4096 原图约几个像素。YOLO 全链路（训练标签变换 + 推理逆映射）用的是同一套约定，所以**训练和推理是自洽的**。自己用 `warpAffine` 生成图时，OpenCV 会处理半像素，不需要手动加。

## 9. 常见坑

| 现象 | 原因 |
| ---- | ---- |
| 宽高弄反，缩放比例算错 | OpenCV `img.shape` 是 `(H, W, C)`，`W_s` 是第二个数 |
| 框整体偏移 | 忘了减 `pad`，或减了但没除以 `r` |
| 框对、关键点全错 | 只逆映射了框，没处理关键点 |
| 逆映射后坐标是负数 | 正常：该点落在灰边区域，源图里没有对应像素 |
| 缩放后图像被裁 | 用了 `max` 而不是 `min` |
| 图像被压扁 | 直接 `resize` 到 640×640，没保持长宽比 |
| 左右留白差 1 px | 总留白是奇数，`round` 方式导致；用 `round(dw-0.1)` / `round(dw+0.1)` 缓解 |
| 坐标取整后关键点抖动 | 中间过程用了 int，丢了亚像素 |
| 自己乘了逆偏置而不是减 pad | 记住 `src = (dst - pad) / s`，不要单独造公式 |
| `warpAffine` 方向搞反 | 它接收源 → 目标的正矩阵，内部自己求逆 |

## 10. groundzero 实际数字汇总

```text
源图：W_s = 3072, H_s = 4096
目标：W_d = 640,  H_d = 640

正变换：
s      = 0.15625
缩放后 = 480 × 640
pad_x  = 80
pad_y  = 0

dst_x = 0.15625 * src_x + 80
dst_y = 0.15625 * src_y

逆变换：
s_inv = 6.4
q_x   = -512
q_y   = 0

src_x = 6.4 * dst_x - 512
src_y = 6.4 * dst_y
```

边界验证：

```text
dst_x = 80   → src_x = 0
dst_x = 560  → src_x = 3072
dst_y = 0    → src_y = 0
dst_y = 640  → src_y = 4096
```

灰边区域：

```text
dst_x < 80 或 dst_x > 560  → src_x < 0 或 src_x > 3072
```

这些位置在源图里不存在，生成图像时填 `(114, 114, 114)`。

## 术语表

| 术语 | 中文 | 一句话 |
| ---- | ---- | ---- |
| image coordinate | 图像坐标 | 以左上角为原点、y 向下的连续坐标 |
| pixel | 像素 | 图像的最小采样单元，坐标单位 |
| subpixel | 亚像素 | 两个像素中心之间的小数位置 |
| letterbox | 等比缩放补边 | 保持长宽比缩放到目标尺寸，剩余区域补灰 |
| affine transform | 仿射变换 | 线性缩放 + 平移，保持直线和平行关系 |
| homogeneous coordinate | 齐次坐标 | 用多一维表示平移，使仿射变换可写成矩阵乘法 |
| forward mapping | 正向映射 | 源图坐标 → 目标图坐标 |
| inverse mapping | 逆向映射 | 目标图坐标 → 源图坐标，重采样时使用 |
| bilinear interpolation | 双线性插值 | 用周围 4 个像素按小数权重加权 |
| padding | 补边 / 留白 | letterbox 在缩放后填充的灰边 |
| scale | 缩放比例 | 源图到目标图的坐标倍率 |
| inverse scale | 逆缩放 | `1 / scale`，目标图回源图的倍率 |
| bias / offset | 偏置 | 仿射变换里的平移量 |
| pixel center convention | 像素中心约定 | 像素中心在整数坐标，半像素偏移的来源 |

## 总结

1. **图像坐标左上原点、y 向下**，OpenCV / PIL / YOLO 都是这套；数学绘图和 OpenGL 可能相反。
2. **单位是像素，但坐标是连续的**；存储是 `uint8` 整数，几何计算用 `float32`。
3. **必须用 float 的原因**：缩放产生小数、插值需要权重、模型输出是回归值、逆映射会把 640 空间的误差放大 6.4 倍、留白可能是 79.5 这种小数。
4. **正变换**：`s = min(...)`，`pad = 0.5 * (目标 - 缩放后源图)`，`dst = src * s + pad`。
5. **逆变换**：`src = (dst - pad) / s`；逆缩放是 `1/s = max(...)`，逆偏置是 `-pad/s`，单位从目标像素变成源像素。
6. **偏置不用背**：正偏置是加留白，逆偏置是减留白再除缩放；逆偏置为负，是因为目标图原点落在灰边里。
7. **框和关键点用同一套逆变换**，关键点置信度不参与坐标变换。
8. **groundzero**：`3072×4096 → 640×640`，`s=0.15625`，`pad=(80,0)`；逆变换 `src_x=6.4*dst_x-512`，`src_y=6.4*dst_y`。
