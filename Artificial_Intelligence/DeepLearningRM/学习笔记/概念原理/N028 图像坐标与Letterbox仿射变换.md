图像坐标以左上角为原点、y 向下，单位是「连续像素」；letterbox 本质是一次「等比缩放 + 居中平移」的仿射变换，正变换用 `min` 算缩放、加 `pad`，逆变换用 `(dst - pad) / scale`；坐标必须用 float，才能保留缩放和插值产生的亚像素信息。

## 坐标系

OpenCV、PIL、YOLO、多数深度学习框架统一使用：

```text
(0,0) ──────────→ x
  │
  ↓
  y
```

- 原点左上，x 向右，y 向下
- OpenCV 访问 `img[y, x]`，先行后列；宽 `W` 对应 x，高 `H` 对应 y
- YOLO 归一化坐标也沿用：`(0,0)` 左上、`(1,1)` 右下

| 场景 | 原点 | y 方向 |
| ---- | ---- | ---- |
| OpenCV / PIL / YOLO | 左上 | 向下 |
| matplotlib `imshow`（默认 `origin='upper'`） | 左上 | 向下 |
| matplotlib `plot`（数学坐标） | 左下 | 向上 |
| OpenGL 纹理坐标 | 左下 | 向上 |
| 机器人相机光学坐标系 | 光心 | x 右、y 下、z 前 |

仿射矩阵不关心原点在哪，**只要源图和目标图用同一套约定**公式就成立；真正会变的是平移项符号。本篇全部按左上原点、y 向下讲。

## 单位：连续像素

图像数组是离散的（`img[y][x]` 为整数索引），但几何变换里的坐标是**连续坐标**，单位仍是 px。

```
像素 (10, 5) 是 1×1 小方块，中心在 (10, 5)
范围约 x ∈ [9.5, 10.5], y ∈ [4.5, 5.5]

所以 10.3 = 第 10 个像素中心往右 0.3 像素
```

| 东西 | 类型 | 单位 / 范围 |
| ---- | ---- | ---- |
| 图像像素值 | uint8 | 0~255 |
| 像素索引 | int | 第几行、第几列 |
| 几何坐标 | float32 | 连续像素，如 123.45 px |
| 模型输入 | float32 | 0.0~1.0（归一化后） |
| 模型输出框/关键点 | float32 | 640 输入空间的像素坐标 |
| 置信度 / score | float32 | 0~1，无单位 |
| class_id | int | 整数索引 |

**存储用整数，计算用浮点。**

## 为什么坐标必须用 float

### 缩放比例不是整数

groundzero `s=0.15625`，源图 `x=100`：

```
x' = 100 * 0.15625 + 80 = 95.625
```

取整成 96 立刻丢 0.375 px。

### 插值需要小数权重

双线性插值要问「小数坐标落在哪两个像素之间、各占多少权重」：

```
src_x = 10.3
像素 10 权重 = 1 - 0.3 = 0.7
像素 11 权重 = 0.3
结果 = 0.7 * img[10] + 0.3 * img[11]
```

没有小数就没有插值，图像会锯齿、关键点会抖。

### 模型输出本来就是连续回归值

YOLO 的框和关键点是回归出来的（`keypoint_x = 312.47`），转整数等于把精度限制在 1 px。

### 逆映射会放大误差

从 640 映射回 3072：`src_x = 6.4 * dst_x - 512`。640 空间差 1 px，原图差 **6.4 px**，所以亚像素信息很重要。

### 留白可能是小数

缩放后宽 481 时 `pad_x = (640-481)/2 = 79.5`，用 int 会左右不对称。

### 用 int 的后果

| 问题 | 后果 |
| ---- | ---- |
| 缩放小数被截断 | 坐标系统性偏移 |
| 多次变换累积舍入 | 误差越滚越大 |
| 无法双线性插值 | 锯齿、关键点抖动 |
| 640 空间 1 px | 原图放大 6.4 倍 |
| 关键点需要亚像素 | 精度掉一个档次 |

### 与 FP16 / INT8 的关系

- **FP32**：坐标精度足够，默认
- **FP16**：尾数 10 位，`[512,1024)` 区间间隔约 0.5，坐标误差最多约 0.25 px；逆映射回原图约 1.6 px（groundzero 实测关键点最大差 1.39 px）
- **INT8**：640 空间只有 256 档，平均一格约 2.5 px，关键点回归基本不能用

所以 groundzero 的 FP16 engine 里，检测头中坐标范围超过 `[-512,512]` 的 Concat 节点保留 FP32。

## Letterbox 正变换

模型输入固定 640×640，直接 `cv2.resize(img, (640,640))` 会把长宽比压扁，所以必须等比缩放 + 补灰边。

设源图 `W_s, H_s`，目标 `W_d, H_d`：

```
s = min(W_d / W_s, H_d / H_s)
```

取 `min` 保证整张图塞进目标框：长边贴边，短边留白；取 `max` 短边会溢出、图被裁掉。

```
pad_x = (W_d - s * W_s) / 2
pad_y = (H_d - s * H_s) / 2

dst_x = src_x * s + pad_x
dst_y = src_y * s + pad_y
```

### 齐次坐标矩阵

平移写不进 2×2 矩阵，所以升到 3×3：

```
[ dst_x ]   [ s  0  pad_x ]   [ src_x ]
[ dst_y ] = [ 0  s  pad_y ] * [ src_y ]
[   1   ]   [ 0  0    1    ]   [   1   ]
```

日常写的 2×3 仿射矩阵是它的简写。

### groundzero 实例

源图 `3072 × 4096`（宽 × 高），OpenCV shape 是 `(H, W, C) = (4096, 3072, 3)`，不要弄反。

```
s = min(640/3072, 640/4096) = min(0.2083, 0.15625) = 0.15625
缩放后 = 3072*0.15625 × 4096*0.15625 = 480 × 640
pad_x = (640-480)/2 = 80
pad_y = (640-640)/2 = 0

dst_x = 0.15625 * src_x + 80
dst_y = 0.15625 * src_y
```

## 逆变换

做图像重采样时用 **inverse warping**：遍历目标图每个像素，用逆变换算它来自源图哪个坐标，再采样；落在源图外填灰 114。

| 方向 | 做法 | 问题 |
| ---- | ---- | ---- |
| 正向 | 遍历源图，算落到目标哪里 | 放大时目标图有空洞 |
| 逆向 | 遍历目标图，算该采样源图哪里 | 每个目标像素都有值 |

从 `dst_x = src_x * s + pad_x` 解出：

```
src_x = (dst_x - pad_x) / s
```

两步：先减留白，再除以缩放。

### 逆缩放 = 1/min = max

```
s_inv = 1/s = max(W_s/W_d, H_s/H_d)
```

逆变换里的 `max` 不是新规则，就是 `1/min`。

### 逆偏置

```
src_x = s_inv * dst_x - pad_x / s
q_x = -pad_x / s
```

代入 `pad_x = (W_d - s*W_s)/2` 得 `q_x = (W_s - s_inv*W_d)/2`。

| 量 | 含义 | 所在空间 | groundzero |
| ---- | ---- | ---- | ---- |
| `s` | 正缩放 | 无量纲 | 0.15625 |
| `pad_x/pad_y` | 左/上留白 | 目标图像素 | 80 / 0 |
| `s_inv` | 逆缩放 | 无量纲 | 6.4 |
| `q_x = -pad_x/s` | 逆偏置 | **源图像素** | −512 |
| `q_y = -pad_y/s` | 逆偏置 | **源图像素** | 0 |

最容易晕的地方：**正偏置在目标空间，逆偏置在源空间。**

groundzero：

```
s_inv = 6.4
q_x = -80/0.15625 = -512
q_y = 0

src_x = 6.4 * dst_x - 512
src_y = 6.4 * dst_y
```

### 逆矩阵

```
M     = [ s    0    pad_x ]     M_inv = [ 1/s   0   -pad_x/s ]
        [ 0    s    pad_y ]             [  0   1/s  -pad_y/s ]
        [ 0    0      1   ]             [  0    0      1     ]
```

实际写代码只记：

```
正变换：dst = src * s + pad
逆变换：src = (dst - pad) / s
```

逆偏置 `-pad/s` 是展开后自然得到的，不用背。

### 用数轴看偏置

```
正变换:
源图 x:    0 ─────────────────── 3072
              × 0.15625
缩放后:    0 ─────── 480
              + 80
目标图 x': 0 ── 80 ─────── 560 ── 640
               |← 留白 80 →|

逆变换:
目标图 x': 0 ── 80 ─────── 560 ── 640
源图 x:  -512 ─ 0 ───────── 3072 ─ 3584
         |←灰边→|    源图     |←灰边→|
```

验证：`x'=0 → -512`（源图外，灰 114）；`x'=80 → 0`（左边界）；`x'=320 → 1536`（中心）；`x'=560 → 3072`（右边界）；`x'=640 → 3584`（源图外）。

## 代码

### letterbox

```python
def letterbox(img, new_size=640):
    h, w = img.shape[:2]                       # 注意是 H, W
    r = min(new_size / h, new_size / w)
    new_w, new_h = int(round(w * r)), int(round(h * r))
    resized = cv2.resize(img, (new_w, new_h), interpolation=cv2.INTER_LINEAR)

    dw, dh = (new_size - new_w) / 2, (new_size - new_h) / 2
    left, right = int(round(dw - 0.1)), int(round(dw + 0.1))
    top, bottom = int(round(dh - 0.1)), int(round(dh + 0.1))

    padded = cv2.copyMakeBorder(
        resized, top, bottom, left, right,
        cv2.BORDER_CONSTANT, value=(114, 114, 114)
    )
    return padded, r, (left, top)
```

对应关系：`r=s`、`left=pad_x`、`top=pad_y`、114=YOLO 默认灰边。`round(dw-0.1)` / `round(dw+0.1)` 让左右留白尽量对称，避免浮点四舍五入导致总宽差 1 px。

### 逆映射

```python
def inverse_letterbox(x, y, r, pad):
    left, top = pad
    return (x - left) / r, (y - top) / r
```

框的四个角、关键点 `(x, y)` 都用这一套；关键点 `conf` 不参与变换。等价的展开写法是 `s_inv*x - left/r`。

### 用 warpAffine 生成图

```python
M = np.array([[s, 0, pad_x],
              [0, s, pad_y]], dtype=np.float32)

dst = cv2.warpAffine(src, M, (640, 640),
                     flags=cv2.INTER_LINEAR,
                     borderValue=(114, 114, 114))
```

`warpAffine` 接收**正变换矩阵**（源 → 目标），内部自己求逆再反查源图。实践中 `resize + copyMakeBorder` 通常更快，也是 Ultralytics 的做法。

## 双线性插值与半像素

目标坐标反算回源图通常不是整数：

```
src_x = 10.3, src_y = 5.8
x0 = 10, x1 = 11, wx = 0.3
y0 = 5,  y1 = 6,  wy = 0.8

top    = (1-wx)*img[y0,x0] + wx*img[y0,x1]
bottom = (1-wx)*img[y1,x0] + wx*img[y1,x1]
value  = (1-wy)*top + wy*bottom
```

`wx, wy` 就是插值权重，这也是坐标要保留小数的原因。

OpenCV 严格重采样用像素中心约定 `src = (dst+0.5)/scale - 0.5`；YOLO 训练和推理统一用本篇的无半像素公式，两者在 640 空间最多差半个像素，逆映射回 4096 约几个像素。因为 YOLO 全链路（训练标签变换 + 推理逆映射）用同一套约定，**训练和推理自洽**；自己用 `warpAffine` 时 OpenCV 会处理半像素。

## 坑与边界

| 现象 | 原因 |
| ---- | ---- |
| 宽高弄反、缩放比例算错 | OpenCV shape 是 `(H,W,C)`，`W_s` 是第二个数 |
| 框整体偏移 | 忘了减 `pad`，或减了没除 `r` |
| 框对、关键点全错 | 只逆映射了框 |
| 逆映射后坐标是负数 | 正常：该点在灰边区域 |
| 缩放后图像被裁 | 用了 `max` 而不是 `min` |
| 图像被压扁 | 直接 resize 到 640×640 |
| 左右留白差 1 px | 总留白为奇数，用 `round(dw±0.1)` 缓解 |
| 关键点抖动 | 中间过程用了 int，丢亚像素 |
| 乘了逆偏置而不是减 pad | 记 `src=(dst-pad)/s`，别单独造公式 |
| `warpAffine` 方向搞反 | 它接收源→目标的正矩阵 |

## 总结

图像坐标左上原点、y 向下；单位是像素但坐标连续，存储 uint8、计算 float32。必须用 float 的原因：缩放产生小数、插值需要权重、模型输出是回归值、逆映射把 640 空间误差放大 6.4 倍、留白可能是 79.5。正变换 `s=min(...)`、`pad=0.5*(目标-缩放后源图)`、`dst=src*s+pad`；逆变换 `src=(dst-pad)/s`，逆缩放是 `1/s=max(...)`，逆偏置 `-pad/s` 在源空间且为负。框和关键点用同一套逆映射，关键点置信度不参与变换。groundzero：`3072×4096 → 640×640`，`s=0.15625`，`pad=(80,0)`，`src_x=6.4*dst_x-512`。
