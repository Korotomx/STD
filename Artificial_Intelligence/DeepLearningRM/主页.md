2. **功能实现 · Ultralytics 训练参数全解（N021）** — 从 `default.yaml` 反查显式 / 隐式参数；`optimizer=auto` 会忽略 `lr0`、`fliplr=0.5` 对 pose 自动关闭、`nbs=64` 梯度累积；附 12 组参数耦合与 16 条踩坑。

3. **功能实现 · ONNX 与 TensorRT Engine 的区别（N022）** — ONNX 是通用计算图；Engine 是按 GPU 架构 / TensorRT 版本 / 输入 shape / 精度现场编译的执行计划，只能在目标设备 build，且只含前向。

4. **功能实现 · 模型全流程总览（N023）** — 数据 → 训练 → 评估 → 导出 → engine → 推理 → ROS2 八阶段总表；每步产物、可选方案、术语表（epoch / mAP / NMS / FP16 / letterbox 等）。

5. **概念原理 · ONNX 编译成 engine 的原理（N024）** — build 分三步：Parse（421 个 ONNX 节点 → 632 个 TRT 层，纯 CPU）→ Optimize + Tactic（算子融合、逐层在 GPU 上试跑候选 kernel、规划显存，35~40 秒）→ Serialize（打包 kernel + 权重 + 内存方案）；engine 里没有 ONNX 图，所以不可移植。

6. **功能实现 · 拿到 ONNX 转 engine 的标准操作（N025）** — 四步：查输入输出 → 判断静态/动态 shape → `trtexec --onnx --saveEngine --memPoolSize=workspace:2048M` → `--loadEngine` 验证；附动态 shape、Python 绑定、FP32/FP16 选择、8 条报错对照。实测 build 11.56 MiB engine，mean latency **1.59 ms / 629 qps**。

7. **错误记录 E003** — detect 模型训 pose 数据任务不匹配（拿数据集先看 `task` 字段再选模型）。

8. **错误记录 E004** — 训练 OOM：WSL2 内存不足、dataloader workers 开太多（默认 8 → 降 workers=2 + batch=8）；区分「显存 8G 才用 3G」与「内存 7.4G 爆了」。

9. **环境 · TensorRT tar 完整 SDK（11.4.0.106 / CUDA 12.9）** — 官方 TAR 包解压到 `~/opt/TensorRT-11.4.0.106`，补齐 C++ 头文件、`libnvonnxparser`、`trtexec`；`~/.bashrc` 已写 `TENSORRT_ROOT` / `PATH` / `LD_LIBRARY_PATH`。

10. **错误记录 E005** — `trtexec --memPoolSize=workspace:2048MiB` 里的 `MiB` 是非法后缀，被解析成 2048 **字节**，导致所有 tactic 报 `insufficient memory` / `Could not find any implementation`；合法后缀只有 `B/K/M/G`。
