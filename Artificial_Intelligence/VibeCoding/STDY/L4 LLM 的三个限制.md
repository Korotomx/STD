模型不是"24 小时在线的初级工程师"：上下文窗口的关系成本是二次方、预训练知识是一张模糊 JPEG、而且完全无状态。不理解这三条，就会把"违背模型工作原理"的失败归咎于 AI 笨。

## 限制一：上下文窗口的二次方成本

- 输入被切成 token，所有可见 token 构成上下文窗口。
- 模型不只存 token，还要记录 token 之间的关系：4 个 token → 6 组，8 个 → 28 组，100 个 → 约 5000 条连接。
- 所以是二次方增长，不像追加文档字符，更像联赛场次：队伍一多，比赛数爆炸。
- 推论：消息越堆越多，模型的计算压力越大，输出质量下降。

## 智能区与愚蠢区

- **智能区**：窗口前段，推理清晰、能吃下全部上下文。
- **愚蠢区**：窗口填得过满后出现幻觉、遗忘、推理崩坏。
- 作者的经验阈值：**用到约 40% 就开始警惕**（20 万窗口约 8 万 token）；有人认为 60–70%，但没人否认分界存在。
- 后续补充：窗口已扩到 100 万 token，40% 这个比例仍然成立；变大的只是"愚蠢区里能干的事"，智能区的绝对容量没怎么变。

## 限制二：模型是数据库，但存的是模糊 JPEG

- 训练把海量数据压缩成一组参数，像把整个互联网压成一张几乎看不清的 JPEG。
- 问**预训练知识**：等于让它回忆这张 JPEG，输出不可靠。
- 问**上下文里的内容**：原始信息就在窗口里，回答可靠（但仍受第一个限制影响）。
- 推论：不要把它当检索库，让它读文件、跑命令、查文档，而不是考它记不记得某个新 API。

## 限制三：知识截止 + 完全无状态

- **知识截止**：部署后模型不更新，不知道截止日期之后的世界；所以它不了解最新框架版本。作者的态度更极端——干脆不指望它有任何背景知识。
- **无状态**：每次请求都不带记忆，清空上下文等于把在代码库里积累的领域知识全部抹掉，要从头重建。
- 推论：文档、代码组织、CLAUDE.md 的质量直接决定代理的表现——这是唯一能跨会话保留的东西。

## 对比真人

团队里新来的工程师：可能十点才到岗，但他有记忆、会随时间学习、记得上次讨论的内容。模型这三条全都没有。

## 术语

| 词 | 含义 |
|---|---|
| token | 模型处理的最小单位 |
| 上下文窗口 | 一次对话里模型能看到的全部 token |
| 智能区 / 愚蠢区 | 窗口利用率低 / 高时模型能力的两个档位 |
| 知识截止 | 预训练数据的时间边界 |
| 无状态 | 请求之间不保留任何记忆 |
