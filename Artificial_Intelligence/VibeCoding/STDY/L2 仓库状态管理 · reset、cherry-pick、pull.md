课程用三个命令管理"你的分支"和"课程录制时的快照"：`pnpm reset` 完全回退，`pnpm cherry-pick` 保留现有工作再叠加一课，`pnpm pull` 拉上游更新。

## 分工

| 命令 | 做什么 | 保留你的改动 |
|---|---|---|
| `pnpm reset` | 把整个分支重置到课程某个提交 | 否，破坏性 |
| `pnpm cherry-pick` | 挑一个课程提交叠加到当前分支 | 是 |
| `pnpm pull` | 从上游 main 拉更新到当前分支 | 是 |

## reset

- 交互列表可按课号搜（`04.05.01`）或按关键词搜（如 `grilled me`）。
- 在 `main` 上不允许重置，会提示你输入新分支名；课程里用 `dev`，自动创建并切换。
- 它不只是 checkout：分支上所有"无关改动"一起被抹掉。所以要保留成果就别用 reset。
- 典型用途：做完一课想回到作者录制时的状态，或者跳到后面的章节。

## cherry-pick

- 冲突是预期内的：课程提交和你的改动落在同一行（比如 package.json 的描述字段）。
- 两种处理：直接让 Claude"修复这个 merge conflict"，或者 `git cherry-pick --abort` 放弃这次挑选——你自己的改动还在。
- 作者的判断：AI 处理合并冲突表现相当好。

## pull

- 等价于从父仓库拉 main 的更新进你的 dev 分支，不重置、不丢工作。
- 冲突同样交给 Claude。

## 一句话记法

三个命令是同一件事的三档力度：**全毁（reset）／叠加（cherry-pick）／更新（pull）**。
