## 1. 代价怎么数：先定一把尺

比较 15 种结构之前，先统一「贵不贵」的度量。复杂度数的不是秒数，而是**基本操作次数随 $n$ 的增长量级**；常数因子和低阶项忽略。

两条地基事实：

1. 内存是一条线性字节序列，每个字节有唯一地址。
2. 同类型元素大小相同。若数组首地址是 $B$、元素大小是 $s$，第 $i$ 个元素的地址是

$$
B+i\cdot s.
$$

数例：`int` 占 4 字节，`a` 的首地址是 `0x1000`：

| 元素 | 地址 |
| --- | --- |
| `a[0]` | `0x1000` |
| `a[1]` | `0x1004` |
| `a[6]` | `0x1018` |

访问 `a[6]` 只需三步：乘 $6\times4=24$、加 `0x1000`、读该地址。三步是常数，与数组长度 $n$ 无关，也与下标 $k$ 无关。这就是 $O(1)$。

**容易混的一点**：数组「按下标访问」是 $O(1)$，不代表数组的所有操作都是 $O(1)$。在中间插入要搬移元素，那是另一笔账，下一节算。

> [!question] 在一个含 $n$ 个元素的数组里访问 $a[k]$（$0\le k<n$），操作次数与哪个量有关？
> - 操作次数与 $k$ 成正比
> - 固定次数操作，与 $n$、$k$ 都无关
> - 操作次数与 $n$ 成正比
> - 我不知道

> [!success]- ✓ 正确
> 固定次数：乘、加、读。地址 $B+k\cdot s$ 可以直接算出，不需要跳过前 $k$ 个元素。

## 2. 数组：连续布局的账单

访问 $O(1)$ 的代价，是修改时必须维持连续。

在长度为 $n$ 的数组的位置 $k$ 插入（$0\le k\le n$），原来的 $a[k],\dots,a[n-1]$ 都要右移一格，共

$$
n-k
$$

次搬移。两个端点：

| 插入位置 | 搬移次数 | 复杂度 |
| --- | --- | --- |
| 头部 $k=0$ | $n$ | $O(n)$ |
| 中间 $k$ | $n-k$ | $O(n)$ |
| 尾部 $k=n$ | $0$ | $O(1)$ |

删除同理：删掉 $a[k]$ 后，$a[k+1],\dots,a[n-1]$ 要左移，共 $n-k-1$ 次。

数例：$n=10^6$，在头部插入要搬 $10^6$ 个元素；在尾部插入不用搬。所以「数组插入是 $O(n)$」准确说是**除尾部外是 $O(n)$**；尾部插入在容量足够时是 $O(1)$。

一句话：**连续布局让地址算术成立，于是访问免费；但保持连续必须搬移，于是中间修改昂贵。** 这笔账会在链表那里反过来（布局对比见第 4 节图）。

> [!note] 「移动」在这里指什么
> 复杂度里的「移动」= 把一个元素从旧槽写到新槽，算一次元素搬移；不特指 C++ 的 `std::move`，也不必然深拷贝。
> - `int`、指针等定长类型：一次搬移就是拷贝几个字节，$O(1)$。
> - `std::string` 等：`std::vector` 搬移时若移动构造是 `noexcept`，走移动（偷指针，$O(1)$）；否则可能走拷贝，成本随内容长度。
> - 元素本身很大时，常存指针/索引，让每次搬移仍是 $O(1)$。
>
> 另外，容量不足时的**扩容**是另一笔账：把 $n$ 个元素搬到新缓冲区，再做 $n-k$ 次搬移。两者都是 $O(n)$，但常数不同。

### C++ 最小实现

```cpp
#include <array>

constexpr std::array<int, 5> a{10, 20, 30, 40, 50};
static_assert(a[3] == 40);   // 地址 = 首地址 + 3 * sizeof(int)，与 n 无关

void insert_at(int* a, int& n, int pos, int v) {
    for (int i = n; i > pos; --i) a[i] = a[i - 1];  // 后面的元素整体右移
    a[pos] = v;
    ++n;
}
```

**应用场景**：查找表、图像缓冲区、矩阵、`std::vector` 的底层。连续布局对 CPU 缓存最友好：遍历时一条缓存行会顺带装入多个相邻元素。

> [!question] 在含 $n$ 个元素的数组第 $k$ 个位置插入（容量足够，不计扩容），需要搬移多少个元素？
> - $k$ 个
> - $n-k$ 个
> - $n$ 个
> - 我不知道

> [!success]- ✓ 正确
> 下标 $k$ 及其后的 $n-k$ 个元素都要右移一格；头部 $k=0$ 时是 $n$ 个，尾部 $k=n$ 时是 $0$ 个。

## 3. 动态数组：扩容策略决定摊还代价

定长数组不能长。`std::vector` 的做法是：容量满了就申请一块更大的新内存，把旧元素搬过去，再释放旧块。

设当前有 $n$ 个元素，扩容一次要搬 $n$ 个。关键问题不是「搬一次多贵」，而是「**$n$ 次 push_back 总共搬多少次**」。

### 固定增量：总代价 $\Theta(n^2)$

每次只加固定容量 $c$。第 $c,2c,3c,\dots$ 次插入时扩容，搬移量分别是 $c,2c,3c,\dots$：

$$
c+2c+\cdots+\frac{n}{c}c
= c\left(1+2+\cdots+\frac{n}{c}\right)
= \Theta(n^2).
$$

单次均摊 $\Theta(n)$。

### 倍增：总代价 $\Theta(n)$

容量按 $1,2,4,8,\dots$ 增长。总搬移量

$$
1+2+4+\cdots+n < 2n = O(n).
$$

单次均摊 $O(1)$。

数例：$n=10^6$。

| 策略 | 扩容次数 | 总搬移量 | 量级 |
| --- | --- | --- | --- |
| 每次 $+1$ | $10^6$ | $\approx 5\times10^{11}$ | $\Theta(n^2)$ |
| 每次 $+1000$ | $1000$ | $\approx 5\times10^8$ | $\Theta(n^2)$ |
| 每次 $\times2$ | $20$ | $<2\times10^6$ | $\Theta(n)$ |

**注意**：C++ 标准要求 `push_back` 摊还 $O(1)$，但**不规定**扩容倍数；libstdc++ 常用 2 倍，MSVC 常用 1.5 倍。固定增量不满足摊还 $O(1)$。

这就是摊还分析：单次操作偶尔很贵，但把总账摊到每次操作上，平均是常数。

### C++ 最小实现：一个会倍增的 Vec

```cpp
#include <algorithm>

struct Vec {
    int* data = nullptr;
    int size = 0, cap = 0;

    void push(int v) {
        if (size == cap) {
            int nc = cap ? cap * 2 : 1;
            int* p = new int[nc];
            std::copy(data, data + size, p);  // 搬旧元素
            delete[] data;
            data = p;
            cap = nc;
        }
        data[size++] = v;
    }
    ~Vec() { delete[] data; }
};
```

`size == cap` 时不能直接在原块后面续写——后面那段内存可能已被别人占用。只能申请一块更大的新内存，把旧元素搬过去，再释放旧块。下图是 `push(50)` 触发 4 → 8 扩容的全过程：

![[viz-dynamic-array-capacity-grow-1794660155436.svg|650]]

**应用场景**：`std::vector`、`std::string`、栈的底层缓冲。绝大多数「不知道要存多少个」的序列都用它；倍增让 push 均摊 $O(1)$，代价是最多多占一倍容量。

> [!question] 如果 vector 每次扩容只增加固定容量 $c$（$c$ 为常数），连续 push_back $n$ 次的总复杂度是多少？
> - $O(n^2)$
> - $O(n\log n)$
> - $O(n)$
> - 我不知道

> [!question] 不知道
> 先把「每次扩容搬多少」列出来再加总。下面用 $n=5$ 手算。

### 用 $n=5$ 手算

容量从 0 开始，每次只 $+1$：

| 插入第几个 | 扩容前容量 | 本次搬移 | 累计搬移 |
| --- | --- | --- | --- |
| 1 | 0 | 0 | 0 |
| 2 | 1 | 1 | 1 |
| 3 | 2 | 2 | 3 |
| 4 | 3 | 3 | 6 |
| 5 | 4 | 4 | 10 |

累计搬移 $0+1+2+3+4=10$。一般地，

$$
0+1+\cdots+(n-1)=\frac{n(n-1)}{2}=\Theta(n^2).
$$

所以固定增量扩容的总代价是 $\Theta(n^2)$，不是 $O(n)$。

> [!question] 每次 $+1$ 扩容，插入到第 5 个元素时，累计搬移了多少次？
> - 5 次
> - 10 次
> - 15 次
> - 我不知道

> [!failure]- ✗ 不对
> $15=1+2+3+4+5$，把第 5 个元素自己也算进搬移了。扩容发生在写入新元素**之前**：容量 4 已满，先搬已有的 4 个，再把第 5 个写进去。所以第 5 次插入搬 4 个，累计 $0+1+2+3+4=10$。

> [!question] 每次 $+1$ 扩容，插入第 5 个元素时，这一次扩容搬移多少个已有元素？
> - 4 个
> - 5 个
> - 10 个
> - 我不知道

> [!success]- ✓ 正确
> 旧书 4 本搬到新书架，第 5 本在扩容后直接放入。这一次只搬 4 个。

> [!question] 按每次 $+1$ 扩容，前 5 次插入累计搬移多少次？
> - 4 次
> - 10 次
> - 15 次
> - 我不知道

> [!success]- ✓ 正确
> $0+1+2+3+4=10$。第 1 次不需要搬，之后每次搬「已有的元素个数」。

> [!question] 固定 $+1$ 扩容，连续 push_back $n$ 次的总复杂度是多少？
> - $O(n)$
> - $O(n\log n)$
> - $O(n^2)$
> - 我不知道

> [!success]- ✓ 正确
> $0+1+\cdots+(n-1)=n(n-1)/2=\Theta(n^2)$。固定增量扩容的均摊代价是 $\Theta(n)$，不是 $O(1)$。

## 4. 链表：用指针换掉搬移

数组的中间修改贵，是因为元素必须连续。链表放弃连续：每个节点单独分配，节点里存

- 值；
- 指向下一个节点的指针。

节点在内存里可以散落，靠指针串起来。

![[viz-array-vs-linked-list-1794635597533.svg|650]]

**已知位置插入**：在节点 $p$ 后插入 $x$：

```cpp
x->next = p->next;
p->next = x;
```

两次指针赋值，与链表长度无关，$O(1)$。

**删除**：若已知前驱 `prev` 和目标 `p`：

```cpp
prev->next = p->next;
```

一次指针赋值，$O(1)$。

**代价**：没有下标算术。找第 $k$ 个节点，必须从头沿 `next` 走 $k$ 步：

$$
O(k),\quad \text{最坏 } O(n).
$$

数例：$n=10^6$。头部插入时数组要搬 $10^6$ 个元素；链表若已持有头节点指针，只需改两次指针。但找第 $500{,}000$ 个节点，链表要走 $500{,}000$ 步，数组一次地址计算就够。

**最容易混的一点**：「链表插入 $O(1)$」的前提是**已经拿到那个位置的节点/迭代器**。若只给头指针、要求在第 $k$ 个位置插入，找位置本身要 $O(k)$，总代价 $O(k)$。

C++：`std::list` 是双向链表，`std::forward_list` 是单向链表；`insert`/`erase` 对迭代器是 $O(1)$，`std::find` 是 $O(n)$。

### C++ 最小实现：单链表节点与指针操作

```cpp
struct Node {
    int val;
    Node* next = nullptr;
};

void push_front(Node*& head, int v) { head = new Node{v, head}; }

void insert_after(Node* p, int v) { p->next = new Node{v, p->next}; }

void erase_after(Node* prev) {
    Node* p = prev->next;
    prev->next = p->next;
    delete p;
}
```

`insert_after`、`erase_after` 都只动一两个指针，这就是「已知位置 $O(1)$」的字面含义；但 `head` 要传引用，因为插入可能换头。生产代码直接用 `std::list`/`std::forward_list`，不必手写 `new`/`delete`。

**工程边界**：链表的 $O(1)$ 是指针操作的理论账；每个节点多一个/两个指针，且节点分散，缓存不友好。遍历大链表常比遍历数组慢一个可观常数。多数场景 `std::vector` 仍是默认选择。

**应用场景**：LRU 缓存的「最近使用顺序」、图的邻接表、操作系统的空闲链表、浏览器的前进后退（双向链表）。链表适合「已经拿到节点、频繁插删」；不适合「按下标随机访问」。

> [!question] 在长度为 $n$ 的单链表中，只给头指针，要在第 $k$ 个位置插入一个新节点，总时间复杂度最准确的是？
> - $O(1)$
> - $O(k)$
> - $O(n^2)$
> - 我不知道

> [!success]- ✓ 正确
> 改指针是 $O(1)$，但先要沿 `next` 走 $k$ 步找到位置，所以总代价是 $O(k)$。

## 5. 栈、队列、双端队列：限制操作，换来 $O(1)$

数组和链表都允许在任意位置读写。很多问题只需要在一端或两端操作；把允许的操作**限制住**，实现就能更简单，代价也更稳定。

三种抽象契约：

| 结构 | 规则 | 操作 | 典型用途 |
| --- | --- | --- | --- |
| 栈 stack | LIFO，后进先出 | push / pop / top | 函数调用栈、撤销、括号匹配、DFS |
| 队列 queue | FIFO，先进先出 | enqueue / dequeue / front | BFS、任务调度、打印队列 |
| 双端队列 deque | 两端都可进出 | 两端 push/pop | 滑动窗口、浏览器前进后退、撤销重做 |

![[viz-stack-lifo-vs-queue-fifo-refined-1794635622681.svg|650]]

**关键**：栈和队列是**抽象数据类型（ADT）**，规定「能做什么」，不规定「底层怎么存」。同一种 ADT 可以用数组、链表或双端队列实现。

- 栈用动态数组实现：push 是尾部追加，摊还 $O(1)$；pop 是尾部删除，$O(1)$。
- 队列用数组实现时，若直接头部删除会搬移 $O(n)$ 个元素；标准做法是**循环缓冲区**，用两个下标 `head`/`tail` 绕圈，enqueue/dequeue 都 $O(1)$。
- `std::deque` 通常是分段数组：两端 $O(1)$，随机访问 $O(1)$（分段映射有常数开销）。

C++ 容器适配器默认底层：

| 适配器                   | 默认底层          | 默认比较             |
| --------------------- | ------------- | ---------------- |
| `std::stack`          | `std::deque`  | —                |
| `std::queue`          | `std::deque`  | —                |
| `std::priority_queue` | `std::vector` | `std::less`（大顶堆） |

数例：括号匹配扫描 $n$ 个字符，每个字符最多入栈一次、出栈一次，总 $O(n)$，栈深最多 $n$。

**边界**：递归过深会耗尽调用栈；队列用普通数组实现而不循环，dequeue 会退化成 $O(n)$。

### C++ 最小实现

```cpp
#include <queue>
#include <stack>

std::stack<int> st;
st.push(1); st.push(2);
int top = st.top();   // 2
st.pop();

std::queue<int> q;
q.push(1); q.push(2);
int front = q.front(); // 1
q.pop();
```

**应用场景**：栈用于函数调用栈、括号匹配、撤销、DFS；队列用于 BFS、任务调度、打印队列、消息队列；双端队列用于滑动窗口、浏览器前进后退。

> [!question] C++ 的 `std::stack` 默认用哪个容器作为底层？
> - `std::vector`
> - `std::list`
> - `std::deque`
> - 我不知道

> [!success]- ✓ 正确
> `std::stack` 的模板声明是 `stack<T, Container = std::deque<T>>`；`std::queue` 同理。

## 6. 哈希表与哈希集合：把 key 变成下标

数组的 $O(1)$ 访问依赖「下标是连续整数」。哈希表把任意 key 映射成整数，再映射到桶：

$$
\text{bucket} = h(\text{key}) \bmod m.
$$

![[viz-hash-collision-chaining-1794635609927.svg|650]]

查找三步：

1. 算 $h(\text{key})$；
2. 取模得到桶号；
3. 在桶内比较 key。

若哈希函数均匀、装载因子 $\alpha=n/m$ 有上界，桶内平均只有常数个元素，平均 $O(1)$。

**冲突**：不同 key 可能落到同一个桶。两种主流处理：

- 链地址法：每个桶挂一条链表（或红黑树）；冲突多时桶内线性查找。
- 开放寻址：冲突时按规则找下一个空槽；装载因子接近 1 时性能急剧下降。

最坏情况：所有 key 都冲突到同一个桶，查找退化成 $O(n)$。

**rehash**：装载因子超过阈值时，申请更大的桶数组，把所有元素重新插入。单次 rehash 是 $\Theta(n)$；若桶数组按几何级数增长，摊到每次插入是 $O(1)$。

**哈希集合**：只有 key、没有 value，只回答「在不在」。插入时若已存在则不重复插入，因此天然去重。

数例：$m=1000$ 个桶，$n=1000$ 个 key，$\alpha=1$，平均每个桶 1 个元素，查找约 2 次比较（算哈希 + 比较桶内元素）。若 1000 个 key 全冲突，桶内是一条长 1000 的链，查找 $O(n)$。

**边界**：无序（不能按 key 顺序遍历）；最坏情况可被构造；桶数组和节点指针有内存开销；哈希函数质量决定平均性能。

C++：`std::unordered_map` / `std::unordered_set`；平均 $O(1)$，最坏 $O(n)$。

### C++ 最小实现：词频统计

```cpp
#include <string>
#include <unordered_map>

std::unordered_map<std::string, int> freq;
for (const char* w : {"a", "b", "a", "c", "a"}) ++freq[w];
// freq["a"] == 3, freq["b"] == 1, freq["c"] == 1
```

**应用场景**：词频统计、去重、缓存索引、数据库哈希索引、编译器符号表。下图是一条词流如何落到桶里。

![[viz-hash-table-word-frequency-1794660195573.svg|650]]

## 7. 树与二叉搜索树：用顺序换查找

哈希表平均 $O(1)$，但不维护顺序；若需要按 key 排序、范围查询、前驱/后继，就要用树。

**树**：一个根节点，每个节点有若干子节点，无环。$n$ 个节点的树有 $n-1$ 条边。二叉树每个节点最多两个孩子。

**BST 不变式**：对每个节点，

$$
\text{左子树所有 key} < \text{节点 key} < \text{右子树所有 key}.
$$

![[viz-bst-order-labeled-1794635598392.svg|650]]

查找：从根开始，比当前节点小就走左，大就走右。每步丢掉一半（若平衡），高度 $O(\log n)$，查找 $O(\log n)$。中序遍历得到有序序列。

**最坏情况**：按升序插入 $1,2,\dots,n$，树退化成一条链，高度 $n$，查找 $O(n)$。所以「BST 查找 $O(\log n)$」只在**平衡**或**随机插入**下成立；要保证最坏 $O(\log n)$，需要自平衡树（AVL、红黑树）。

数例：$n=10^6$，平衡树高度约 $\log_2 10^6\approx20$，查找最多 20 次比较；升序插入的链高度 $10^6$，查找最多 $10^6$ 次比较。

C++：`std::map` / `std::set` 通常用红黑树，查找/插入/删除 $O(\log n)$，有序遍历；`std::unordered_map` / `std::unordered_set` 平均 $O(1)$，无序。

**选型**：只需要「按 key 取值」→ 哈希；需要「有序、范围、前驱后继」→ 平衡 BST。

### C++ 最小实现：有序映射

```cpp
#include <map>
#include <string>

std::map<int, std::string> m;   // 红黑树，按 key 有序
m[3] = "c"; m[1] = "a"; m[2] = "b";
// 遍历顺序：1, 2, 3

auto it = m.lower_bound(2);      // 第一个 key >= 2 的位置
```

**应用场景**：数据库索引、排行榜、区间查询、需要按 key 顺序遍历的配置表。只需要精确查找时用 `unordered_map`；需要顺序时用 `map`。

## 8. 堆：只维护「谁最重要」

BST 维护完整顺序，代价是每个节点都要满足左小右大。如果只关心**当前最大/最小**，不需要完整顺序，可以用更弱的条件换更便宜的操作。

**堆**是一棵完全二叉树，满足堆序：

- 大顶堆：每个节点 $\ge$ 它的孩子，根是最大值；
- 小顶堆：每个节点 $\le$ 它的孩子，根是最小值。

它**只保证根是极值**，不保证左右子树之间有序。

**数组存储**：完全二叉树可以按层放进数组，不需要指针。下标 $i$ 的孩子是 $2i+1,2i+2$，父亲是 $\lfloor(i-1)/2\rfloor$。

**操作**：

| 操作 | 做法 | 复杂度 |
| --- | --- | --- |
| top | 读 `a[0]` | $O(1)$ |
| push | 放到末尾，向上筛 | $O(\log n)$ |
| pop | 末尾移到根，向下筛 | $O(\log n)$ |
| build | 从最后一个非叶节点向前，逐个向下筛 | $O(n)$ |

**建堆为什么是 $O(n)$ 而不是 $O(n\log n)$**：高度 $h$ 的节点最多 $n/2^{h+1}$ 个，每个向下筛最多 $h$ 层，总代价

$$
\sum_{h\ge0} \frac{n}{2^{h+1}}h
= \frac{n}{2}\sum_{h\ge0}\frac{h}{2^h}
= O(n).
$$

大多数节点在底层，只需筛很少几层；只有根可能筛 $\log n$ 层。逐个插入建堆才是 $O(n\log n)$。

数例：$n=10^6$，堆高约 20。push/pop 最多比较 20 次；自底向上建堆总比较次数是 $O(n)$ 量级（`std::make_heap` 至多 $3n$ 次比较）。

C++：`std::priority_queue<T>` 默认大顶堆；`std::priority_queue<T, std::vector<T>, std::greater<T>>` 是小顶堆。底层是 `std::vector`，用 `std::push_heap` / `std::pop_heap` 维护。

**别混淆**：数据结构的 heap 和内存分区里的 heap（自由存储区）是两回事，只是同名。

**边界**：堆不排序，不能高效查找任意元素；只能快速拿到极值。适合优先队列、Dijkstra、任务调度、Top-K。

### C++ 最小实现：优先队列与 Top-K

```cpp
#include <queue>
#include <vector>

std::priority_queue<int> maxq;                                       // 大顶堆
std::priority_queue<int, std::vector<int>, std::greater<int>> minq;  // 小顶堆

std::vector<int> top_k(const std::vector<int>& a, int k) {
    std::priority_queue<int, std::vector<int>, std::greater<int>> q;
    for (int x : a) {
        q.push(x);
        if ((int)q.size() > k) q.pop();   // 弹掉当前最小的
    }
    std::vector<int> out;
    while (!q.empty()) { out.push_back(q.top()); q.pop(); }
    return out;
}
```

**应用场景**：Top-K、任务调度、Dijkstra / Prim、事件模拟。下图是大小为 3 的小顶堆如何筛出前 3 名。

### 自底向上建堆到底在做什么

「自底向上」指的是**处理节点的顺序**：从最后一个非叶节点开始，倒着处理到根，而不是从根往下。

![[viz-binary-heap-array-siftdown-refined-1794636066933.svg|650]]

1. **叶子天然是堆**：没有孩子，堆序条件空洞地成立，不用处理。
2. **最后一个非叶节点**的下标是 $\lfloor n/2\rfloor-1$（从它开始，后面的全是叶子）。
3. 处理节点 $i$ 时，它的孩子下标 $2i+1,2i+2$ 都大于 $i$，已经在之前的步骤里处理过，所以左右子树各自是合法的堆。
4. 因此只需对 $i$ 做一次 **sift-down**（与较大的孩子比较、交换、继续下沉），就能把以 $i$ 为根的整棵子树修成堆。

以 $n=7$、数组 `[4, 10, 3, 5, 1, 2, 8]` 为例，就是上图：

| 步骤 | 处理节点 | 发生什么 |
| --- | --- | --- |
| ① | $i=2$（值 3） | 与较大的孩子 8 交换 |
| ② | $i=1$（值 10） | 10 比 5、1 都大，不动 |
| ③ | $i=0$（值 4） | 与较大的孩子 10 交换；到新位置后与 5 交换 |

倒序是关键：先修好孩子，再修父亲；父亲下沉时，孩子的子树已经是堆，所以一次 sift-down 就够。

### 用 $n=7$ 手算建堆

| 层 | 节点数 | 最多向下筛几层 | 代价上界 |
| --- | --- | --- | --- |
| 根 | 1 | 2 | 2 |
| 第二层 | 2 | 1 | 2 |
| 叶子 | 4 | 0 | 0 |
| 合计 | 7 | — | 4 |

总代价不超过 4，而 $n\log n$ 约为 $7\times2.8\approx20$。一半以上的节点是叶子，什么都不用做；越往上节点越少。求和

$$
\sum_{h\ge0}\frac{n}{2^{h+1}}h
= \frac{n}{2}\sum_{h\ge0}\frac{h}{2^h}
= O(n)
$$

收敛到 $2n$，所以是 $O(n)$。

> [!question] $n=15$ 的四层满二叉树，自底向上建堆的总向下筛层数上界是多少？
> - 11 次
> - 15 次
> - 34 次
> - 我不知道

> [!success]- ✓ 正确
> 按高度分层：高度 3 的 1 个节点至多筛 3 层，高度 2 的 2 个至多 2 层，高度 1 的 4 个至多 1 层，叶子 8 个筛 0 层，总计 $3+4+4=11$。越高层节点越少，这正是总代价 $O(n)$ 的来源。

## 9. 图：放弃层级，允许任意连接

树要求「一个根、每个节点一个父亲、无环」。现实中的连接常常不是层级：朋友关系互相连通、城市之间有多条路、网页互相链接。要表达这种关系，就得允许任意两个顶点相连。

**图的定义**：图 $G=(V,E)$ 由顶点集合 $V$ 和边集合 $E$ 组成。边连接两个顶点；有方向记作 $(u,v)$，无方向记作 $\{u,v\}$。两个顶点由一条边相连时，称它们**相邻**，互称邻居。

- **无向图**：边双向，如微信好友；**有向图**：边单向，如微博关注——你关注对方，对方不一定关注你。
- **带权图**：每条边附一个数值（距离、时间、费用），如地图导航。

树是图的特例：连通、无环、$|E|=|V|-1$。图则允许环、允许一个顶点有很多邻居、允许不连通。

**怎么存**：两种基本表示。

| 表示 | 空间 | 判断 $u,v$ 是否相邻 | 枚举 $u$ 的邻居 |
| --- | --- | --- | --- |
| 邻接矩阵 | $O(V^2)$ | $O(1)$ | $O(V)$ |
| 邻接表 | $O(V+E)$ | $O(\deg u)$ | $O(\deg u)$ |

邻接矩阵是一张 $V\times V$ 的表，`a[u][v]=1` 表示有边（带权就存权重）。邻接表是每个顶点挂一个邻居列表。时间与空间的取舍取决于**稀疏程度**：

- $E\ll V^2$ 的稀疏图用邻接表，只存真实存在的边；
- $E$ 接近 $V^2$ 的稠密图用矩阵，判断相邻 $O(1)$，实现也简单。

数例：$V=10^6$ 个城市、$E=3\times10^6$ 条路，邻接矩阵要 $10^{12}$ 个格子，邻接表只需约 $2E=6\times10^6$ 条记录。

**遍历**：从起点出发访问所有可达顶点。

- **BFS**：用队列，一层一层向外扩；在无权图上，第一次到达某点就是最短路。
- **DFS**：用栈或递归，一条路走到底再回退。

邻接表下两者都是 $O(V+E)$；邻接矩阵下是 $O(V^2)$，因为每次枚举邻居都要扫一整行。

图能表达「谁和谁相连」：社交网络、地图导航、网页链接、任务依赖、状态机。只要关系不是树状层级，就考虑图。

> [!question] 一张有 $V=10^6$ 个顶点、$E=3\times10^6$ 条边的无向图，用邻接矩阵存要占多少个格子？
> - $10^6$ 个
> - $3\times10^6$ 个
> - $10^{12}$ 个
> - 我不知道

> [!success]- ✓ 正确
> 矩阵是 $V\times V$，与边数无关：$10^6\times10^6=10^{12}$ 个格子。每个格子哪怕只存 1 字节也要约 1 TB，所以稀疏图必须用邻接表。

> [!question] 用邻接表存图，BFS 遍历所有可达顶点的时间复杂度是多少？
> - $O(V)$
> - $O(E)$
> - $O(V+E)$
> - 我不知道

### BFS 在邻接表上到底扫了什么

![[viz-bfs-adjacency-list-o-v-plus-e-1794656324153.svg|650]]

BFS 只做两件事：

1. 每个顶点**出队一次**；
2. 出队时，把它邻接表里的**每条记录看一遍**。

无向图里每条边 $(u,v)$ 在 $u$ 的邻接表里存一次、在 $v$ 的邻接表里也存一次，所以总邻接记录数是 $2E$。因此总步数

$$
\underbrace{V}_{\text{顶点出队}} + \underbrace{2E}_{\text{扫邻接记录}} = O(V+E).
$$

以一张 6 个顶点、6 条边的小图为例，队列的完整变化画在下面：

jixv![[viz-bfs-queue-six-steps-1794656466221.svg|650]]

扫过的邻接记录共 $2+2+2+2+3+1=12=2E$，出队 6 次 $=V$，合计 18 步。即使图再大，也是「顶点数 + 边数」的量级。

对比邻接矩阵：每出队一个顶点都要扫一整行 $V$ 个格子，总共 $V^2$，与边数无关——稀疏图上大部分格子是空的 0。

### C++ 最小实现：邻接表 + BFS

```cpp
#include <queue>
#include <vector>

std::vector<std::vector<int>> g(n);
g[0].push_back(1); g[1].push_back(0);   // 无向边 0-1

std::vector<int> dist(n, -1);
std::queue<int> q;
dist[0] = 0; q.push(0);
while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : g[u]) {
        if (dist[v] != -1) continue;
        dist[v] = dist[u] + 1;
        q.push(v);
    }
}
```

**应用场景**：社交网络的好友关系、地图导航、网页链接、任务依赖、网络路由。下图对比「图」在两个场景里的具体长相。

## 10. Trie：把单词拆成字符路径

哈希表擅长「给定完整 key 取值」，但不擅长「给一个前缀，列出所有以它开头的 key」：哈希函数把 key 打散，前缀相同的单词落在完全无关的位置，只能逐个检查全部 key。

Trie（读作 “try”）换一种存法：**把 key 的每个字符放在一条边上**，从根走到某个节点的路径拼起来，就是该节点代表的前缀。

- 根代表空字符串；
- 每条边标一个字符；
- 节点用**结束标记**表示「这里恰好是一个完整单词」。

共享前缀的单词共享同一条路径：`app`、`apple`、`apply` 都走 根→a→p→p，之后才分叉。

![[viz-trie-shared-prefix-char-tree-1794657095473.svg|650]]

**操作**（$L$ = 单词长度）：

- **插入**：沿字符逐层走，缺节点就建，最后打结束标记，$O(L)$。
- **精确查找**：沿字符走到底，检查结束标记，$O(L)$。
- **前缀查找**：走 $L$ 步到前缀节点，再 DFS 它的子树收集所有结束标记，$O(L+\text{输出字符数})$。

关键差别：哈希表的前缀查找要检查全部 $n$ 个 key，$O(n)$；Trie 只走前缀长度步，与总词数无关。

数例：$10^5$ 个单词、平均长度 8。输入 `app` 时，哈希表最多要比对 $10^5$ 个 key；Trie 只走 3 步，然后只遍历以 `app` 开头的子树。

**空间**：节点数约等于所有单词的字符总数，共享前缀只存一份。每个节点要存「字符 → 子节点」的映射：26 叉数组快但稀疏时大量空位；哈希表省空间但每步多一次查表。实际实现常用压缩前缀（radix tree）把单链合并。

### C++ 最小实现：小写字母 26 叉 Trie

```cpp
#include <array>
#include <string_view>

struct Trie {
    std::array<Trie*, 26> next{};
    bool end = false;

    void insert(std::string_view w) {
        Trie* cur = this;
        for (char c : w) {
            int i = c - 'a';
            if (!cur->next[i]) cur->next[i] = new Trie;
            cur = cur->next[i];
        }
        cur->end = true;
    }

    bool contains(std::string_view w) const {
        const Trie* cur = this;
        for (char c : w) {
            cur = cur->next[c - 'a'];
            if (!cur) return false;
        }
        return cur->end;
    }
};
```

教学版省略了析构函数，真实实现要递归释放每个 `next` 指针。`insert` 和 `contains` 都只走 $L$ 步，与词库大小无关。

**应用场景**：搜索框自动补全、拼写检查、词典、IP 路由（二进制 Trie）、敏感词过滤。下图是输入 `app` 后如何沿前缀走到子树并列出补全候选。

## 11. 并查集：只回答「是不是同一组」

**问题**：有 $n$ 个元素，不断执行两种操作：

- **合并**两个元素所在的组；
- **询问**两个元素是否在同一组。

如果每次询问都沿关系链走一遍，在动态合并的场景里会越来越慢。并查集（disjoint set / union-find）只维护「每个元素属于哪一组」，把这两个操作都做到接近 $O(1)$。

**存储**：一个 `parent` 数组。每个元素指向它的父节点；一个组的**代表**（leader / root）指向自己。

- `find(x)`：沿 `parent` 一路走到根，返回根。
- `union(x,y)`：先 `find` 出两个根，再把其中一个根挂到另一个根下面。
- 判断同组：`find(x) == find(y)`。

**两个优化**：

1. **按大小 / 按秩合并**：合并时把较矮（或较小）的树挂到较高（较大）的树下面，避免长链，树高 $O(\log n)$。
2. **路径压缩**：`find(x)` 找到根之后，把路径上所有节点直接挂到根。之后再查这些节点就是一步。

两者合用，单次操作均摊 $O(\alpha(n))$，$\alpha$ 是反阿克曼函数，在实际能遇到的任何 $n$ 下都不超过 4，可当作 $O(1)$。

**例**：`1..5`，依次 `union(1,2)`、`union(3,4)`、`union(2,3)`：

- `2` 挂到 `1`；`4` 挂到 `3`；
- `find(2)=1`，`find(3)=3`，按大小把 `3` 挂到 `1`，此时 `4→3→1`；
- `find(4)` 走 `4→3→1`，压缩后 `4→1`、`3→1`。

![[viz-union-find-path-compression-1794657383685.svg|650]]

空间 $O(n)$，就是一个数组。

### C++ 最小实现：带路径压缩与按大小合并

```cpp
#include <numeric>
#include <vector>

struct DSU {
    std::vector<int> p, sz;

    explicit DSU(int n) : p(n), sz(n, 1) { std::iota(p.begin(), p.end(), 0); }

    int find(int x) {
        if (p[x] == x) return x;
        return p[x] = find(p[x]);   // 路径压缩：顺路把每个节点挂到根
    }

    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;   // 已经同组，合并会成环
        if (sz[a] < sz[b]) std::swap(a, b);
        p[b] = a;                   // 小树挂到大树下
        sz[a] += sz[b];
        return true;
    }
};
```

`unite` 返回 `false` 正好表示「这条边会成环」——Kruskal 就是靠这个信号跳过环边。

**应用场景**：网络连通性、Kruskal 最小生成树、图像连通块、账户合并、渗透（percolation）。下图是 Kruskal 从小到大选边、用 `find` 判环的过程。

![[viz-kruskal-union-find-1794660126679.svg|650]]

> - 把 5、4、3 的父指针都直接指向 1
> - 把 1 的父指针改成指向 5

## 12. 布隆过滤器：允许单向错误的集合

**动机**：判断「某个元素在不在集合里」，集合有几十亿条，全部存下来内存放不下。能不能用很小的空间，换一个**方向可控**的错误？

布隆过滤器用**位数组 + 多个哈希函数**：

- 位数组 $m$ 位，初始全 0；
- $k$ 个不同的哈希函数，每个把元素映射到一位。

**插入** $x$：算出 $k$ 个哈希，把对应的 $k$ 位全部置 1。

**查询** $x$：

- 只要有**任意一位是 0** → $x$ **一定不在**（插入时它的所有位都会被置 1）；
- 如果**所有位都是 1** → $x$ **可能在**（这些位可能是别的元素置的）。

所以错误只朝一个方向：**没有假阴性，只有假阳性**。这正是它能用的原因——当它说「不在」时，可以放心跳过昂贵操作。

**为什么不会有假阴性**：插入只置 1，从不置 0，已插入元素的位永远不会被清掉；但不同元素会共享位，别人置的 1 会让一个没插入过的元素看起来「全 1」。

**数例**：$m=10$，$k=2$。插入 `cat` 置位 2、7。

- 查 `dog`：哈希到 2、5。位 5 是 0 → 一定不在。
- 查 `fox`（没插入过）：哈希到 2、7。两位都是 1 → 判「可能在」，实际不在 → 假阳性。

![[viz-bloom-filter-false-positive-bits-1794657960422.svg|650]]

**代价与参数**：位数组越小、插入元素越多，位越拥挤，假阳性率越高。$m$ 位、$n$ 个元素、$k$ 个哈希时，假阳性率约为

$$
\left(1-e^{-kn/m}\right)^k.
$$

给定 $m/n$，最优 $k=\frac{m}{n}\ln 2$。经验值：约 10 bit/元素 → 1% 假阳性；约 14 bit/元素 → 0.1%。

**限制**：标准布隆过滤器不支持删除——把某位置 0 会误伤共享该位的其他元素。需要删除时用计数布隆过滤器或 Cuckoo filter。

### C++ 最小实现：两个哈希凑出 $k$ 个位置

```cpp
#include <string_view>
#include <vector>

struct Bloom {
    std::vector<bool> bits;
    int m;

    explicit Bloom(int m_) : bits(m_, false), m(m_) {}

    int pos(std::string_view s, unsigned seed) const {
        return std::hash<std::string_view>{}(s) * seed % m;
    }

    void add(std::string_view s) {
        for (unsigned seed : {1u, 1315423911u}) bits[pos(s, seed)] = true;
    }

    bool maybe(std::string_view s) const {
        for (unsigned seed : {1u, 1315423911u})
            if (!bits[pos(s, seed)]) return false;   // 有一位 0 → 一定不在
        return true;                                  // 全 1 → 可能在
    }
};
```

这里用「同一个哈希乘不同种子」模拟两个独立哈希，真实实现常用双重哈希 $h_1 + i\cdot h_2$ 生成 $k$ 个位置，省去 $k$ 次哈希计算。`std::vector<bool>` 是位压缩的，一位只占 1 bit。

**应用场景**：密码泄露检查、Chrome 恶意网址预筛、拼写检查先快速排除、数据库避免磁盘查找、以太坊轻节点。下图是 Chrome 的 URL 清单如何经过布隆过滤器分流。

![[viz-bloom-filter-url-pipeline-1794660172940.svg|650]]

> - 一定正确
> - 可能错，存在假阴性
> - 不一定，取决于哈希函数

> [!success]- ✓ 正确

## 13. LRU 缓存：让两种结构各管一件事

**问题**：缓存空间有限，满了必须淘汰一个。选谁？**最近最少使用**（Least Recently Used）：最久没被访问的，最不可能马上被访问，先淘汰它。

需要同时支持：

- `get(key)`：有就返回并标记「刚用过」，没有返回空，$O(1)$；
- `put(key, value)`：写入并标记「刚用过」；超容量时淘汰最久未使用的，$O(1)$。

**单用一种结构都不够**：

- 哈希表：定位 $O(1)$，但不知道谁最久没用；
- 链表：能维护顺序，头尾插入删除 $O(1)$，但按 key 找节点要 $O(n)$；
- 数组：中间删除要搬移，$O(n)$。

**组合**：哈希表存 `key → 链表节点指针`，双向链表按最近使用排序：

- 队首 = 最近使用，队尾 = 最久未使用；
- `get`：哈希表 $O(1)$ 找到节点，把它从当前位置摘下、插到队首；
- `put`：已存在就更新值并移到队首；新 key 就新建节点插到队首并写入哈希表；若超容量，删掉队尾节点并从哈希表删除对应 key。

每一步都是「哈希表定位 + 链表摘除/插入」，所以 `get` 和 `put` 都是 $O(1)$。

![[viz-lru-hash-doubly-linked-o1-1794658701849.svg|650]]

**前驱 / 后继是什么**：链表节点除了存值，还存指向其他节点的指针。

- **后继**（successor）：排在我后面的那个节点，用 `next` 指向；
- **前驱**（predecessor）：排在我前面的那个节点，用 `prev` 指向。

`A → B → C` 里，B 的前驱是 A，后继是 C。

![[viz-predecessor-successor-linked-delete-1794659301117.svg|650]]

**为什么必须是双向链表**：要删除中间的 B，得让 B 的前驱 A 直接指向 B 的后继 C。单链表每个节点只有 `next`，站在 B 上只有指向 C 的路，没有回到 A 的指针，只能从 head 重新走到 A，$O(n)$。双向链表每个节点多了 `prev`，B 直接知道前驱是 A，于是 `A.next = C`、`C.prev = A` 两步指针修改就完成摘除，$O(1)$。

**例**：容量 2。`put(1,1)`、`put(2,2)` → 链表 `[2]⇄[1]`（2 最新）。`get(1)` → `[1]⇄[2]`。`put(3,3)` 超容量，淘汰队尾 2 → `[3]⇄[1]`。`get(2)` → 未命中。

**代价**：$O(1)$ 时间，额外空间 $O(\text{容量})$（哈希表 + 每个 key 一个链表节点）。真实系统常用近似 LRU（CLOCK、分段 LRU），因为严格维护顺序的常数与并发代价不小。

### C++ 最小实现：哈希表 + `std::list`

```cpp
#include <list>
#include <unordered_map>
#include <utility>

class LRU {
    int cap;
    std::list<std::pair<int, int>> order;              // 队首 = 最近使用
    std::unordered_map<int, std::list<std::pair<int, int>>::iterator> pos;

public:
    explicit LRU(int c) : cap(c) {}

    int get(int key) {
        auto it = pos.find(key);
        if (it == pos.end()) return -1;
        order.splice(order.begin(), order, it->second); // 摘下来插到队首，O(1)
        return it->second->second;
    }

    void put(int key, int value) {
        if (auto it = pos.find(key); it != pos.end()) {
            it->second->second = value;
            order.splice(order.begin(), order, it->second);
            return;
        }
        if ((int)order.size() == cap) {                 // 满了先淘汰队尾
            pos.erase(order.back().first);
            order.pop_back();
        }
        order.emplace_front(key, value);
        pos[key] = order.begin();
    }
};
```

`std::list::splice` 只改指针、不搬元素，正好实现「从中间摘下再插到队首」的 $O(1)$ 操作；`pos` 里存的是迭代器，所以能直接定位到链表节点。

**应用场景**：CPU 缓存（硬件近似）、浏览器缓存、数据库 buffer pool、操作系统页面置换。下图是浏览器缓存容量 3 时的访问时间线。

![[viz-lru-browser-cache-1794660146750.svg|650]]

> - 双向链表才能按 key 快速定位
> - 要在 $O(1)$ 内从链表中间摘下任意节点，必须能拿到前驱
> - 双向链表才能保证先进先出

> [!question] 不知道
> 卡在「前驱」这个词上。`A → B → C` 中，B 的前驱是 A，后继是 C；前驱就是排在前面的那个节点。先看上面的单/双向链表对比图。

> [!question] 双向链表中要删除中间的节点 B，应该改哪两根指针？
> - B.next = A，B.prev = C
> - head.next = C，B.next = 空
> - A.next = C，C.prev = A
> - 我不知道

> [!success]- ✓ 正确
> 删除 B 就是让它的前驱和后继直接相连：`A.next = C`、`C.prev = A`。站在 B 上就能拿到 `B.prev = A` 和 `B.next = C`，两步完成，$O(1)$。单链表没有 `prev`，拿不到 A，只能从 head 重找——这就是 LRU 必须用双向链表的原因。

## 14. 选型：先问操作，再选结构

没有「最好的数据结构」，只有「对这个操作最合适的结构」。拿到问题先问：**最频繁、最关键的操作是什么？**

- 按完整 key 取值 / 更新 → 哈希表
- 需要有序、范围查询、前驱后继 → 平衡 BST
- 只关心当前最大 / 最小 → 堆
- 按前缀补全、查词典 → Trie
- 判断「在不在」，允许假阳性、省内存 → 布隆过滤器
- 动态合并分组、判断同组 → 并查集
- 缓存满了淘汰最久未用 → LRU（哈希表 + 双向链表）
- 任意连接、路径、连通性 → 图
- 只在两端进出 → 栈 / 队列
- 按下标随机访问 → 数组；频繁中间插删 → 链表

![[viz-ds-selection-decision-1794659161670.svg|650]]

同一问题常常**组合**多种结构：LRU = 哈希表 + 双向链表；数据库索引常用 B+ 树（平衡树的多叉磁盘版）；路由表用 Trie / radix tree。选型不是背一张对照表，而是先锁定关键操作，再看哪种结构把这个操作做到最便宜。

> [!question] 一个缓存要求 `get` / `put` 都是 $O(1)$，容量满时淘汰最久未使用的 key。应该组合哪两种结构？
> - 数组 + 栈
> - 哈希表 + 双向链表
> - 平衡 BST + 队列
> - 我不知道

> [!success]- ✓ 正确
> 哈希表负责 $O(1)$ 定位 key；双向链表把「最近使用顺序」维护成前后指针，$O(1)$ 把节点移到队首、$O(1)$ 摘掉队尾。两种结构各管一件事，合起来才同时满足定位、顺序、淘汰。

## 15. 全篇压缩：每个结构只留一句

- **数组**：连续内存换来下标 $O(1)$，代价是中间插删要搬移。
- **动态数组**：容量不够时倍增，均摊插入 $O(1)$。
- **链表**：指针换来插删 $O(1)$，代价是失去下标访问。
- **栈 / 队列**：只允许在一端或两端操作，换来严格 $O(1)$ 和清晰语义（后进先出 / 先进先出）。
- **哈希表**：key 直接算出位置，平均 $O(1)$，但不保序。
- **BST**：保持有序，平衡时 $O(\log n)$；不平衡会退化成链。
- **堆**：只维护「根是极值」，$O(1)$ 取顶、$O(\log n)$ 插入删除、$O(n)$ 建堆。
- **图**：表达任意连接；邻接表 $O(V+E)$，矩阵 $O(V^2)$。
- **Trie**：把 key 拆成字符路径，前缀查找只走前缀长度步。
- **并查集**：只回答「同不同组」，合并 + 查询均摊 $O(\alpha(n))\approx O(1)$。
- **布隆过滤器**：位数组 + 多哈希，省内存、只可能假阳性。
- **LRU**：哈希表定位 + 双向链表排队，$O(1)$ 淘汰最久未使用。

**选型三问**：

1. 最频繁的操作是什么（查找 / 插入 / 取极值 / 前缀 / 合并 / 淘汰）？
2. 需不需要顺序、范围、前驱后继？
3. 能不能用一点空间换时间、容忍近似（布隆），或组合多种结构（LRU）？

答完这三问，结构基本就定了。
