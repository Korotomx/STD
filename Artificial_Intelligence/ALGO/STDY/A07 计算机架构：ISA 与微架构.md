# A07 计算机架构：ISA 与微架构

> 材料：[[The Most Ambiguous Concept in Computer Science]]（视频转录）

> [!info] 学习目标
> 把「架构」拆成 **指令集架构（ISA）** 与 **微架构**，能解释为什么同一份程序能在 Intel 和 AMD 上跑、却不能原生跑在 Apple M 系列上。

「架构」在计算机里至少指两样东西：软件与 CPU 之间的契约，以及 CPU 内部的具体电路实现。视频里那个「最歧义的概念」就是它——同一句「换了架构」，可能意味着「程序不能跑了」，也可能只是「内部重新设计了，程序照跑」。

## 1. 指令：CPU 真正认识的东西

CPU 不读 C、不读 Python，也不读函数。它只执行**机器指令**：一串二进制位，其中固定位置放**操作码**（要做什么）和**操作数**（对谁做）。

- 一条指令回答两件事：做什么操作、操作对象在哪。
- 一个 CPU 能理解的**全部指令**，就是它的**指令集**（instruction set）。
- 指令集不只列指令名，还规定每类指令如何编码成二进制、执行后对寄存器和内存产生什么影响。

x86-64 与 ARM 的根本区别就在这里：两者能听懂的指令集合不同。同一串二进制位在一边可能表示加法，在另一边可能是完全不同的操作——所以「0/1 序列」本身没有含义，要配合「哪套指令集」才有含义。

## 2. ISA：软件与 CPU 的契约

把「指令集」加上编码规则与行为规范，就是**指令集架构**（Instruction Set Architecture，ISA）。它规定所有**程序员可见**的东西：

- 有哪些指令（包括可选的扩展）；
- 每条指令的二进制编码格式；
- 寄存器模型：有哪些架构寄存器、位宽多少；
- 数据类型、寻址方式、内存对齐与异常行为。

它**不**规定 CPU 内部怎么实现：流水线分几级、分支预测怎么做、缓存多大、有几个执行单元、主频多少。这些是实现细节，不是软件与 CPU 的约定。

> [!question] 下列哪一项由**微架构**决定，而不是由 ISA 规定？
> - 指令的二进制编码
> - 通用寄存器的数量
> - L1 缓存的大小
> - 我不知道

> [!success]- ✓ 正确
> 对。缓存大小是微架构的实现选择：同一套 x86-64，不同型号可以给 32 KB、256 KB 或 512 KB 的 L1，程序行为不变，只是快慢不同。编码和架构寄存器数量则写进 ISA，软件看得见、也依赖它们。

## 3. 微架构：同一套契约的不同实现

ISA 只说到契约为止；真正把契约变成电路的，是**微架构**（microarchitecture）。同一套 ISA 可以有完全不同的微架构：流水线级数、缓存大小、执行单元数量、乱序窗口、分支预测器，全都可以不一样。

视频用 ALU 举例。一个 ALU 要支持加、减、与、或四种操作，`op` 用两位编码：`00` 加、`01` 减、`10` 与、`11` 或。至少三种内部设计都能实现同一份契约：

1. **广播输入、选输出**：四个运算单元同时算，解码器选择让哪一路结果出门；
2. **选输入**：解码器只把 A、B 路由到被选中的那个单元，其余单元不工作；
3. **使能单元**：A、B 送到所有单元，解码器只给目标单元发使能信号，只有它驱动输出。

三者内部结构完全不同，但对同样的 A、B、`op` 产生同样的输出——同一套 ISA，三种微架构，互相兼容。

类比：**ISA 之于微架构，就像问题规格之于算法**。同一个问题可以有很多算法，同一个 ISA 也可以有很多微架构。

## 4. 兼容性只看 ISA

判断一份机器码能不能直接执行，只看目标 CPU 是否实现**同一套 ISA**，不看内部设计。

- Intel Core 与 AMD Ryzen 的微架构完全不同，但都实现 x86-64；同一份 x86-64 机器码在两边都能跑，通常不需要重新编译。
- Apple M 系列实现的是 ARM，属于另一套 ISA；x86-64 机器码不能原生执行，必须重新编译成 ARM 机器码。
- Rosetta 2 是运行时的**翻译层**：把 x86-64 指令翻译成 ARM 指令再执行。它让程序能跑，但不是原生执行。
