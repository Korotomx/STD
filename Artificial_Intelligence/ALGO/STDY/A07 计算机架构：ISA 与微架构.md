# A07 计算机架构：ISA 与微架构

> 材料：[[The Most Ambiguous Concept in Computer Science]]（视频转录）

> [!info] 学习目标
> 把「架构」拆成 **指令集架构（ISA）** 与 **微架构**，能解释为什么同一份程序能在 Intel 和 AMD 上跑、却不能原生跑在 Apple M 系列上。

「架构」在计算机里至少指两样东西：软件与 CPU 之间的契约，以及 CPU 内部的具体电路实现。视频里那个「最歧义的概念」就是它——同一句「换了架构」，可能意味着「程序不能跑了」，也可能只是「内部重新设计了，程序照跑」。

## 1. 指令：CPU 真正认识的东西

CPU 不读 C、不读 Python，也不读函数。它只执行**机器指令**：一串二进制位，其中固定位置放**操作码**（要做什么）和**操作数**（对谁做）。

- 一条指令回答两件事：做什么操作、操作对象在哪。
- 一个 CPU 能理解的**全部指令**，就是它的**指令集**（instruction set）。
- 指令集不只列指令名，还规定每类指令如何编码成二进制、执行后对寄存器和内存产生什么影响。

x86-64 与 ARM 的根本区别就在这里：两者能听懂的指令集合不同。同一串二进制位在一边可能表示加法，在另一边可能是完全不同的操作——所以「0/1 序列」本身没有含义，要配合「哪套指令集」才有含义。

## 2. ISA：软件与 CPU 的契约

把「指令集」加上编码规则与行为规范，就是**指令集架构**（Instruction Set Architecture，ISA）。它规定所有**程序员可见**的东西：

- 有哪些指令（包括可选的扩展）；
- 每条指令的二进制编码格式；
- 寄存器模型：有哪些架构寄存器、位宽多少；
- 数据类型、寻址方式、内存对齐与异常行为。

它**不**规定 CPU 内部怎么实现：流水线分几级、分支预测怎么做、缓存多大、有几个执行单元、主频多少。这些是实现细节，不是软件与 CPU 的约定。

> [!question] 下列哪一项由**微架构**决定，而不是由 ISA 规定？
> - 指令的二进制编码
> - 通用寄存器的数量
> - L1 缓存的大小
> - 我不知道

> [!success]- ✓ 正确
> 对。缓存大小是微架构的实现选择：同一套 x86-64，不同型号可以给 32 KB、256 KB 或 512 KB 的 L1，程序行为不变，只是快慢不同。编码和架构寄存器数量则写进 ISA，软件看得见、也依赖它们。

## 3. 微架构：同一套契约的不同实现

ISA 只说到契约为止；真正把契约变成电路的，是**微架构**（microarchitecture）。同一套 ISA 可以有完全不同的微架构：流水线级数、缓存大小、执行单元数量、乱序窗口、分支预测器，全都可以不一样。

视频用 ALU 举例。一个 ALU 要支持加、减、与、或四种操作，`op` 用两位编码：`00` 加、`01` 减、`10` 与、`11` 或。至少三种内部设计都能实现同一份契约：

1. **广播输入、选输出**：四个运算单元同时算，解码器选择让哪一路结果出门；
2. **选输入**：解码器只把 A、B 路由到被选中的那个单元，其余单元不工作；
3. **使能单元**：A、B 送到所有单元，解码器只给目标单元发使能信号，只有它驱动输出。

三者内部结构完全不同，但对同样的 A、B、`op` 产生同样的输出——同一套 ISA，三种微架构，互相兼容。

![[viz-alu-three-microarchitectures-1794664458633.svg|650]]

类比：**ISA 之于微架构，就像问题规格之于算法**。同一个问题可以有很多算法，同一个 ISA 也可以有很多微架构。

## 4. 兼容性只看 ISA

判断一份机器码能不能直接执行，只看目标 CPU 是否实现**同一套 ISA**，不看内部设计。

- Intel Core 与 AMD Ryzen 的微架构完全不同，但都实现 x86-64；同一份 x86-64 机器码在两边都能跑，通常不需要重新编译。
- Apple M 系列实现的是 ARM，属于另一套 ISA；x86-64 机器码不能原生执行，必须重新编译成 ARM 机器码。
- Rosetta 2 是运行时的**翻译层**：把 x86-64 指令翻译成 ARM 指令再执行。它让程序能跑，但不是原生执行。

![[viz-isa-compatibility-matrix-1794664000542.svg|650]]

> [!question] 一份为 Intel x86-64 编译好的程序，拿到 AMD 的 x86-64 CPU 上，通常需要重新编译吗？
> - 不需要，两者实现同一套 ISA
> - 需要，两者的微架构不同
> - 需要，两家厂商的指令集各有一套
> - 我不知道

> [!success]- ✓ 正确
> 对，这次判断对了。编译产物面向的是 ISA，不是某款芯片；Intel 和 AMD 的微架构差异只影响内部执行效率，不影响同一份机器码的语义。

## 5. 「新架构」到底指什么

到这里，视频标题里的「歧义」就可以拆开了。说「A 和 B 架构不同」，有两种可能：

- **ISA 不同**：机器码不通用，必须重新编译，甚至改源码；
- **微架构不同**：只要实现同一套 ISA，同一份机器码照跑，只是快慢和功耗不同。

所以「架构不同」既不代表兼容，也不代表不兼容——要看说的是哪一层。

新闻和发布会上说「全新架构」，绝大多数时候指**新的微架构**，仍然实现现有 ISA。原因很实际：换 ISA 等于让现有软件全部失效，开发者要重新编译、适配甚至重写。视频里提到 1980 年代各种机器字长五花八门（32、36、72 位），操作系统和程序要为每台机器单独移植，就是这种代价的极端版本。

反过来，在编程语境里说「架构」，几乎总是指 ISA，因为编译器面向的是它。

> [!question] 发布会上说某款 CPU 采用「全新架构」，最可能指什么？
> - 新的微架构，仍然实现现有 ISA
> - 一套全新的指令集架构
> - 新的芯片制造工艺
> - 我不知道

> [!success]- ✓ 正确
> 对。厂商换微架构是为了更快、更省电，同时保持软件兼容；换 ISA 则要重建整个软件生态，代价高到不会每年发生。

## 6. 补充：厂商扩展与基线

x86-64 不是一个由单一厂商封闭维护的规范。Intel 和 AMD 共享同一个基础 ISA，再各自添加可选扩展（SSE、AVX 系列等）。所以「基础相同，但每家有不兼容的改动」这句话有一半对：扩展确实可能一边有一边没有，但它们是**契约里的可选项**，不是基础契约的差异。

编译器默认只生成基线指令，所以普通程序在两家都能跑。只有显式启用某个扩展（例如 `-mavx512f`）编译出的程序，才要求 CPU 支持它；健壮的软件会在运行时检查 CPUID，再决定走哪条代码路径。

同理，**RISC-V** 是一套开放的 ISA 规范，任何厂商都可以实现自己的微架构；同一份 RISC-V 机器码可以在不同厂商的芯片上运行，靠的仍是「同一 ISA、不同微架构」。

> [!question] 一份用默认选项编译的 x86-64 程序，为什么能在不支持 AVX-512 的老 CPU 上运行？
> - 编译器默认只使用基线指令集
> - AVX-512 不属于 x86 指令
> - 操作系统会把不支持的指令翻译掉
> - 我不知道

> [!success]- ✓ 正确
> 对。默认编译面向基线 ISA，不会生成 AVX-512 指令；只有显式开启扩展的程序才要求 CPU 支持，并且通常会在运行时用 CPUID 检测后再分派。

## 术语

| 英文 | 中文 | 含义 |
| --- | --- | --- |
| instruction | 指令 | CPU 能执行的最小命令，含操作码和操作数 |
| instruction set | 指令集 | 一个 CPU 能理解的全部指令 |
| instruction set architecture (ISA) | 指令集架构 | 指令、编码、寄存器、行为等程序员可见契约 |
| microarchitecture | 微架构 | 实现某套 ISA 的内部电路与组织 |
| machine code | 机器码 | 按某套 ISA 编码的二进制指令序列 |
| compatibility | 兼容性 | 同一份机器码能否在目标 CPU 上直接执行 |
| baseline ISA | 基线指令集 | 所有实现都必须支持的最小指令集合 |
| extension | 扩展 | 厂商在基线上可选添加的指令 |
| translation layer | 翻译层 | 运行时把一种 ISA 的指令转成另一种，如 Rosetta 2 |

## 总结

- 指令是 CPU 真正执行的东西；指令集是它能理解的全部指令。
- **ISA 是契约，微架构是实现**：ISA 规定指令、编码、寄存器与可见行为；微架构决定流水线、缓存、执行单元怎么搭。
- 兼容性只看 ISA：同一 ISA 的不同微架构能跑同一份机器码；不同 ISA 必须重新编译。
- 「架构不同」有歧义：新闻里多指新微架构（兼容），编程语境里多指不同 ISA（不兼容）。
- 厂商扩展是 ISA 里的可选项：基线保证兼容，扩展按需检测；Rosetta 2 是翻译层，不是原生执行。

## 面试三句话

1. ISA 是软件与处理器之间的契约，规定指令集合、二进制编码、寄存器模型和可见行为；微架构是这份契约的具体电路实现。
2. 同一套 ISA 可以有多种微架构，所以 Intel 和 AMD 的 x86-64 CPU 能直接跑同一份机器码；ARM 是另一套 ISA，必须重新编译，或者靠 Rosetta 2 这类翻译层。
3. 厂商发布「新架构」通常指新微架构；换 ISA 会破坏现有软件生态，代价极高，所以很少发生。
